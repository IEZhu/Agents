One real Agents-Core implementation worker supplies the candidate; its original contract/result must pass structural validation, then independent parent artifact inspection and focused tests. Runtime trials replay the same candidate afterward. They are not four independent model successes; native worker execution is controlled by the host, not by Accord. Replay request credits measure callback invocations, not the worker's internal model calls or provider billing.

Four arms: JSON Contract -> Accord Runtime; native Python Contract -> same Runtime; native Python JobSpec -> independent PythonSDK; exact same JSON bytes -> independent JobSpec decoder -> PythonSDK. First add equivalent child allocation, subset constraints and ancestor cancellation to the SDK. Share artifact bytes, snapshots, validators, Git publication adapter and fault positions. The small contract-set envelope packages a parent and child; it is not a workflow IR or scheduler. Adoption and child-output provenance remain explicit host code.

Parent starts with three credits, delegates one to a non-publishing child, receives a checked bundle and makes one checked adoption attempt. Success leaves one unused root credit, zero child credits and two charged replay calls. Test success, child target/input/output expansion, excess allocation, parent cancellation, behavioral mutation retaining a schema-valid bundle, parent reusing child receipts, tampered accepted output, stale source and repeated publication. All rejection cases must produce no document publication; successful replay publishes the exact three-file bundle once. Record state and bytes, not just a pass count.

IR-specific tests: both backends consume two unchanged contract sets, the second changing target, budget and validator revision with zero per-task backend edits after the generic wiring is frozen. A read-only subprocess inspects the data without importing task declarations or Runtime. Reject unknown fields/versions, duplicate keys, Boolean budget, missing checks and child expansion. Formatting changes preserve normalized identity; policy changes alter it. Export the ordinary Python JobSpec to the same format as the counterfactual: equivalent behavior credits the shared data contract, not unique language power. Account for decoder/adapter setup work. Do not infer productivity from source lines or replay time.

The token hypothesis is separate: measure actual prepared-worker prompt encoding with locally available tokenizers, record tokenizer fingerprints, transport size and exact reconstruction limits. Do not dispatch token IDs to a provider without a supported interface, call embedding tokenizers chat-model tokenizers, or infer token-cost/prefill savings from encoding time. A text/message IR, token IDs and KV execution state are different artifacts. Document verified provider capabilities separately from the locally executed probe.

Decision: an unsafe accepted mutation or a scope/credit failure rejects the implementation until fixed. Equal guards plus unchanged data interchange can justify an IR as an exchange/inspection format. Parity with exported Python and absent measured authoring gains do not justify standalone syntax or a compiler.

## Review-driven amendments

The initial implementation passed 45 focused tests and the original 19 behavior checks, but independent review found changed error-code precedence for mixed invalid inputs. A fresh prepared implementation attempt 2 corrected it; the final focused suite contains 56 cases and the parent behavior probe contains 22. Both original and corrected artifacts and exchange contracts are preserved. The code task used two actual implementation worker attempts, plus separate design, SDK, review and token-probe work. Paired trials replay only the final candidate. The amendment strengthens checks after the observed regression and must not be represented as a blinded, preregistered success rate.
