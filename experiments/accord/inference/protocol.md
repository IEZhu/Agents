# Real-model inference protocol

Frozen before scored model trials, 2026-10-14. Repository input revision: `7b81e3e8b748f7cfff0c6b712740ff313bd5f091`. Local calibration used only a synthetic request to return `{"answer":42}` and confirmed direct integer input, streaming token events, cache counters and snapshot APIs; those requests are excluded from the scored experiment.

Model: cached Qwen3 8B, Q4_K Medium GGUF SHA256 `d98cdcbd03e17ce47681435b5150e34c1417f50b5c0019dd560e4882c5745785`. Engine: official llama.cpp b11429, commit `d81235049384534c167caea52b85a694f6103d14`; release archive SHA256 `740288ec6887be94280a5dfa25b5e23a78285cab104519e6c7e218904ee82459`. Hardware: Apple M4 Max, 36 GiB unified memory, macOS 26.5.1. The server binds loopback only, uses one slot, 8192-token context, Metal GPU offload, flash attention, 512-token logical/physical batches, eight CPU threads, no context shifting, no global RAM prompt cache and reasoning off. No provider API is called.

Cross two factors: complete rendered text versus prepared integer IDs, and empty versus restored prefix KV cache. Use the same `/completion` endpoint and effective generation settings: greedy temperature zero, fixed seed, 128 output-token cap, EOS enabled, no custom grammar or answer repair. Complete messages are rendered by the model's chat template. The trusted engine tokenizes complete text with `add_special=true, parse_special=true`; integer prompts traverse the same native prompt path. Check full elementwise token equality before timed runs, not only counts or decoded text.

Freeze 12 repository-derived questions (retrieval, execution-state reasoning and bounded code reasoning) and their strict JSON answers before scoring. Use three repetitions, 144 measured generations. Randomize task-block order with recorded seed; rotate four cell orders by task/repetition to balance positions. Do not tune questions, expected answers or prompts after model outcomes. Repetitions measure timing noise; there are twelve distinct quality tasks, not 144 independent capability samples.

Warm weights/kernels with three declared unscored synthetic prompts, then clear slot state. Compute the longest common prefix of full task token sequences. Prime that prefix with one generated token, save the KV state once, and bind the snapshot to the engine/model/template/token and generation profile. Clear and restore that exact snapshot before each warm trial; clear before each cold trial and disable reuse. Record prefix priming, snapshot save and every restore separately. Include restore time in operational warm TTFT/total, while also reporting request-only steady-state timings. Repeated snapshot restoration is a controlled handoff experiment, not a claim that in-memory prefix reuse inherently needs disk I/O. The engine's zero-output setting generated a token in calibration, so use explicit `n_predict=1` and record it.

Require cold `timings.cache_n=0`, warm observed prefix reuse, no truncation, and `cache_n + prompt_n = total input tokens`. `tokens_cached` in a final native response describes retained state, not the number reused at admission; do not use it as the reuse metric. Keep all outputs, tokens, effective settings, order and timing records, including failures. Stream TTFT starts at request submission and ends at the first generated token event; server `prompt_ms` and `predicted_ms` remain distinct. No client-side GPU synchronization claim is made.

Score strict JSON validity and expected task answer separately from exact output byte/token identity. Cache-dependent batching can change floating-point results, so greedy output equality is an observation, not assumed. Failed parse, wrong answers, output limits or drift remain in the report. No model retries or answer normalization beyond JSON parsing.

Record one-time rendering/tokenization/packet preparation, input transport bytes, input/reused/evaluated/output token counts, client latency, engine timing, process CPU-time deltas and sampled resident memory where available. Token packets do not reduce logical prompt-token count. API invoice is zero for this local run; electricity, energy and hardware depreciation are unmeasured, not zero. Report measured work/latency and avoid invented currency savings. Include artifact/cache setup when estimating repeated-use break-even; it is a local estimate, not provider pricing.

Non-scored controls reject wrong model/template/source profile and altered IDs before dispatch. An empty-cache fallback must execute the complete original input with zero reuse. Snapshot/model incompatibility must not be silently accepted by the host. Persist exact raw evidence and source/profile hashes. This pilot tests one model/backend/configuration; it cannot establish general quality equivalence, billing savings, cross-model cache portability or a need for standalone Accord syntax.
