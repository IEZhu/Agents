## Answer A
Классический баг: изменяемое значение по умолчанию (mutable default argument).

### [BLOCKER] `tags=[]` вычисляется один раз — при определении функции

Список создаётся на этапе `def`, а не на каждом вызове, и живёт в `add_tag.__defaults__[0]`. Все вызовы без второго аргумента работают с **одним и тем же** списком:

```python
add_tag("a")   # ['a']
add_tag("b")   # ['a', 'b']  <- ожидалось ['b']
add_tag("c")   # ['a', 'b', 'c']
```

Почему важно: состояние протекает между несвязанными вызовами, и в долгоживущем процессе список растёт бесконечно — утечка памяти плюс выдача чужих данных. Проявляется не сразу, при втором вызове, поэтому в тестах с одним вызовом не видно.

Фикс — sentinel `None`:

```python
def add_tag(tag: str, tags: list[str] | None = None) -> list[str]:
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
```

### [MINOR] Двойной контракт: мутирует аргумент и возвращает его

Функция и меняет переданный список на месте, и возвращает его. Вызывающий не может понять по подписи, нужно ли присваивать результат, а `x = add_tag("a", y)` незаметно портит `y` (`x is y`). Варианты:

- мутирующая версия — `-> None`, ничего не возвращать;
- чистая версия — не трогать вход:

```python
def add_tag(tag: str, tags: Sequence[str] = ()) -> list[str]:
    return [*tags, tag]
```

Второй вариант заодно снимает проблему с default: пустой кортеж неизменяем, так что общий объект безвреден.

### [NIT] Нет аннотаций типов

`tag`, `tags` и возврат ничем не ограничены. Для публичного API стоит добавить — это ловит путаницу «тег vs список тегов» статически.

Что ещё стоит уточнить (не берусь утверждать без контекста): если теги должны быть уникальными, `append` даёт дубликаты — тогда нужен `set` или проверка `if tag not in tags`. По коду не видно, какое поведение задумано.

Итого: 1 blocker, 1 minor, 1 nit.


## Answer B
Главная проблема — изменяемый аргумент по умолчанию. `tags=[]` вычисляется один раз, при определении функции, а не при каждом вызове. Этот один список живёт в `add_tag.__defaults__` и накапливает теги между вызовами.

```python
add_tag("a")   # ['a']
add_tag("b")   # ['a', 'b']  <- сюрприз, тот же список
```

Классический Python-gotcha, по факту — баг уровня BLOCKER: состояние утекает между несвязанными вызовами, и поведение зависит от истории процесса. Воспроизводится сразу, без конкурентности.

Фикс — sentinel `None`:

```python
def add_tag(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
```

Второе, помягче (MINOR): функция и мутирует переданный список, и возвращает его. Контракт двусмысленный — вызывающий по `tags = add_tag(x, tags)` легко решит, что получил копию, и удивится, что исходный список тоже изменился. Выбрать одно:

```python
# in-place, ничего не возвращаем — как list.append
def add_tag(tag, tags):
    tags.append(tag)

# или чистая версия, вход не трогаем
def add_tag(tag, tags=()):
    return [*tags, tag]
```

Чистая версия, кстати, снимает и первую проблему: кортеж как дефолт неизменяем, так что общий дефолт безвреден.
