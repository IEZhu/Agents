**Short answer:** exactly one combination works with the versions you listed:

**acme-auth 3.2 + acme-billing 5.1 + acme-events 2.0 + acme-proto 4.x**

"Bump everything to latest" can't be resolved. It isn't a pip quirk; your constraints conflict.

### Why latest fails

- acme-billing 6.0 requires acme-events >= 2.1.
- acme-events 2.1 supports **only** acme-proto 5.x.
- You've ruled out proto 5.x, so billing 6.0 is out with it. The cause is a transitive dependency: billing 6.0 itself would accept proto 4.

### How the solution follows

1. **Proto major:** auth 3.2 needs proto 4.x or 5.x. With 5.x excluded, you're on **proto 4.x**.
2. **Events on proto 4:** 1.4 only supports 3.x and 2.1 only supports 5.x, so **events 2.0** is the only option.
3. **Billing >= 5.1 on proto 4 with events 2.0:**
   - 6.0 needs events >= 2.1, so it's out.
   - 5.1 supports proto 3.x or 4.x and events 2.x, so it works.

Every package's constraints are satisfied, and nothing else fits.

### What to pin

```text
acme-auth==3.2.*
acme-billing==5.1.*
acme-events==2.0.*
acme-proto>=4,<5
```

Use `==X.Y.*` or exact patch versions, depending on how you normally pin. Keep `acme-proto` open inside 4.x so pip can choose a patch that all three libraries accept.

### Caveats worth checking before you commit to this

- **The listed versions only.** This assumes your table covers every release. If an acme-events 2.2+ exists that supports proto 4.x, billing 6.0 might become possible. Run `pip index versions acme-events` against your internal index to check.
- **Docs vs. real metadata.** Internal compatibility docs often drift from the actual `Requires-Dist` constraints in the wheels. If pip still fails on the combo above, run `pip install --dry-run --report - ...` (or `pipdeptree` in a clean venv) and compare the real constraints with the docs. A narrower range such as `acme-proto>=4.2,<5` in one of the libs would explain the failure.
- **Refunds API in 5.1.** You said you need billing >= 5.1 for refunds, so 5.1 should cover it. Confirm that the refunds features you use aren't 6.0-only additions.
- **Your upgrade path out:** getting proto 5.x into your base image (the Python version bump) unlocks auth 3.2 + billing 6.0 + events 2.1 + proto 5.x. That combination also satisfies every constraint and is where you'd want to end up.
