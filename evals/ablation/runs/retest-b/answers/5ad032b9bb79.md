Вот отполированный вариант. Я расставил шаги в том порядке, в котором их нужно выполнять, и оформил команды отдельными блоками. Сами команды и смысл не менял.

```markdown
## Запуск

1. Скопируйте файл с переменными окружения. Без этого шага сервис не запустится:

   ```bash
   cp .env.example .env
   ```

2. Запустите сервис:

   ```bash
   docker compose up -d
   ```

   После запуска сервис будет доступен по адресу http://localhost:8080.

3. Проверьте, что сервис работает:

   ```bash
   curl http://localhost:8000/health
   ```

   Ожидаемый ответ:

   ```json
   {"status":"ok"}
   ```

### Если порт занят

Порт задаётся переменной `APP_PORT` в файле `.env` (по умолчанию `8000`). Измените её значение на свободный порт.

### Логи

```bash
docker compose logs -f app
```
```

**Обратите внимание на порты.** В исходном тексте есть противоречие, и я его сохранил, потому что вы просили не менять смысл. Сервис якобы доступен на `8080`, а health check и значение `APP_PORT` по умолчанию указывают на `8000`. Скорее всего, один из номеров опечатка. Если верный порт `8000`, замените адрес в шаге 2 на http://localhost:8000. Если `8080`, исправьте команду `curl` и значение по умолчанию.
