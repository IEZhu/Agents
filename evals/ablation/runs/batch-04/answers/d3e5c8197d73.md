Вот сообщение для одного коммита. В заголовок вынесен баг-фикс: это единственное изменение, которое меняет поведение для клиентов, и его будут искать по `git log` и по тикету.

```
fix(billing): use client timezone for invoice date (BILL-412)

Invoice date was computed in UTC instead of the client's timezone,
so clients east of UTC (e.g. Vladivostok, UTC+10) got invoices
dated the previous day.

Also included in this commit:
- refactor(billing): rename utils helpers, no behavior change:
  calc_t -> calculate_tax, fmt -> format_amount
- chore(deps): bump requests 2.31.0 -> 2.32.3
- docs(readme): add local billing setup via docker compose

Refs: BILL-412
```

Сообщение написано на английском, как принято для Conventional Commits. Если в команде коммиты пишут по-русски, переведите тело, а префиксы `fix(billing):` и остальные оставьте как есть.

Перед `git commit` стоит проверить две вещи:

1. **Не остались ли вызовы старых имён.** Переименование ломает всех, кто вызывает `calc_t` или `fmt` за пределами `utils.py`. Если diff затрагивает только `invoice.py` и `utils.py`, а функции используются где-то ещё, упадёт в рантайме. Проверка займёт секунды:
   ```bash
   git grep -nwE 'calc_t|fmt' -- '*.py'
   ```
2. **Обновление `requests`.** Насколько я помню, в линейке 2.32.x меняли работу с SSL-контекстом в `HTTPAdapter`, а часть ранних 2.32.x-релизов отзывали. Я это не проверял, так что посмотрите changelog. Если у вас нет своих адаптеров и нестандартного `verify`, скорее всего, ничего не сломается.

Один коммит на четыре несвязанных изменения затруднит `git revert` и `git bisect`. Если фикс BILL-412 придётся откатить, вместе с ним откатятся переименования, зависимость и README. Разбить на части можно примерно за минуту, всё уже застейджено:

```bash
git reset
git add src/billing/invoice.py && git commit -m "fix(billing): use client timezone for invoice date (BILL-412)"
git add src/billing/utils.py   && git commit -m "refactor(billing): rename calc_t/fmt to calculate_tax/format_amount"
git add requirements.txt       && git commit -m "chore(deps): bump requests from 2.31.0 to 2.32.3"
git add README.md              && git commit -m "docs(readme): add local billing setup via docker compose"
```

Есть оговорка: если `invoice.py` уже вызывает новые имена из `utils.py`, первый коммит сам по себе не запустится. Тогда закоммитьте `utils.py` первым или объедините эти два файла в один коммит. Если не хочется с этим разбираться, спокойно заливайте одним коммитом с сообщением выше: оно всё равно гораздо информативнее, чем «Правки биллинга».
