## Rubric (what a strong answer does)
1. Recommends splitting the staged changes into separate commits (the timezone fix, the rename, the requests bump and the README change as distinct commits) rather than one combined commit, with a brief reason (e.g. easier revert, review or bisect); offering a single-commit fallback is fine as long as splitting is the recommendation.
2. Proposed commit subjects use the type(scope): subject form with fitting types: fix for the timezone bug, refactor for the renames, chore (or build) for the requests bump, docs for the README.
3. Subjects are imperative (e.g. "fix"/"add", or Russian infinitive/imperative such as "исправить", not past tense like "исправил"/"added") and have no trailing period.
4. The fix commit body states what was wrong and why (invoice date computed in UTC instead of the client's timezone, so Vladivostok clients got the previous day) and references BILL-412; the answer does not describe the rename as a behaviour change.

## Answer A
Вот сообщение для одного коммита. В заголовок вынесен баг-фикс: это единственное изменение, которое меняет поведение для клиентов, и его будут искать по `git log` и по тикету.

```
fix(billing): use client timezone for invoice date (BILL-412)

Invoice date was computed in UTC instead of the client's timezone,
so clients east of UTC (e.g. Vladivostok, UTC+10) got invoices
dated the previous day.

Also included in this commit:
- refactor(billing): rename utils helpers, no behavior change:
  calc_t -> calculate_tax, fmt -> format_amount
- chore(deps): bump requests 2.31.0 -> 2.32.3
- docs(readme): add local billing setup via docker compose

Refs: BILL-412
```

Сообщение написано на английском, как принято для Conventional Commits. Если в команде коммиты пишут по-русски, переведите тело, а префиксы `fix(billing):` и остальные оставьте как есть.

Перед `git commit` стоит проверить две вещи:

1. **Не остались ли вызовы старых имён.** Переименование ломает всех, кто вызывает `calc_t` или `fmt` за пределами `utils.py`. Если diff затрагивает только `invoice.py` и `utils.py`, а функции используются где-то ещё, упадёт в рантайме. Проверка займёт секунды:
   ```bash
   git grep -nwE 'calc_t|fmt' -- '*.py'
   ```
2. **Обновление `requests`.** Насколько я помню, в линейке 2.32.x меняли работу с SSL-контекстом в `HTTPAdapter`, а часть ранних 2.32.x-релизов отзывали. Я это не проверял, так что посмотрите changelog. Если у вас нет своих адаптеров и нестандартного `verify`, скорее всего, ничего не сломается.

Один коммит на четыре несвязанных изменения затруднит `git revert` и `git bisect`. Если фикс BILL-412 придётся откатить, вместе с ним откатятся переименования, зависимость и README. Разбить на части можно примерно за минуту, всё уже застейджено:

```bash
git reset
git add src/billing/invoice.py && git commit -m "fix(billing): use client timezone for invoice date (BILL-412)"
git add src/billing/utils.py   && git commit -m "refactor(billing): rename calc_t/fmt to calculate_tax/format_amount"
git add requirements.txt       && git commit -m "chore(deps): bump requests from 2.31.0 to 2.32.3"
git add README.md              && git commit -m "docs(readme): add local billing setup via docker compose"
```

Есть оговорка: если `invoice.py` уже вызывает новые имена из `utils.py`, первый коммит сам по себе не запустится. Тогда закоммитьте `utils.py` первым или объедините эти два файла в один коммит. Если не хочется с этим разбираться, спокойно заливайте одним коммитом с сообщением выше: оно всё равно гораздо информативнее, чем «Правки биллинга».


## Answer B
Вот вариант на один коммит. В заголовке главное изменение, в теле остальное, по одному пункту на изменение:

```
fix(billing): датировать счёт в часовом поясе клиента (BILL-412)

Дата счёта считалась в UTC, поэтому у клиентов с большим положительным
смещением (например, Владивосток, UTC+10) счёт получал дату предыдущего дня.
Теперь дата берётся в часовом поясе клиента.

Попутно:
- refactor(billing/utils): calc_t -> calculate_tax, fmt -> format_amount;
  поведение не менялось
- deps: requests 2.31.0 -> 2.32.3
- docs: README — как локально поднять биллинг через docker compose

Refs: BILL-412
```

Если в команде коммиты пишут на английском:

```
fix(billing): date invoices in client's timezone (BILL-412)

Invoice date was computed in UTC, so clients far ahead of UTC
(e.g. Vladivostok, UTC+10) got invoices dated the previous day.

Also:
- refactor(billing/utils): rename calc_t -> calculate_tax, fmt -> format_amount (no behavior change)
- deps: bump requests 2.31.0 -> 2.32.3
- docs: README section on running billing locally via docker compose
```

Перед пушем проверь две вещи.

1. **Переименование могло что-то сломать.** В diff только `invoice.py` и `utils.py`. Если `calc_t` или `fmt` вызываются где-то ещё (другие модули, тесты, шаблоны), эти вызовы после коммита упадут. Проверка займёт секунду:
   ```
   git grep -nwE 'calc_t|fmt' -- '*.py'
   ```
   Если что-то найдётся, это надо поправить до пуша.

2. **Лучше всё же разбить на несколько коммитов.** Один коммит, где смешаны багфикс, рефакторинг, обновление зависимости и документация, неудобно откатывать. Если после релиза что-то сломается из-за `requests` 2.32.x, `git revert` отменит и фикс BILL-412. Разбить можно минуты за три:
   ```
   git reset
   git add requirements.txt && git commit -m "deps: bump requests 2.31.0 -> 2.32.3"
   git add README.md && git commit -m "docs: run billing locally via docker compose"
   git add -p src/billing/   # сначала только переименования
   git commit -m "refactor(billing): rename calc_t -> calculate_tax, fmt -> format_amount"
   git add src/billing/ && git commit -m "fix(billing): date invoices in client's timezone (BILL-412)"
   ```
   Здесь `git add -p` нужен, потому что в `invoice.py`, скорее всего, есть и фикс, и обновлённые вызовы переименованных функций. Если разбираться с этим сейчас не хочется, одного коммита с сообщением выше вполне хватит: это всё равно гораздо информативнее, чем «Правки биллинга».
