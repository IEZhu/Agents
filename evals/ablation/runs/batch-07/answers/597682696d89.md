---

**Subject: Approval requested by Friday: move our search platform to a managed AWS service**

**Decision needed**
Approve moving our search and logging platform from servers we run ourselves to Amazon's managed equivalent (Amazon OpenSearch Service).

**Why now**
Our current search software is stuck on an old version because of a vendor licensing change, and it no longer gets security fixes. The only way to keep patching it ourselves is a major upgrade, and that upgrade needs a license review that could add cost. Moving to the managed service removes that exposure, and AWS takes over patching and upgrades.

**Cost impact**

| | Today | Proposed |
|---|---|---|
| Monthly infrastructure cost | ~$14.2k | ~$11.8k |
| Annualized | ~$170k | ~$142k |
| **Estimated savings** | | **~$2.4k/month (~$29k/year)** |

- **Staff time:** about half of one SRE's time currently goes to maintaining this system. Most of that time is freed for other work. It is a capacity gain and does not reduce headcount.
- **One-time cost:** about 6 engineer-weeks of migration work, plus roughly 2 weeks of running the old and new systems side by side, which briefly doubles that month's infrastructure bill.

**Risks and how we manage them**
- **Slower searches on old data:** searches on logs older than 30 days may be 10–15% slower. We accept this because it is how we get the storage savings. Recent data is unaffected.
- **Rework:** some internal dashboards need to be rebuilt, and two custom add-ons need to be replaced with built-in features. Both are included in the 6-week estimate.
- **Cutover:** we move over during a scheduled maintenance window, after two weeks of running both systems in parallel, so we can fall back if something goes wrong.

**Recommendation**
Approve. The move cuts running costs by about 17%, closes a security gap we can't fix cheaply otherwise, and frees up SRE time. The one-time cost is modest.

---

**Check these with engineering before you send it:**

1. **Is the SRE time already in the $14.2k?** The original wording is ambiguous. If $14.2k covers infrastructure only, the real savings are larger than shown, because half an SRE's time is being freed. If $14.2k already includes the SRE time, then $11.8k may be an infrastructure-only figure and the two numbers aren't comparable. Get both figures on the same basis.
2. **Put a dollar figure on the one-time cost.** A finance reader will want the migration cost in dollars and a payback period. As an illustration only: if a loaded engineer-week costs about $4k (my assumption, so use your internal rate), the one-time cost comes to about $24k of labor plus about $12k for the overlap month, so roughly $35k in total. That pays back in about 14–15 months from the infrastructure savings alone, and sooner if you count the SRE time.
3. **Confirm the $11.8k estimate.** Ask whether it uses on-demand or reserved pricing, and whether it covers data transfer and snapshot storage. Reserved instances could lower it further, but they come with a 1- or 3-year commitment that she should know about.
4. **Confirm the security claim.** "No more security patches" reflects engineering's description of our situation. Check that the memo states it accurately, because this is the strongest reason for doing the move now.
