У обеих проблем одна причина. Сервер списывает монеты **только в DataStore**, а GUI читает **leaderstats**. Их никто не связывает: leaderstats заполняются из DataStore при входе, поэтому новое число появляется только после перезахода.

Второй баг, «два меча за клик», — это не редкая случайность, а обычная race condition. `GetAsync` и `SetAsync` **уступают выполнение** (yield). Если игрок быстро кликает дважды, оба обработчика успевают прочитать одно и то же старое значение монет до того, как первый его перезапишет. Оба проходят проверку `coins >= price`, и игрок получает два меча, заплатив один раз. К тому же `GetAsync`, насколько я помню, кэширует значение на несколько секунд. Это расширяет окно для гонки (recalled, не проверено — уточни в документации DataStore).

## Как правильно

**DataStore — это хранилище для сохранения, а не рабочая переменная.** Во время игры источник правды — значение на сервере, например `leaderstats.Coins`. В DataStore пишем при выходе игрока и по автосохранению. Если монеты меняются в памяти без yield между проверкой и списанием, гонка исчезает: Luau однопоточный, и обработчики могут перемежаться только в точках yield.

Бонус: сейчас на каждый клик уходит 2 запроса к DataStore. При 40 игроках, которые кликают в магазине, ты довольно быстро упрёшься в лимиты запросов, и начнутся ошибки и задержки.

### Сервер (Script в ServerScriptService)

Я предполагаю, что в leaderstats лежит `IntValue` с именем `Coins`. Если у тебя другое имя, поправь.

```lua
local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local ServerStorage = game:GetService("ServerStorage")

local BuyItem = ReplicatedStorage:WaitForChild("BuyItem")
local Prices = ReplicatedStorage:WaitForChild("Prices")
local Items = ServerStorage:WaitForChild("Items")

local PURCHASE_COOLDOWN = 0.5 -- секунды между покупками одного игрока
local lastPurchaseTime: {[Player]: number} = {}

local function getCoins(player: Player): IntValue?
	local leaderstats = player:FindFirstChild("leaderstats")
	local coins = leaderstats and leaderstats:FindFirstChild("Coins")
	if coins and coins:IsA("IntValue") then
		return coins
	end
	return nil
end

BuyItem.OnServerEvent:Connect(function(player: Player, itemName: unknown)
	-- 1. Клиенту не доверяем: проверяем тип аргумента
	if typeof(itemName) ~= "string" then return end

	-- 2. Защита от спама кликами
	local now = os.clock()
	local last = lastPurchaseTime[player]
	if last and now - last < PURCHASE_COOLDOWN then return end
	lastPurchaseTime[player] = now

	-- 3. Предмет и цена должны существовать (FindFirstChild, а не prices[itemName])
	local priceValue = Prices:FindFirstChild(itemName)
	local itemTemplate = Items:FindFirstChild(itemName)
	if not (priceValue and priceValue:IsA("IntValue") and itemTemplate) then return end

	local coins = getCoins(player)
	if not coins then return end

	-- 4. Проверка и списание БЕЗ yield между ними — гонки нет
	local price = priceValue.Value
	if coins.Value < price then return end
	coins.Value -= price

	itemTemplate:Clone().Parent = player.Backpack
end)

Players.PlayerRemoving:Connect(function(player)
	lastPurchaseTime[player] = nil
end)
```

Почему `FindFirstChild`, а не `prices[itemName]`: эксплойтер может отправить любую строку. Несуществующее имя вызовет ошибку в скрипте. А имя свойства вроде `"Name"` или `"Parent"` вернёт вовсе не дочерний объект.

Если меч должен быть **один на игрока**, добавь перед списанием проверку владения: есть ли предмет уже в `player.Backpack` или в `player.Character`. Иначе быстрый двойной клик после кулдауна честно купит два меча за две цены.

### Клиент (LocalScript у текстового лейбла с монетами)

Проблема в том, что GUI читает значение **один раз при старте**. Нужно подписаться на изменения:

```lua
local Players = game:GetService("Players")

local player = Players.LocalPlayer
local coins = player:WaitForChild("leaderstats"):WaitForChild("Coins")
local label = script.Parent

local function refresh()
	label.Text = tostring(coins.Value)
end

refresh()
coins.Changed:Connect(refresh) -- у IntValue .Changed срабатывает при смене Value
```

Изменения `Value` на сервере реплицируются клиенту автоматически, поэтому цифра обновится сразу после покупки. Никаких дополнительных RemoteEvent не нужно.

LocalScript в кнопке можно оставить как есть. Только `game.ReplicatedStorage` лучше заменить на `game:GetService("ReplicatedStorage")`.

## Сохранение

Раз во время игры монеты живут в leaderstats, в DataStore их пишет скрипт загрузки/сохранения:

- **При входе**: `GetAsync` в `pcall`. Если вернулся `nil` (новый игрок), подставь дефолт, например 0. В твоём текущем коде `nil >= price` у нового игрока просто упадёт с ошибкой.
- **При выходе** (`PlayerRemoving`) и **по автосохранению** (раз в несколько минут): пиши `coins.Value`, лучше через `UpdateAsync`, тоже в `pcall`.
- **`game:BindToClose`**: сохраняй всех, иначе при выключении сервера данные теряются.

Если хочешь не возиться с этим вручную, для данных игроков хорошо подходит ProfileService или его преемник ProfileStore. Они берут на себя сессионную блокировку и защиту от дюпа между серверами.

⚠️ **Проверь одну вещь прямо сейчас.** Если у тебя уже есть скрипт, который при выходе сохраняет `leaderstats.Coins.Value` в тот же DataStore `"Coins"`, то текущий баг хуже, чем кажется. Магазин списывает монеты только в DataStore, а при выходе их перезаписывает старое значение из leaderstats. Выходит, покупки фактически **бесплатные**. После перехода на схему выше эта проблема тоже уйдёт.

## Как проверить

1. Запусти **Test → Local Server** с 2 игроками. Купи меч, и цифра должна уменьшиться сразу.
2. Кликай по кнопке максимально быстро. Должен списываться ровно один платёж за каждый выданный меч, а при проверке владения — выдаваться только один меч.
3. Выйди, зайди снова: баланс должен совпадать с тем, что был перед выходом.
4. Для проверки защиты из командной строки сервера вызови обработчик с мусором вроде `123`, `"Name"` или несуществующего предмета. В Output не должно быть ошибок.
