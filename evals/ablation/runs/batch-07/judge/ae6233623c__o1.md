## Rubric (what a strong answer does)
1. Addresses the actual lag question with a sound approach, e.g. rendering the projectile visually on clients while the server does its own hit detection (raycast/shapecast or position checks) instead of relying on a server-simulated physics part with Touched
2. Points out that damage is sent from the client and must be decided on the server, and removes the damage parameter from FireServer
3. Adds a server-side per-player cooldown/rate limit for casting, since the client can fire the remote as often as it wants
4. Notes the cleanup problems: the Touched handler can fire multiple times and hit the caster, and parts are removed with Parent = nil instead of :Destroy() (or Debris), leaving connections and instances around

## Answer A
You can't fix the stutter by tuning this setup. The approach itself causes it, so the projectile needs to be built a different way.

## Why it stutters and why hits come late

1. **You're replicating a physics part.** The server creates an unanchored Part driven by `BodyVelocity`. Every client only sees its position through physics replication, which runs at a lower rate than the frame rate and is interpolated. That's the stutter. Roblox may also hand network ownership of an unanchored part to a nearby player (as I recall, automatic ownership goes to the closest client), so the ball can jump between simulations. Rapid Q presses by 25 players multiply the problem.
2. **`Touched` fires on the server's view of the world.** The server's copy of the ball and the server's copy of the target both lag behind what each client sees. So the hit registers "after it visually passed". `Touched` is also unreliable for fast objects.
3. **Other bugs in the current code:**
   - **The client decides damage.** An exploiter can call `FireServer(pos, 999999)`. Damage must be a server constant.
   - **There's no server cooldown.** Q-spam, or an exploiter firing the remote in a loop, creates unlimited parts.
   - **A ball that misses never gets cleaned up.** It flies forever and keeps using physics time. `ball.Parent = nil` also doesn't destroy it or disconnect the `Touched` connection.
   - **The ball probably hits its own caster.** It spawns inside the HumanoidRootPart, so `Touched` will likely fire on the caster's own body parts first.
   - `target` isn't validated. It could be nil, NaN, or equal to the origin, which makes `.Unit` NaN.

## The fix: simulate on the server, draw on the clients

- **Server:** no Part at all. The server moves a point along the path each `Heartbeat` and does a spherecast for each step. It decides hits and damage and enforces cooldowns. This is server-authoritative and cheap: it's math plus one raycast per step, with nothing to replicate.
- **Clients:** each client draws its own anchored, non-colliding visual and positions it from a shared start time every frame. Movement is perfectly smooth because nothing is being replicated.
- **Caster:** draws the fireball the instant Q is pressed (prediction), so it feels responsive.

Only two small messages cross the network for each fireball: "spawned" (origin, direction, time) and "ended" (id, position).

### Setup
In ReplicatedStorage, add:
- 3 RemoteEvents: `CastFireball`, `FireballSpawned`, `FireballEnded`
- 1 ModuleScript: `FireballConfig`

**ReplicatedStorage/FireballConfig** (ModuleScript, shared so client and server agree on speed and range)
```lua
return {
	SPEED = 80,          -- studs/sec
	RADIUS = 1,          -- collision + visual radius
	MAX_RANGE = 300,     -- studs before it fizzles
	DAMAGE = 35,         -- server-only authority; client never sends this
	COOLDOWN = 0.75,     -- seconds between casts per player
	MAX_ACTIVE_PER_PLAYER = 3,
}
```

**ServerScriptService/FireballServer** (Script)
```lua
local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local RunService = game:GetService("RunService")

local Config = require(ReplicatedStorage.FireballConfig)
local CastFireball = ReplicatedStorage.CastFireball
local FireballSpawned = ReplicatedStorage.FireballSpawned
local FireballEnded = ReplicatedStorage.FireballEnded

type Projectile = {
	id: string,
	owner: Player,
	position: Vector3,
	direction: Vector3,
	traveled: number,
	params: RaycastParams,
}

local projectiles: {Projectile} = {}
local lastCastAt: {[Player]: number} = {}
local activeCount: {[Player]: number} = {}

local function isFiniteVector(v: Vector3): boolean
	for _, c in {v.X, v.Y, v.Z} do
		if c ~= c or math.abs(c) == math.huge then return false end -- NaN / inf
	end
	return true
end

local function getHumanoid(instance: Instance): Humanoid?
	local model = instance:FindFirstAncestorOfClass("Model")
	return model and model:FindFirstChildOfClass("Humanoid")
end

local function rejectCast(player: Player, id: string)
	-- Tell only the caster to delete their predicted visual
	FireballEnded:FireClient(player, id, nil)
end

CastFireball.OnServerEvent:Connect(function(player: Player, castId: any, target: any)
	-- 1. Validate payload types (never trust the client)
	if typeof(castId) ~= "number" or castId % 1 ~= 0 or castId < 1 or castId > 2^31 then return end
	if typeof(target) ~= "Vector3" or not isFiniteVector(target) then return end
	local id = player.UserId .. ":" .. castId

	-- 2. Character must exist and be alive
	local character = player.Character
	local root = character and character:FindFirstChild("HumanoidRootPart")
	local humanoid = character and character:FindFirstChildOfClass("Humanoid")
	if not (root and humanoid and humanoid.Health > 0) then return rejectCast(player, id) end

	-- 3. Rate limits
	local now = os.clock()
	if now - (lastCastAt[player] or -math.huge) < Config.COOLDOWN then return rejectCast(player, id) end
	if (activeCount[player] or 0) >= Config.MAX_ACTIVE_PER_PLAYER then return rejectCast(player, id) end

	local offset = target - root.Position
	if offset.Magnitude < 0.5 then return rejectCast(player, id) end

	lastCastAt[player] = now
	activeCount[player] = (activeCount[player] or 0) + 1

	local params = RaycastParams.new()
	params.FilterType = Enum.RaycastFilterType.Exclude
	params.FilterDescendantsInstances = {character} -- can't hit yourself

	local direction = offset.Unit
	local origin = root.Position
	table.insert(projectiles, {
		id = id, owner = player, position = origin,
		direction = direction, traveled = 0, params = params,
	})

	FireballSpawned:FireAllClients(id, origin, direction, workspace:GetServerTimeNow())
end)

local function finish(index: number, p: Projectile)
	-- swap-remove: O(1) instead of shifting the array
	projectiles[index] = projectiles[#projectiles]
	projectiles[#projectiles] = nil
	if activeCount[p.owner] then
		activeCount[p.owner] -= 1
	end
	FireballEnded:FireAllClients(p.id, p.position)
end

RunService.Heartbeat:Connect(function(dt: number)
	for i = #projectiles, 1, -1 do
		local p = projectiles[i]
		local stepDistance = math.min(Config.SPEED * dt, Config.MAX_RANGE - p.traveled)
		local displacement = p.direction * stepDistance

		-- Sweep the whole step, so fast balls can't tunnel through targets
		local result = workspace:Spherecast(p.position, Config.RADIUS, displacement, p.params)

		if result then
			p.position = result.Position
			local humanoid = getHumanoid(result.Instance)
			if humanoid and humanoid.Health > 0 then
				humanoid:TakeDamage(Config.DAMAGE)
			end
			finish(i, p)
		else
			p.position += displacement
			p.traveled += stepDistance
			if p.traveled >= Config.MAX_RANGE then
				finish(i, p)
			end
		end
	end
end)

Players.PlayerRemoving:Connect(function(player)
	lastCastAt[player] = nil
	activeCount[player] = nil
end)
```

**StarterPlayer/StarterPlayerScripts/FireballClient** (LocalScript; it lives here rather than in StarterCharacterScripts so it survives respawns)
```lua
local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local RunService = game:GetService("RunService")
local UserInputService = game:GetService("UserInputService")

local Config = require(ReplicatedStorage.FireballConfig)
local CastFireball = ReplicatedStorage.CastFireball
local FireballSpawned = ReplicatedStorage.FireballSpawned
local FireballEnded = ReplicatedStorage.FireballEnded

local player = Players.LocalPlayer
local mouse = player:GetMouse()

local fxFolder = Instance.new("Folder")
fxFolder.Name = "FireballFx"
fxFolder.Parent = workspace
mouse.TargetFilter = fxFolder -- don't aim at our own fireballs

local LIFETIME = Config.MAX_RANGE / Config.SPEED + 1 -- safety cleanup if "ended" is lost
local visuals = {}
local nextCastId = 0
local lastLocalCast = -math.huge

local function createVisual(id: string, origin: Vector3, direction: Vector3, startTime: number)
	if visuals[id] then return end -- caster already predicted it
	local part = Instance.new("Part")
	part.Shape = Enum.PartType.Ball
	part.Size = Vector3.one * Config.RADIUS * 2
	part.Material = Enum.Material.Neon
	part.Color = Color3.fromRGB(255, 120, 30)
	part.Anchored = true
	part.CanCollide = false
	part.CanTouch = false
	part.CanQuery = false
	part.CastShadow = false
	part.CFrame = CFrame.new(origin)
	part.Parent = fxFolder
	visuals[id] = { part = part, origin = origin, direction = direction, startTime = startTime }
end

local function destroyVisual(id: string, hitPosition: Vector3?)
	local visual = visuals[id]
	if not visual then return end
	visuals[id] = nil
	visual.part:Destroy()
	if hitPosition then
		-- play explosion particles / sound at hitPosition here
	end
end

RunService.RenderStepped:Connect(function()
	local now = workspace:GetServerTimeNow()
	for id, visual in visuals do
		local elapsed = now - visual.startTime
		if elapsed > LIFETIME then
			destroyVisual(id, nil)
		else
			-- Position from shared clock, not accumulated dt: late joiners of the
			-- event "catch up" instead of starting behind the server's ball
			local distance = math.clamp(elapsed * Config.SPEED, 0, Config.MAX_RANGE)
			visual.part.CFrame = CFrame.new(visual.origin + visual.direction * distance)
		end
	end
end)

UserInputService.InputBegan:Connect(function(input, gameProcessed)
	if gameProcessed or input.KeyCode ~= Enum.KeyCode.Q then return end

	local character = player.Character
	local root = character and character:FindFirstChild("HumanoidRootPart")
	if not root then return end

	-- Client-side cooldown is only for feel; the server enforces the real one
	local now = os.clock()
	if now - lastLocalCast < Config.COOLDOWN then return end
	lastLocalCast = now

	local target = mouse.Hit.Position
	local offset = target - root.Position
	if offset.Magnitude < 0.5 then return end

	nextCastId += 1
	local id = player.UserId .. ":" .. nextCastId
	createVisual(id, root.Position, offset.Unit, workspace:GetServerTimeNow()) -- instant feedback
	CastFireball:FireServer(nextCastId, target) -- note: no damage sent
end)

FireballSpawned.OnClientEvent:Connect(createVisual)
FireballEnded.OnClientEvent:Connect(destroyVisual)
```

## What this gets you
- **Smooth for everyone.** Each client animates its own anchored part every frame, so nothing depends on physics replication.
- **Hits match the ball.** Other players' visuals are placed by the server clock (`GetServerTimeNow`), so they show the ball where the server's simulation has it. The "ended" event explodes it where the server says it hit.
- **Much cheaper under spam.** Each fireball is a table entry plus a spherecast per frame, with no physics bodies and no instances replicated from the server. Casts are capped by the cooldown and by the active-per-player limit.
- **Exploit-safe basics.** Damage stays on the server, the payload is type- and NaN-checked, and there are rate limits and self-hit exclusion.

## Limits worth knowing
- **The victim you see can still be slightly off.** Hits are judged against where the victim is *on the server*, and that differs from what the caster sees by roughly their ping. This is the honest trade-off of server authority. For ~80 stud/s fireballs with a 1-stud radius it's usually fine. If players complain, the next step is lag compensation: the server keeps ~1 s of character position history and rewinds targets by the caster's ping. That adds real complexity, so I'd only do it if you need it.
- **The caster's ball is slightly ahead of the server's.** The predicted ball starts before the server's does, so the caster may see it travel a little past the target before it explodes. You can hide this by delaying the start of the caster's own visual by half their ping, or just accept it.
- **API names to confirm in the docs.** I wrote `workspace:Spherecast(origin, radius, direction, params)` and `workspace:GetServerTimeNow()` from memory and haven't checked them here, so confirm both on create.roblox.com. If `Spherecast` isn't available in your setup, `workspace:Raycast(p.position, displacement, p.params)` works as a thinner fallback. Hits will be less forgiving, because a ray has no radius.
- **Libraries.** If you later add gravity-arc projectiles or many projectile types, the community FastCast module (recalled, not verified here) implements this same "cast the path, draw it separately" pattern.

## How to test it
1. In Studio, open **Test → Clients and Servers** with 2–3 players. Solo Play won't show replication issues.
2. Turn on incoming replication lag in Studio's network settings (the exact menu location varies by version) to simulate ~150–200 ms of ping. Check that the other clients' fireballs stay smooth and explode on contact.
3. Spam Q and confirm the server caps the casts (at most ~1.3 casts/s and 3 in flight).
4. From the command bar on a client, fire the remote with bogus arguments, such as `CastFireball:FireServer(1, Vector3.new(0/0, 0, 0))` or `CastFireball:FireServer("x", nil)`. Nothing should spawn, and there should be no server errors.

Possible next steps are a team check so allies can't be hit, and pooling the visual parts. Pooling only matters if the Microprofiler shows `Instance.new` as a hotspot, which is unlikely at these rates.


## Answer B
The stutter and the late hits come from the same design choice: you're running a **physics part on the server** and relying on `Touched`. Your setup also has a few bugs and exploit holes that get worse when people spam Q. Here's what's wrong, then a rewrite.

## Why it looks bad right now

1. **Network ownership handoff (the stutter).** An unanchored part spawned next to a player is usually given automatically to a nearby client for physics simulation. As the fireball flies past other players, ownership can jump between clients and the server. Each switch causes a visible hitch, and other players only see the part at the physics replication rate with interpolation.
2. **Hits are decided on the server's timeline (the late hits).** Each client sees the projectile a bit behind where the server has it, and the target a bit behind where they really are. `Touched` fires on whoever owns the physics, at the physics step, and it's unreliable for fast, small parts. It can miss thin parts completely or fire late.
3. **It hits the caster.** The ball spawns *inside* your own HumanoidRootPart, so `Touched` can fire on your own body first. Your own `Humanoid` gets found and damaged, and the ball disappears immediately.
4. **The client sends the damage value.** `FireServer(mouse.Hit.Position, 35)` means an exploiter can send `FireServer(pos, 999999)`. Damage has to live on the server.
5. **No cooldown on the server.** With 25 players spamming Q you get hundreds of physics parts, and nothing stops an exploiter from firing the remote 1000 times a second.
6. **Leak.** `ball.Parent = nil` doesn't destroy the part or disconnect the `Touched` connection, and a ball that never hits anything is never cleaned up. Spam builds up parts in memory for the whole server session.

**Quick fix if you just want it less bad today:** call `ball:SetNetworkOwner(nil)` right after parenting, give it a server cooldown, remove the `damage` argument, and `Debris:AddItem(ball, 4)`. That stops the ownership stutter, but hits will still feel off. The proper fix is below.

## The proper pattern: server does math, clients draw

- **Server:** no physical part. It stores the projectile as data (origin, direction, speed) and moves it with a **spherecast each Heartbeat**. That makes hit detection deterministic, cheap and authoritative.
- **Clients:** every client renders its own anchored, non-colliding visual ball and moves it with `RenderStepped`, which is perfectly smooth. Other players' clients use a shared server timestamp, so their visual lines up with where the server thinks the ball is.
- **Caster:** spawns their visual **immediately** on key press (client prediction), so there's zero input delay.

### 1. Shared config: `ReplicatedStorage/FireballConfig` (ModuleScript)

```lua
local FireballConfig = {
	SPEED = 80,           -- studs/sec
	RANGE = 300,          -- studs before it fizzles
	RADIUS = 1,           -- hit radius (matches the 2x2x2 visual)
	DAMAGE = 35,          -- server-owned, never sent by the client
	COOLDOWN = 0.75,      -- seconds between casts
}

return FireballConfig
```

Also create two RemoteEvents in ReplicatedStorage: `CastFireball` (client → server) and `FireballFx` (server → clients).

### 2. Server: `ServerScriptService/FireballServer` (Script)

```lua
local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local RunService = game:GetService("RunService")
local Workspace = game:GetService("Workspace")

local Config = require(ReplicatedStorage:WaitForChild("FireballConfig"))
local CastFireball = ReplicatedStorage:WaitForChild("CastFireball")
local FireballFx = ReplicatedStorage:WaitForChild("FireballFx")

type Projectile = {
	id: string,
	owner: Player,
	position: Vector3,
	direction: Vector3,
	traveled: number,
	params: RaycastParams,
}

local activeProjectiles: {Projectile} = {}
local lastCastTime: {[Player]: number} = {}

local function isFiniteNumber(n: number): boolean
	return n == n and math.abs(n) < math.huge -- rejects NaN and inf
end

local function isValidVector(v: any): boolean
	return typeof(v) == "Vector3"
		and isFiniteNumber(v.X) and isFiniteNumber(v.Y) and isFiniteNumber(v.Z)
end

local function getHumanoidFromPart(part: BasePart): Humanoid?
	local model = part:FindFirstAncestorOfClass("Model")
	return model and model:FindFirstChildOfClass("Humanoid")
end

CastFireball.OnServerEvent:Connect(function(player: Player, castId: any, targetPosition: any)
	-- Validate the payload: never trust what the client sends
	if typeof(castId) ~= "number" or not isFiniteNumber(castId) then return end
	if not isValidVector(targetPosition) then return end

	-- Server-side cooldown (the real anti-spam; the client check is just UX)
	local now = os.clock()
	if now - (lastCastTime[player] or 0) < Config.COOLDOWN then return end

	local character = player.Character
	local root = character and character:FindFirstChild("HumanoidRootPart")
	local humanoid = character and character:FindFirstChildOfClass("Humanoid")
	if not root or not humanoid or humanoid.Health <= 0 then return end

	local offset = targetPosition - root.Position
	if offset.Magnitude < 0.01 then return end
	lastCastTime[player] = now

	-- Exclude the caster so the fireball can't hit its own owner
	local params = RaycastParams.new()
	params.FilterType = Enum.RaycastFilterType.Exclude
	params.FilterDescendantsInstances = { character }

	local projectile: Projectile = {
		id = player.UserId .. ":" .. castId,
		owner = player,
		position = root.Position,
		direction = offset.Unit,
		traveled = 0,
		params = params,
	}
	table.insert(activeProjectiles, projectile)

	FireballFx:FireAllClients("Spawn", projectile.id, player,
		projectile.position, projectile.direction, Workspace:GetServerTimeNow())
end)

local function removeAt(index: number)
	-- Swap-remove: O(1), order doesn't matter
	activeProjectiles[index] = activeProjectiles[#activeProjectiles]
	activeProjectiles[#activeProjectiles] = nil
end

RunService.Heartbeat:Connect(function(dt: number)
	for i = #activeProjectiles, 1, -1 do
		local p = activeProjectiles[i]
		local stepDistance = math.min(Config.SPEED * dt, Config.RANGE - p.traveled)
		local step = p.direction * stepDistance

		local result = Workspace:Spherecast(p.position, Config.RADIUS, step, p.params)
		if result then
			local humanoid = getHumanoidFromPart(result.Instance)
			if humanoid and humanoid.Health > 0 then
				humanoid:TakeDamage(Config.DAMAGE)
			end
			FireballFx:FireAllClients("Hit", p.id, result.Position)
			removeAt(i)
		else
			p.position += step
			p.traveled += stepDistance
			if p.traveled >= Config.RANGE then
				removeAt(i) -- clients time out their visuals on their own
			end
		end
	end
end)

Players.PlayerRemoving:Connect(function(player)
	lastCastTime[player] = nil
end)
```

### 3. Client: `StarterPlayerScripts/FireballClient` (LocalScript)

I'd move it out of StarterCharacterScripts. Otherwise it respawns with the character and re-creates the connections each time.

```lua
local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local RunService = game:GetService("RunService")
local UserInputService = game:GetService("UserInputService")
local Workspace = game:GetService("Workspace")

local Config = require(ReplicatedStorage:WaitForChild("FireballConfig"))
local CastFireball = ReplicatedStorage:WaitForChild("CastFireball")
local FireballFx = ReplicatedStorage:WaitForChild("FireballFx")

local localPlayer = Players.LocalPlayer
local mouse = localPlayer:GetMouse()

local MAX_LIFETIME = Config.RANGE / Config.SPEED
local activeVisuals: {[string]: {ball: BasePart, connection: RBXScriptConnection}} = {}
local castCounter = 0
local lastCastTime = 0

local function destroyVisual(id: string)
	local visual = activeVisuals[id]
	if not visual then return end
	visual.connection:Disconnect()
	visual.ball:Destroy()
	activeVisuals[id] = nil
end

local function spawnVisual(id: string, origin: Vector3, direction: Vector3, startTime: number)
	local ball = Instance.new("Part")
	ball.Shape = Enum.PartType.Ball
	ball.Size = Vector3.one * Config.RADIUS * 2
	ball.Material = Enum.Material.Neon
	ball.Color = Color3.fromRGB(255, 120, 30)
	ball.Anchored = true   -- no physics, we move it ourselves
	ball.CanCollide = false
	ball.CanTouch = false
	ball.CanQuery = false
	ball.CFrame = CFrame.new(origin)
	ball.Parent = Workspace

	local connection = RunService.RenderStepped:Connect(function()
		-- Position from shared server time, so everyone sees it where the server has it
		local elapsed = Workspace:GetServerTimeNow() - startTime
		if elapsed >= MAX_LIFETIME then
			destroyVisual(id)
			return
		end
		ball.CFrame = CFrame.new(origin + direction * Config.SPEED * math.max(elapsed, 0))
	end)

	activeVisuals[id] = { ball = ball, connection = connection }
end

UserInputService.InputBegan:Connect(function(input, gameProcessed)
	if gameProcessed or input.KeyCode ~= Enum.KeyCode.Q then return end

	local now = os.clock()
	if now - lastCastTime < Config.COOLDOWN then return end -- UX only; the server enforces the real cooldown

	local character = localPlayer.Character
	local root = character and character:FindFirstChild("HumanoidRootPart")
	if not root then return end

	local offset = mouse.Hit.Position - root.Position
	if offset.Magnitude < 0.01 then return end
	lastCastTime = now
	castCounter += 1

	-- Client prediction: show the caster their fireball instantly
	local id = localPlayer.UserId .. ":" .. castCounter
	spawnVisual(id, root.Position, offset.Unit, Workspace:GetServerTimeNow())

	CastFireball:FireServer(castCounter, mouse.Hit.Position) -- no damage value!
end)

FireballFx.OnClientEvent:Connect(function(kind: string, id: string, ...)
	if kind == "Spawn" then
		local caster, origin, direction, startTime = ...
		if caster == localPlayer then return end -- already predicted locally
		spawnVisual(id, origin, direction, startTime)
	elseif kind == "Hit" then
		local hitPosition = ...
		destroyVisual(id)
		-- Put your explosion particles / sound at hitPosition here
	end
end)
```

## Why this fixes both symptoms

- **No stutter:** nothing is physically simulated or replicated per frame. Each client moves an anchored part locally at render rate. The network traffic is one `Spawn` and one `Hit` message per fireball, instead of a stream of physics updates. That also scales much better with 25 spammers.
- **Hits match the visuals for observers:** other clients place the ball using `GetServerTimeNow() - startTime`, so the visual starts a little "fast-forwarded" by the latency and stays in step with the server's spherecast. The ball disappears exactly when the server sends `Hit`, not after it has visually flown through someone.
- **Honest trade-off:** the caster's predicted ball runs roughly half a round-trip ahead of the server's copy. On a high-ping caster, the hit can land a few studs "behind" what they saw. That's normal for server-authoritative projectiles. Removing it fully would need server-side lag compensation (rewinding target positions), which I'd only add if playtests show it matters.

## Things to verify

- `Workspace:Spherecast(position, radius, direction, params)` and `Workspace:GetServerTimeNow()` are both from memory, not checked here. Confirm the exact signatures on create.roblox.com/docs. If you'd rather avoid Spherecast, `Workspace:Raycast` with the same arguments minus the radius works, but thin hitboxes get a bit harder to hit.
