Готовлю материал про застройщика. В марте 2024 у них на сайте была страница /news/zhk-severny с пресс-релизом, где был указан срок сдачи «IV квартал 2025». Как это сделать быстро и так, чтобы результат нельзя было оспорить? Питон знаю на базовом уровне.

## Rubric (what a strong answer does)
1. Recommends querying the Wayback Machine CDX API for the page URL and deduplicating captures by content digest (collapse=digest or comparing the digest field), explaining that an unchanged digest means unchanged content, so only the few distinct versions need inspection.
2. Explains retrieving the original page HTML without the Wayback toolbar/injected markup (the id_ suffix after the timestamp) before diffing, or otherwise addresses archive-injected noise in the comparison.
3. Gives a concrete way to bound the change: the last capture with the old wording and the first capture with the new wording, cited by their archive URLs/timestamps as evidence, with the caveat that the edit happened somewhere between those two captures, not at an exact moment.
4. Stays practical for a basic Python user (concrete steps or a short script) and mentions pacing requests to the archive (e.g. about one per second, with a pause/backoff on errors) rather than hammering it.

## Answer A
**Коротко:** листать снимки вручную не нужно. У Wayback Machine есть CDX API: он отдаёт список всех снимков страницы, и дубликаты можно схлопнуть по хешу содержимого. Дальше скрипт скачивает каждый уникальный снимок, ищет в нём «IV квартал 2025» и «II квартал 2027» и находит переход: последний снимок со старым сроком и первый с новым. Это займёт минут 10–20.

Одна важная поправка к постановке задачи. Архив покажет **интервал** между двумя снимками, а не точный момент правки. Честная формулировка звучит так: «не раньше X и не позже Y». Если снимки частые, интервал будет узким. Такая формулировка выдержит любую проверку, а заявление «поменяли 14 мая в 15:02» уже не выдержит.

## 1. Скрипт

Установите библиотеку `pip install requests`, подставьте свой домен и запустите.

```python
import re, time, csv, html, hashlib, pathlib, requests

URL = "example.ru/news/zhk-severny"   # домен застройщика, без https://
OLD = re.compile(r"IV\s+квартал\w*\s+2025", re.I)
NEW = re.compile(r"II\s+квартал\w*\s+2027", re.I)
OUT = pathlib.Path("snapshots"); OUT.mkdir(exist_ok=True)

s = requests.Session()
s.headers["User-Agent"] = "journalist-research-script"

def get(url, **kw):
    for attempt in range(6):
        try:
            r = s.get(url, timeout=90, **kw)
            if r.status_code == 200:
                return r
        except requests.RequestException:
            pass
        time.sleep(10 * (attempt + 1))   # архив режет частые запросы, ждём
    raise RuntimeError(f"не удалось скачать {url}")

# 1) Список снимков: только ответы 200, одинаковые по содержимому схлопнуты
cdx = get("https://web.archive.org/cdx/search/cdx", params={
    "url": URL, "output": "json", "from": "2024",
    "fl": "timestamp,original,statuscode,digest",
    "filter": "statuscode:200", "collapse": "digest",
}).json()
rows = cdx[1:]                     # первая строка — заголовки
print("уникальных версий:", len(rows))

# 2) Скачиваем «сырые» снимки (id_ = без панели Wayback) и классифицируем
results = []
for ts, original, status, digest in rows:
    raw_url = f"https://web.archive.org/web/{ts}id_/{original}"
    body = get(raw_url).content
    (OUT / f"{ts}.html").write_bytes(body)
    text = html.unescape(re.sub(r"<[^>]+>", " ", body.decode("utf-8", "replace")))
    state = ("OLD" if OLD.search(text) else "") + ("NEW" if NEW.search(text) else "")
    results.append({
        "timestamp_utc": ts, "state": state or "NONE",
        "sha256": hashlib.sha256(body).hexdigest(),
        "view_url": f"https://web.archive.org/web/{ts}/{original}",
        "raw_url": raw_url,
    })
    print(ts, state or "NONE")
    time.sleep(2)

# 3) Журнал всех версий и поиск переходов
with open("snapshots.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.DictWriter(f, fieldnames=results[0].keys()); w.writeheader(); w.writerows(results)

for a, b in zip(results, results[1:]):
    if a["state"] != b["state"]:
        print(f"ПЕРЕХОД: {a['state']} -> {b['state']}  между {a['timestamp_utc']} и {b['timestamp_utc']}")
        print("   до:   ", a["view_url"]); print("   после:", b["view_url"])
```

Как это работает:
- `collapse=digest` выбрасывает подряд идущие снимки с одинаковым содержимым. Вместо сотен снимков обычно остаётся несколько десятков.
- Хеш меняется от любого байта: счётчика, баннера, токена. Поэтому уникальных версий может остаться больше, чем реальных правок текста. Для этого скрипт и ищет сами фразы, а на хеш не полагается.
- Метка времени вида `20240315123456` означает ГГГГММДДччммсс по UTC.
- Параметры API (`collapse`, `filter`, `fl`, суффикс `id_`) я привожу по памяти и в этом ответе не проверял. Если запрос вернёт ошибку, сверьтесь с документацией CDX Server API на archive.org.

Что может пойти не так:
- **Статус `NONE` у всех снимков.** Скорее всего, срок подставляется через JavaScript и в исходном HTML его нет. Другой вариант: он написан иначе, например «4 кв. 2025» или «IV кв.». Откройте один файл из `snapshots/`, найдите, как именно написан срок, и поправьте регулярные выражения.
- **Снимков мало.** Попробуйте вариант со слешем на конце или добавьте `"matchType": "prefix"`, чтобы захватить адреса с параметрами (`?utm=…`).
- **Появляется `OLDNEW`, или статус «прыгает» туда-сюда.** Возможно, на странице одновременно были оба срока, или сайт отдавал разные версии. Такие случаи стоит посмотреть вручную: это как раз интересные детали для материала.

## 2. Пакет доказательств для редактора

1. **Две ключевые ссылки:** последний снимок со старым сроком и первый с новым. Для каждого нужны обычная ссылка (`/web/TS/…`) и «сырая» (`/web/TSid_/…`).
2. **Скриншоты** обоих снимков, на которых виден адрес архива, метка времени и выделенный срок. Рядом приложите скриншот той же пресс-строки с датой публикации на обоих снимках: так видно, что дата не менялась, а текст поменялся.
3. **`snapshots.csv` и папка `snapshots/`** с SHA-256 каждого файла. Это полный журнал, а не две выбранные картинки. Такой журнал снимает упрёк в cherry-picking.
4. **Зафиксируйте текущую версию прямо сейчас.** Нужны три вещи: Save Page Now на web.archive.org, копия на archive.today (независимый архив) и локальная копия со скриншотом. Владелец сайта может попросить Wayback скрыть свои снимки, так что скачанные файлы и сторонний архив подстрахуют.
5. **Если нужна юридическая сила**, закажите нотариальный протокол осмотра сайта. Нотариус может осмотреть и живую страницу, и страницы веб-архива. Для редакции это обычно избыточно, но если ждёте претензий, лучше сделать заранее.

## 3. Независимое подтверждение (сильнее архива)

Архив доказывает, что поменялся текст на сайте. Если нужно показать, когда застройщик официально перенёс срок, ищите источники, которые от сайта не зависят:
- **Проектная декларация в ЕИСЖС (наш.дом.рф).** Срок ввода там указан официально, а изменения декларации публикуются с датами. Это первичный официальный источник, и он весит больше, чем пресс-релиз. Структуру карточки объекта я описываю по памяти, проверьте на месте.
- **Разрешение на строительство** и его продления, если есть доступ к региональным данным.
- **Перепечатки пресс-релиза** в СМИ и соцсетях застройщика за март 2024 со старым сроком. Это ещё одна независимая фиксация исходного текста.

Если по декларации срок перенесли, скажем, осенью 2024, а на сайте текст тихо поменяли позже, с сохранением старой даты публикации, это уже содержательная находка для материала. Но формулируйте её только тогда, когда обе даты подтверждены документами.


## Answer B
**Коротко:** листать снимки руками не нужно. CDX API Wayback Machine отдаёт список всех снимков страницы, а параметр `collapse=digest` отбрасывает подряд идущие одинаковые копии. Короткий скрипт скачивает каждую уникальную версию в «сыром» виде и ищет в ней обе формулировки. На выходе получаются два снимка: последний со старым сроком и первый с новым. Точный момент правки архив не покажет, он даёт только окно между этими двумя снимками. Именно так результат и стоит формулировать для редактора: «текст изменён между X и Y». Такую формулировку оспорить трудно, а утверждение «изменили 14 мая» оспорить легко.

## 1. Скрипт

Нужен только `requests` (`pip install requests`). Подставьте свой домен в `URL`.

```python
import csv, hashlib, html, re, time, pathlib
import requests

URL = "example.ru/news/zhk-severny"      # без http:// и www, со звёздочкой ниже
OUT = pathlib.Path("snapshots"); OUT.mkdir(exist_ok=True)

# Шаблоны терпимы к неразрывным пробелам, "квартал"/"квартала", регистру.
# (?<![IVX]) не даёт "II" совпасть внутри "III".
OLD = re.compile(r"(?<![IVXІ])IV\s*кв(?:артал[а-я]*|\.)?\s*2025", re.I)
NEW = re.compile(r"(?<![IVXІ])II\s*кв(?:артал[а-я]*|\.)?\s*2027", re.I)

s = requests.Session()
s.headers["User-Agent"] = "research script (journalist fact-check)"

def get(url, **kw):
    for attempt in range(5):
        try:
            r = s.get(url, timeout=60, **kw)
            if r.status_code == 200:
                return r
        except requests.RequestException:
            pass
        time.sleep(5 * (attempt + 1))          # бэкофф при 429/503
    raise RuntimeError(f"не удалось скачать {url}")

# 1) Список уникальных версий
params = [
    ("url", URL + "*"),                       # ловит и /, и ?utm=..., и http/https
    ("output", "json"),
    ("fl", "timestamp,original,statuscode,digest"),
    ("filter", "statuscode:200"),
    ("collapse", "digest"),
    ("from", "2024"),
]
rows = get("https://web.archive.org/cdx/search/cdx", params=params).json()[1:]
print("уникальных версий:", len(rows))

def normalize(raw: bytes) -> str:
    for enc in ("utf-8", "cp1251"):
        try:
            text = raw.decode(enc); break
        except UnicodeDecodeError:
            continue
    else:
        text = raw.decode("utf-8", "replace")
    text = html.unescape(re.sub(r"<[^>]+>", " ", text))
    text = text.replace("\xa0", " ").replace("І", "I")   # кириллическая І -> латинская
    return re.sub(r"\s+", " ", text)

# 2) Скачиваем каждую версию и классифицируем
with open("timeline.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.writer(f)
    w.writerow(["timestamp_utc", "status", "sha256", "archive_link", "original"])
    for ts, original, code, digest in rows:
        raw_url = f"https://web.archive.org/web/{ts}id_/{original}"   # id_ = без тулбара архива
        raw = get(raw_url).content
        sha = hashlib.sha256(raw).hexdigest()
        (OUT / f"{ts}.html").write_bytes(raw)
        t = normalize(raw)
        status = {(True, False): "OLD", (False, True): "NEW",
                  (True, True): "BOTH", (False, False): "NONE"}[(bool(OLD.search(t)), bool(NEW.search(t)))]
        w.writerow([ts, status, sha, f"https://web.archive.org/web/{ts}/{original}", original])
        print(ts, status)
        time.sleep(1.5)                        # не больше ~1 запроса в секунду
```

После этого откройте `timeline.csv` и найдите место, где `OLD` сменяется на `NEW`. Это и есть искомое окно.

**Почему я проверяю все версии, а не делаю бинарный поиск.** Бинарный поиск быстрее, но он молча предполагает, что текст поменяли один раз. Если срок правили несколько раз (2025 → 2026 → 2027) или откатывали обратно, бинарный поиск это пропустит. Для материала такая промежуточная правка может оказаться отдельной историей. Несколько сотен запросов с паузой 1,5 с займут минут 10–15, и это нормальная цена.

## 2. На что обратить внимание в результатах

- **Много `NONE`.** Скорее всего, текст подгружается JavaScript'ом и в сыром HTML его нет. Другой вариант: срок записан иначе, например «4 кв. 2025», «IV кв.», римские цифры кириллицей или картинка. Откройте пару таких файлов из `snapshots/` и поправьте регулярки. Ещё одна возможность: в эти даты по адресу была заглушка или страница-ошибка, отданная с кодом 200.
- **«Уникальных» версий почти столько же, сколько всех снимков.** Это нормально. Digest меняется от любой мелочи вроде счётчиков, токенов или блока «другие новости», поэтому дедупликация по digest только сокращает объём, а содержание всё равно сравнивает скрипт.
- **Разные `original`.** Если в выборку попали адреса с параметрами (`?utm_...`), убедитесь, что граничные снимки относятся к той же самой странице.
- **Время в `timestamp` указано в UTC.** В тексте для редактора переведите его в московское время и укажите оба значения.
- **Проверьте дату публикации в граничном NEW-снимке.** Если там по-прежнему стоит мартовская дата 2024 года, это прямо доказывает тихую правку задним числом, а не новую публикацию. Для вашего сюжета это, пожалуй, главный факт.

## 3. Доказательный пакет для редактора

Wayback доказывает одно: что краулер архива увидел по этому адресу в конкретный момент. Для журналистики это стандартный и широко принятый источник. Но застройщик может сказать «это не наш официальный ресурс». Поэтому одного архива мало, нужны независимые подтверждения:

1. **Два граничных снимка** (последний OLD и первый NEW) со ссылками вида `web.archive.org/web/<timestamp>/<url>`, скриншоты с видимым тулбаром архива и сохранённые сырые HTML с SHA-256 из `timeline.csv`. Хеш позволит показать, что файлы потом не редактировали.
2. **Строки CDX для этих снимков.** Там есть поле `digest`, контрольная сумма содержимого, вычисленная самим архивом (насколько я помню, это SHA-1 в base32; не проверял, уточните в документации CDX). Любой может повторить запрос и получить тот же результат, и это сильный аргумент в пользу воспроизводимости.
3. **Второй независимый архив.** Проверьте `archive.today` / `archive.ph` (поиск `archive.ph/<url>`). Если там есть снимок за тот же период, у вас два независимых источника вместо одного.
4. **Текущее состояние, зафиксированное прямо сейчас:** Save Page Now (`web.archive.org/save/<url>`) плюс archive.today. Страницу могут поправить ещё раз, особенно после вашего запроса.
5. **Самое сильное: первичный официальный источник.** Для долевого строительства срок ввода указывается в проектной декларации, а она публикуется в ЕИСЖС (наш.дом.рф). Насколько я знаю, изменения декларации там фиксируются с датами. Проверьте это сами, я сейчас не могу это подтвердить. Если перенос срока есть в декларации, у вас официальный документ с датой, и архив сайта только иллюстрирует, что пресс-релиз поправили без пометки. Стоит также посмотреть разрешение на строительство и публикации застройщика и СМИ, где цитировался «IV квартал 2025».
6. **Если есть риск суда:** нотариальный протокол осмотра интернет-страниц, включая страницы Wayback Machine. Этот способ фиксации в российской практике принимают охотнее всего. Обычно он нужен уже тогда, когда поступает претензия, но если сюжет острый, лучше сделать его заранее.

## 4. Как сформулировать в тексте

Оспорить трудно вот такую формулировку: «По данным Internet Archive, 12.05.2024 на странице ещё значился срок "IV квартал 2025", а на снимке от 03.06.2024 — уже "II квартал 2027"; дата публикации и текст пресс-релиза в остальном не изменились, пометки об изменении нет». Даты здесь условные, подставьте свои. Вторую часть фразы можно утверждать, только если вы действительно сравнили два граничных снимка целиком. Для этого прогоните `diff` по двум HTML или откройте их рядом.

Не пишите «изменили N-го числа», если между граничными снимками прошло несколько дней или недель. Точную дату правки знает только сам застройщик. Можно прямо спросить у него: когда и почему изменили срок и почему нет пометки. Отказ или молчание тоже войдут в материал.
