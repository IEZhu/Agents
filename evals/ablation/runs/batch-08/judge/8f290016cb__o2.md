## 1. Единая мерка (её же отдайте сеньорам)

Проблема «к одному придирались больше, чем к другому» обычно возникает не из-за строгости, а из-за того, что правила не зафиксированы. Поэтому серьёзность определяется **последствием**, а не впечатлением проверяющего.

**Шкала серьёзности:**

| Уровень | Критерий (проверяемый) |
|---|---|
| **BLOCKER** | При обычном использовании функция **молча** возвращает неверный результат или портит состояние. |
| **MAJOR** | Утечка ресурса; поведение зависит от ОС или окружения; падение на входе, который **явно упомянут в условии**. |
| **MINOR** | Граничный случай, который условие не оговаривало, но который стоило обработать или хотя бы задокументировать. Результат расходится с общепринятым смыслом имени функции. |
| **NIT** | Стиль, отсутствие type hints и docstring (если условие их не требовало). |
| **POSITIVE** | Обязательно хотя бы один пункт у каждого. |

**Чек-лист, одинаковый для всех (идти строго по порядку):**
1. Корректность на обычном входе.
2. Граничные входы: пусто, `None`, один элемент, пробелы и юникод для строк.
3. Ресурсы: файлы, соединения (`with`).
4. Побочные эффекты: мутирует ли функция то, что ей передали или что лежит между вызовами.
5. Переносимость: кодировка, пути, ОС.
6. Контракт: type hints, docstring, понятные исключения.

**Правило для спорных случаев:** если в условии задания поведение не описано, это MINOR плюс вопрос стажёру, а не MAJOR. Одинаково для всех.

## 2. Разбор

### Аня: `add_tag`: BLOCKER

**Проблема:** значение по умолчанию `[]` вычисляется один раз, при определении функции, и дальше переиспользуется во всех вызовах.

```python
add_tag("a")  # ['a']
add_tag("b")  # ['a', 'b'], ожидалось ['b']
```

**Почему это важно:** функция молча возвращает неверные данные, а баг проявляется только со второго вызова. Такое тяжело поймать в проде. Второй момент: если передать свой список, функция его мутирует. Это может быть задумано, а может и нет, так что об этом стоит спросить.

**Вариант исправления:**
```python
def add_tag(tag: str, tags: list[str] | None = None) -> list[str]:
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
```
Если мутация не нужна: `return [*(tags or []), tag]`.

**Хорошо:** функция короткая, имя понятное.

### Борис: `read_config`: MAJOR

**Проблема 1, ресурс:** файл открыт без `with` и не закрывается явно. В CPython его, скорее всего, закроет сборщик мусора, но это деталь реализации. Если `json.load` бросит исключение, дескриптор повиснет до сборки.

**Проблема 2, переносимость:** `open()` без `encoding` берёт кодировку из локали. На Windows с cp1251 UTF-8 конфиг с кириллицей упадёт с `UnicodeDecodeError`.

**Вариант исправления:**
```python
import json
from pathlib import Path
from typing import Any

def read_config(path: str | Path) -> Any:
    with open(path, encoding="utf-8") as f:
        return json.load(f)
```

**Для обсуждения (не дефект):** `FileNotFoundError` и `json.JSONDecodeError` уходят наружу как есть. Для такой функции это, на мой взгляд, нормально, заглушать их хуже.

**Хорошо:** использован `json.load`, а не ручной `read()` + `loads`, и никакой лишней логики.

### Вика: `average`: MINOR (MAJOR, если пустой ввод упомянут в условии)

**Проблема:** `average([])` бросает `ZeroDivisionError`. Сообщение ничего не говорит вызывающему коду о причине. Кроме того, генератор не пройдёт: у него нет `len()`, будет `TypeError`.

**Почему только MINOR:** бросить исключение на пустом входе — законное поведение (`statistics.mean` делает так же). Недочёт в том, что исключение непонятное и нигде не задокументировано.

**Вариант исправления:**
```python
from collections.abc import Sequence

def average(nums: Sequence[float]) -> float:
    if not nums:
        raise ValueError("average() requires at least one number")
    return sum(nums) / len(nums)
```
Можно предложить и `statistics.fmean`: он принимает любые iterable и на пустом входе бросает `StatisticsError`.

**Хорошо:** решение идиоматичное, без ручного цикла.

### Гоша: `slugify`: MINOR (MAJOR, если в условии был «URL-safe slug»)

**Проблема:** удаляются только пробелы.

```python
slugify("Hello, World!")  # 'hello,-world!'
slugify("a - b")          # 'a---b'
```
Обычно под slug понимают строку из букв, цифр и одиночных дефисов, так что результат расходится с общепринятым смыслом имени.

**Вариант исправления:**
```python
import re

def slugify(title: str) -> str:
    slug = re.sub(r"[^\w\s-]", "", title.lower())
    return re.sub(r"[-\s]+", "-", slug).strip("-")
```
Кириллица сохранится (`\w` в Python 3 юникодный). Если нужен чистый ASCII, понадобится транслитерация, и это вопрос к условию.

**Хорошо:** есть type hints (единственный из четырёх), корректно работают множественные пробелы и пробелы по краям (`split()` без аргументов), пустая строка даёт `""` без падения.

**Про type hints у остальных:** если условие их не требовало, это NIT для всех троих, а не минус. Важно отметить это одинаково, иначе Гоша получит неявное преимущество, а остальные — неявный штраф.

## Шкала (единая для всех)

- **BLOCKER**: неверный результат *без ошибки*, порча данных, уязвимость. Проявляется при обычном использовании.
- **MAJOR**: утечка ресурсов, поведение зависит от окружения (ОС, локаль), падение на входе, который в ТЗ явно разрешён.
- **MINOR**: граничный случай, на котором функция падает *громко* и понятно, но сообщение можно сделать лучше; вход, который ТЗ не описывает.
- **NIT**: стиль, именование, отсутствие type hints/docstring, **если ТЗ их не требовало**.
- **POSITIVE**: хотя бы одно на каждого.

Правило для спорного случая: если ошибка зависит от трактовки ТЗ, оценка не снижается, а стажёру задаётся вопрос.

## 1. Аня: `add_tag`

**[BLOCKER] Изменяемый аргумент по умолчанию**
Значение `[]` создаётся один раз, при определении функции, а не при каждом вызове:

```python
add_tag("a")  # ['a']
add_tag("b")  # ['a', 'b']  ← теги "протекли" из прошлого вызова
```

**Почему это важно:** результат неверный, а ошибки нет. Такие баги ищут дольше всего.

**Второй момент (вопрос, а не ошибка):** если список передан снаружи, функция его меняет. Если так задумано, это стоит отразить в названии или в docstring.

**Как исправить:**
```python
def add_tag(tag: str, tags: list[str] | None = None) -> list[str]:
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
```

**[POSITIVE]** Функция короткая и делает одно дело.

## 2. Борис: `read_config`

**[MAJOR] Файл не закрывается**
`open()` без `with`: если `json.load` бросит исключение (битый JSON), файл останется открытым до сборки мусора. В CPython при нормальном ходе он обычно закроется сам, но это деталь реализации, а не гарантия. В долгоживущем процессе так накапливаются незакрытые дескрипторы, а в режиме разработки Python выдаёт `ResourceWarning`.

**[MAJOR] Не указана кодировка**
Без `encoding=` берётся кодировка локали. Если в конфиге есть кириллица, на Windows он может прочитаться иначе, чем на Linux. (Насколько помню, UTF-8 по умолчанию сделают в будущих версиях Python по PEP 686, но в 3.11 это не так. Номер версии не проверял.)

**Как исправить:**
```python
import json
from pathlib import Path
from typing import Any

def read_config(path: str | Path) -> Any:
    with open(path, encoding="utf-8") as f:
        return json.load(f)
```

**[POSITIVE]** Ошибки (`FileNotFoundError`, `json.JSONDecodeError`) не глотаются, а уходят наверх. Для функции чтения конфига это правильно.

Ошибки две, но это одна тема: «работа с файлом». Засчитывать как один MAJOR, иначе у Бориса окажется «больше замечаний» просто потому, что у него больше строк.

## 3. Вика: `average`

**[MINOR] Пустой ввод**
`average([])` бросает `ZeroDivisionError`. Падение громкое, данные не портятся, поэтому это MINOR. Но сообщение вводит в заблуждение: деления на ноль в логике нет, есть пустой ввод. Если в ТЗ пустой список явно допустим, уровень поднимается до MAJOR.

**[MINOR] Работает только с последовательностями**
Генератор (`average(x for x in data)`) упадёт на `len()` с `TypeError`. Ошибка ли это, зависит от ТЗ.

**Как исправить:**
```python
def average(nums: list[float]) -> float:
    if not nums:
        raise ValueError("average() requires at least one number")
    return sum(nums) / len(nums)
```
Можно упомянуть `statistics.fmean`: в стандартной библиотеке это уже есть.

**[POSITIVE]** Решение прямолинейное и читаемое, без лишних абстракций.

## 4. Гоша: `slugify`

**[Зависит от ТЗ] Не удаляется пунктуация и не-ASCII**
```python
slugify("Hello, World!")  # 'hello,-world!'
slugify("Привет мир")     # 'привет-мир'
```
Если slug идёт в URL, это **MAJOR**: запятые, `!`, `?`, `/` в URL ломают ссылки или требуют экранирования. Если по ТЗ нужно было только «пробелы в дефисы и нижний регистр», функция корректна. Спросить у Гоши, как он понял задачу, а не снижать оценку молча.

**Возможное решение (для URL-slug):**
```python
import re

def slugify(title: str) -> str:
    words = re.findall(r"\w+", title.lower())
    return "-".join(words)
```
(Кириллицу `\w` оставит. Транслитерация уже вопрос требований.)

**[POSITIVE]** Единственный, кто поставил type hints. `split()` без аргументов правильно схлопывает множественные пробелы и табы, края тоже обрезаются.
