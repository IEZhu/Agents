**Short answer:** A and C need only simple reformatting. B needs a date swap and German number parsing. D is the trap: its signs are **reversed** relative to your target, so every amount has to be multiplied by −1. Two more things will affect the combined sheet whichever method you use: **mixed currencies** and **transfers between your own accounts**, which get counted twice.

## Per-account conversion

| | Date → YYYY-MM-DD | Description | Amount → (− out / + in) |
|---|---|---|---|
| **A** US checking | `MM/DD/YYYY` → `03/04/2024` = **2024-03-04** (March 4) | `Description` | `Amount` as-is (already − = out) |
| **B** German current | `DD.MM.YYYY` → `03.04.2024` = **2024-04-03** (April 3) | `Verwendungszweck` | `Betrag`: delete `.` (thousands), then `,` → `.` → `-1.150,00` = **-1150.00**; sign already correct |
| **C** UK credit card | already ISO, keep | `Details` | `Credit − Debit`, blank = 0 → TESCO = **-23.10**, payment = **+300.00** |
| **D** US credit card | `MM/DD/YYYY` | `Payee` | **`−1 × Amount`** → AMAZON = **-45.99**, AUTOPAY = **+500.00** |

### Details that will bite you

- **A and D in a spreadsheet app:** if your Excel/Sheets locale is non-US, it will auto-parse `03/04/2024` as 3 April, and it does this silently. Import date columns **as text**, then convert with a formula:
  - A/D: `=DATE(RIGHT(A2,4), LEFT(A2,2), MID(A2,4,2))`
  - B: `=DATE(RIGHT(A2,4), MID(A2,4,2), LEFT(A2,2))`
  - Format the result as `yyyy-mm-dd`.
- **B file format:** the delimiter is `;`, not `,`. German bank exports often include a few preamble lines (account number, period, balance) above the header, and are often encoded as Windows-1252/ISO-8859-1 rather than UTF-8. Umlauts showing up as `Ã¼` means the encoding is wrong. Amount formula with Betrag imported as text: `=VALUE(SUBSTITUTE(SUBSTITUTE(C2,".",""),",","."))`. That formula assumes your spreadsheet locale uses `.` as the decimal separator.
- **C:** `=N(D2)-N(C2)`, where C = Debit and D = Credit. Refunds land in Credit and come out positive, which is correct.
- **D's sign:** your two sample rows strongly suggest that positive = charge (the card issuer's point of view). Before trusting that, confirm it against one known refund or payment on the statement.

## Two issues that affect the whole sheet

1. **Currency:** A and D are USD, B is EUR, C is GBP. Add a `currency` column. Summing −54.20 USD with −1150.00 EUR gives a meaningless number. Either keep totals per currency or add a converted column using a documented rate (by date or monthly average).
2. **Double counting:** paying off a credit card appears twice. For example, D's `AUTOPAY PAYMENT +500.00` probably has a matching −500.00 in checking A, and C's `PAYMENT RECEIVED` matches an outflow from whichever account paid it. Add a `category` or `is_transfer` column and exclude transfers from spending and income totals. Otherwise your spending looks higher by the full value of every card payment.

## Making new banks painless: describe each bank with 6 answers, not new logic

Every bank export differs from the others in only these ways:

| # | Question | How to answer it |
|---|---|---|
| 1 | Delimiter, encoding, header/preamble rows to skip | Open the file in a plain text editor |
| 2 | Date format | Find a row where the day is > 12. That settles DD/MM vs MM/DD. |
| 3 | Decimal and thousands separators | Look for an amount ≥ 1,000 |
| 4 | One signed amount column, or split Debit/Credit (or an amount plus a "D/C"/"S/H" indicator column) | Header row |
| 5 | Sign convention: whose point of view? | Check one known purchase and one known payment/refund. Credit cards are often reversed. |
| 6 | Currency | Account statement |

Put those answers in a small config table and use one converter for all banks. Adding a bank, or your friend's banks, then means adding one profile rather than writing new logic:

```python
import pandas as pd

# One profile per account. Adding a bank = adding one entry here.
PROFILES = {
    "A_us_checking": dict(file="a.csv", sep=",", encoding="utf-8", skiprows=0,
                          date="Date", date_fmt="%m/%d/%Y", desc="Description",
                          amount="Amount", dec=".", thou=",", sign=1, currency="USD"),
    "B_de_current":  dict(file="b.csv", sep=";", encoding="cp1252", skiprows=0,
                          date="Buchungstag", date_fmt="%d.%m.%Y", desc="Verwendungszweck",
                          amount="Betrag", dec=",", thou=".", sign=1, currency="EUR"),
    "C_uk_card":     dict(file="c.csv", sep=",", encoding="utf-8", skiprows=0,
                          date="Transaction Date", date_fmt="%Y-%m-%d", desc="Details",
                          debit="Debit", credit="Credit", dec=".", thou=",", sign=1, currency="GBP"),
    "D_us_card":     dict(file="d.csv", sep=",", encoding="utf-8", skiprows=0,
                          date="Posted Date", date_fmt="%m/%d/%Y", desc="Payee",
                          amount="Amount", dec=".", thou=",", sign=-1, currency="USD"),
}

def to_number(s, dec, thou):
    s = s.astype(str).str.strip().str.replace(r"[^\d,.\-]", "", regex=True)  # drop currency symbols/spaces
    if thou:
        s = s.str.replace(thou, "", regex=False)
    if dec != ".":
        s = s.str.replace(dec, ".", regex=False)
    return pd.to_numeric(s, errors="raise")

def convert(name, p):
    df = pd.read_csv(p["file"], sep=p["sep"], dtype=str, encoding=p["encoding"],
                     skiprows=p["skiprows"])
    df.columns = df.columns.str.strip()
    out = pd.DataFrame()
    # format= makes it fail loudly on a wrong date format instead of guessing
    out["date"] = pd.to_datetime(df[p["date"]].str.strip(), format=p["date_fmt"]).dt.strftime("%Y-%m-%d")
    out["description"] = df[p["desc"]].str.strip()
    if "amount" in p:
        amt = to_number(df[p["amount"]], p["dec"], p["thou"])
    else:  # split debit/credit columns; blank = 0
        amt = (to_number(df[p["credit"]].fillna("0"), p["dec"], p["thou"])
               - to_number(df[p["debit"]].fillna("0"), p["dec"], p["thou"]))
    out["amount"] = (amt * p["sign"]).round(2)
    out["currency"] = p["currency"]
    out["account"] = name
    print(f"{name}: {len(out)} rows, net {out['amount'].sum():.2f} {p['currency']}")
    return out

all_tx = pd.concat([convert(n, p) for n, p in PROFILES.items()], ignore_index=True)
all_tx.sort_values("date").to_csv("combined.csv", index=False)
print("Saved: combined.csv")
```

I haven't run this against your actual files. The `cp1252` encoding for B and the absence of preamble rows are guesses, so adjust `encoding`/`skiprows` if the read fails. Pandas and `format=` are strict on purpose: a mismatched profile raises an error rather than producing wrong dates.

## Validate each account once, when you add it

- **Row count** matches the export.
- **Net sum per account** matches the statement's closing balance minus its opening balance. For a credit card, the balance owed moves the opposite way, so the net should equal minus the change in balance owed. A sign error on one account shows up here straight away.
- **Spot-check 2–3 rows**, including one where the day is > 12 and one amount ≥ 1,000.
