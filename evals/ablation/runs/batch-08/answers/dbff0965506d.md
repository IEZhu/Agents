**No, Node 20 is no longer getting security fixes. Standardize on Node 24 LTS (`node:24-alpine`). It is supported until April 30, 2028.**

I haven't checked these dates against the live schedule for this answer. They come from memory of the Node.js release schedule, so check them at https://github.com/nodejs/Release or https://nodejs.org/en/about/previous-releases before they go into the doc.

| Line | Status (late Sep 2026) | End of life |
|---|---|---|
| Node 20 | **EOL** | Apr 30, 2026 |
| Node 22 | Maintenance LTS (security fixes only) | Apr 30, 2027 |
| **Node 24** | Active LTS, moving to Maintenance around Oct 2026 | **Apr 30, 2028** |
| Node 26 | Current, expected to become LTS around Oct 2026 | around Apr 2029 |

**Why 24 and not the others**
- **Node 20:** your 14 services have been running an unsupported runtime for about 5 months. Treat this as security debt to fix in Q4, not something that can wait.
- **Node 22:** support ends in about 7 months. If you standardize on it, you'll have to migrate again in mid-2027. Skip it.
- **Node 24:** it has been LTS for about a year, so the ecosystem has had time to catch up. It covers your planning horizon with more than a year to spare.
- **Node 26:** it gives the longest runway, but it only becomes LTS around the time you'd start. Expect some native addons and tooling to lag. It makes sense as the 2027 target, not now.

**Planning doc line**
> Target: Node.js 24 LTS (`node:24-alpine`, pinned by digest) across all API services by end of Q4 2026 (Dec 31, 2026). Node 20 EOL was Apr 30, 2026; Node 24 EOL is Apr 30, 2028. Next upgrade (to Node 26 LTS) planned for H2 2027.

**Migration notes**
- Pin images by tag plus digest (`node:24.x.y-alpine@sha256:...`), and let Renovate or Dependabot bump patch versions.
- Check framework support: Express 4/5 and NestJS 10/11 should run on 24. I believe that's right, but confirm against each project's `engines` field and changelog.
- Main risks: native addons such as `bcrypt`, `sharp` and `node-gyp` builds, which need rebuilt binaries for 24 on Alpine/musl. Also crypto and OpenSSL behavior changes and removed deprecated APIs. Run `npm ls` and check for native deps first.
- Rollout: do a CI matrix build on 20 and 24, move 1–2 low-traffic services first, then the rest. The blast radius is one service per deploy.
- Rollback: redeploy the previous `node:20-alpine` image tag. It's an image swap, with no data or state change.
