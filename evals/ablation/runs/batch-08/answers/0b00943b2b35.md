**Short answer:** all three problems come from the same cause. You are fetching Wayback's *rewritten playback* pages one by one. Split the job into stages: (1) one CDX query that dedups on the server, (2) raw `id_` fetches of the unique captures only, slow and cached to disk, (3) offline parsing, and (4) diffing the *extracted* plans instead of the HTML. With that setup, 1,400 captures typically drops to a few dozen fetches.

---

## 1. Why your md5 dedup fails, and what to use instead

What you download from `web.archive.org/web/<ts>/...` is not the page as captured. Wayback injects its toolbar, scripts and banner comments, and those include the capture timestamp and playback metadata. It also rewrites every URL to include the timestamp. So every capture hashes differently even when the site did not change.

The fix is to dedup **before** you fetch, using the CDX index:

- Every CDX row has a `digest` field. It is a hash of the *original* captured payload, not of the rewritten playback.
- `collapse=digest` makes the server drop rows whose digest matches the previous row. That is exactly "skip captures where nothing changed."

```
https://web.archive.org/cdx/search/cdx
  ?url=acme-analytics.io/pricing
  &from=20220901&to=20250925
  &output=json
  &fl=timestamp,original,statuscode,mimetype,digest
  &filter=statuscode:200
  &filter=mimetype:text/html
  &collapse=digest
```

Caveats:
- `collapse=digest` only collapses **adjacent** identical rows. If the page flips A→B→A, you get three rows. That is fine, because that is a real change history.
- **Dynamic junk defeats digests too.** A CSRF token, a nonce, a build hash in `<script src>`, or "© 2024" in the footer changes the digest while the prices stay the same. So add a second dedup layer after parsing (stage 4). The digest cuts fetches; the parsed tuple decides what counts as a real change.
- If you don't need daily resolution, `collapse=timestamp:8` gives one capture per day and `timestamp:6` one per month. Use it with or instead of `collapse=digest` for a rough first pass.
- Check whether the prices are even in the HTML. Many pricing pages render from JS or a JSON endpoint. If the parsed plans come out empty for some captures, query CDX for `acme-analytics.io/*` and look for something like `/api/plans` or `pricing.json`, then parse that instead.

## 2. Junk in your selectors and web.archive.org links

This is the same rewriting problem. Request the **raw capture** by adding `id_` right after the timestamp:

```
https://web.archive.org/web/20230415120000id_/https://acme-analytics.io/pricing
```

That returns the archived bytes without the toolbar, injected scripts or rewritten links. Your selectors then only see the competitor's own markup, and `href`s point back to their domain (or stay relative).

Further hardening:
- **Scope your selectors** to the pricing container (for example the section that holds the plan cards), not `soup.find_all("h3")`. Sites redesign, so expect 2–4 selector variants over 3 years. Write one small parser per layout era and pick the one that returns plausible data.
- **Check the served timestamp.** Wayback may redirect you to the *nearest* capture if the exact one isn't playable. Follow redirects, read the timestamp from `resp.url`, and store that one instead of the timestamp you asked for.
- Skip or record separately any capture whose final URL moved off `/pricing`, for example a redirect to `/plans` or the homepage after a restructure.

## 3. Errors and connection resets

Resets after a few hundred rapid requests look like Wayback rate limiting or a temporary block, not a bug in your code. archive.org is a nonprofit and throttles aggressive clients. I don't know its exact current limits, so treat any specific number as a guess and tune from observed behavior. With dedup, though, you will likely need only tens of requests, so this problem mostly goes away.

- **Go sequential and slow:** roughly 1 request per second, no parallelism.
- **Reuse one `requests.Session`** with keep-alive, and set a descriptive `User-Agent` with contact info.
- **Retry with exponential backoff** on 429, 5xx, `ConnectionError` and `ChunkedEncodingError`. Honor `Retry-After` if it is present. If you keep getting resets, stop for several minutes; hammering can extend a block.
- **Cache every response to disk** keyed by timestamp (or digest). A crash then resumes where it stopped, and you never re-download to tweak a selector.

## Restructured pipeline

```python
import json, time, random, pathlib, hashlib
import requests
from bs4 import BeautifulSoup

CACHE = pathlib.Path("wb_cache"); CACHE.mkdir(exist_ok=True)
S = requests.Session()
S.headers["User-Agent"] = "pricing-history-research (you@example.com)"

def get(url, max_tries=6):
    for i in range(max_tries):
        try:
            r = S.get(url, timeout=60)
            if r.status_code == 200:
                return r
            if r.status_code in (429, 500, 502, 503, 504):
                wait = int(r.headers.get("Retry-After", 0)) or 2 ** i * 5
            else:
                r.raise_for_status()
        except (requests.ConnectionError, requests.exceptions.ChunkedEncodingError):
            wait = 2 ** i * 5
        time.sleep(wait + random.random())
    raise RuntimeError(f"giving up on {url}")

# Stage 1: one CDX query, server-side dedup
cdx = get(
    "https://web.archive.org/cdx/search/cdx"
    "?url=acme-analytics.io/pricing&from=20220901&to=20250925&output=json"
    "&fl=timestamp,original,statuscode,mimetype,digest"
    "&filter=statuscode:200&filter=mimetype:text/html&collapse=digest"
).json()
rows = [dict(zip(cdx[0], r)) for r in cdx[1:]]
print(len(rows), "unique captures")

# Stage 2: raw fetch, cached, throttled
def fetch_raw(ts, original):
    path = CACHE / f"{ts}.html"
    if path.exists():
        return path.read_bytes()
    r = get(f"https://web.archive.org/web/{ts}id_/{original}")
    path.write_bytes(r.content)
    (CACHE / f"{ts}.meta.json").write_text(json.dumps({"final_url": r.url}))
    time.sleep(1.0)
    return r.content

# Stage 3: offline parse (scope to the pricing container; add variants per redesign)
def parse(html):
    soup = BeautifulSoup(html, "html.parser")
    plans = []
    for card in soup.select("[class*=pricing] [class*=plan], [class*=pricing-card]"):
        name = card.select_one("h2, h3")
        price = card.select_one("[class*=price]")
        if name and price:
            plans.append((name.get_text(strip=True), price.get_text(" ", strip=True)))
    return tuple(sorted(plans))

# Stage 4: dedup on extracted content, emit change log
timeline, last = [], None
for row in rows:
    plans = parse(fetch_raw(row["timestamp"], row["original"]))
    if not plans:
        print("no plans parsed:", row["timestamp"])  # new layout or JS-rendered: inspect
        continue
    if plans != last:
        timeline.append({"timestamp": row["timestamp"], "plans": plans})
        last = plans

json.dump(timeline, open("pricing_timeline.json", "w"), indent=2)
```

The selectors above are placeholders. Open 2–3 cached raw captures from different years and write the real ones.

Notes:
- **Log the parse failures** ("no plans parsed"). That list shows you exactly when they redesigned, which is often itself a pricing event.
- **Normalize prices** before comparing, so that whitespace, `$49/mo` vs `$49 / month`, or monthly/annual toggle defaults don't create false changes. Record which billing period the static HTML shows by default.
- **Coverage gaps are not "no change."** If CDX has no capture for a period, a price change could fall in the gap. Report each change as "between capture X and capture Y," not as an exact date.
