All three problems come from fetching the *replayed* page, which the Wayback Machine rewrites, when you want the *original* capture. Here's how I'd restructure it:

1. **Dedupe from the CDX index before downloading anything.** Don't hash the HTML you download.
2. **Fetch raw captures with the `id_` modifier.** That removes the toolbar junk and the rewritten links.
3. **Split the job into stages, fetch slowly, and cache everything to disk.** You'll only fetch a few dozen pages instead of 1,400, and you'll never fetch the same one twice.

---

## 1. Why your hashes all differ, and the fix

When you request `web.archive.org/web/<timestamp>/url`, you get the capture after replay has altered it. Wayback injects its banner/toolbar scripts, comment blocks with the capture timestamp and other replay metadata, and rewrites every URL in the page to point back through `web.archive.org/web/<timestamp>/...`. Because the timestamp is part of the page, two byte-identical captures still produce different MD5s.

The fix is to use the `digest` field the CDX API already gives you. It's a hash of the original archived payload, computed at crawl time. Ask for it and dedupe on it:

```
https://web.archive.org/cdx/search/cdx
  ?url=acme-analytics.io/pricing
  &from=2023&to=2026
  &output=json
  &fl=timestamp,original,statuscode,mimetype,digest
  &filter=statuscode:200
  &filter=mimetype:text/html
  &collapse=digest
```

Things to know about this query:

- **`collapse=digest` only merges adjacent duplicates.** A page that goes A → B → A still gives you three rows. Also keep a `seen_digests` set in Python.
- **`filter=statuscode:200`** drops redirects (3xx) and error captures. Those are probably part of your "junk".
- **URL variants:** check whether captures exist under `www.`, with a trailing slash, or with query strings like `?ref=...` or `?billing=annual`. To see what's there, run a separate query with `matchType=prefix`, or with `url=acme-analytics.io/pricing*`, and without `collapse`.
- **Nonces still defeat digest dedupe.** If their HTML embeds per-request values such as CSRF tokens, build hashes or nonces, many digests will still be unique. In that case, dedupe on the *extracted* data instead: parse out plan names and prices, normalize them, and hash that tuple. Only a change in that hash counts as a "change".

A further trick, since pricing changes rarely: **bisect the timeline.** Fetch the first and last capture in a range. If the extracted pricing is identical, assume nothing changed in between and skip the range; if it differs, split the range and recurse. This finds every change point in roughly O(changes × log n) fetches. The risk is missing an A → B → A change inside a skipped range. That's usually acceptable for pricing, but you can sample a few midpoints to guard against it.

## 2. Junk in your selectors and links pointing to web.archive.org

Add `id_` right after the timestamp:

```
https://web.archive.org/web/20240115093000id_/https://acme-analytics.io/pricing
```

`id_` asks Wayback for the original bytes as captured: no toolbar, no injected scripts, no URL rewriting. Links will point to `acme-analytics.io` again, and your selectors will only see their markup.

Other likely causes of junk, even with `id_`:

- **Client-side rendering.** If their pricing page is a React/Next.js/Vue app, the HTML might contain only an empty shell plus a JSON blob, and your selector ends up matching something else. Check a few raw captures by hand. Prices are often easier to get from embedded JSON (`<script id="__NEXT_DATA__">`, `window.__INITIAL_STATE__`, JSON-LD) than from the DOM. If prices come from a separate API call, look in the CDX index for that endpoint, because Wayback sometimes captured it on its own.
- **Redesigns.** Over three years the markup almost certainly changed. Don't use a single selector. Write a small list of extractor functions, try them in order, and log which one matched. Make an empty result fail loudly so it doesn't silently return garbage.
- **Soft-404s / interstitials.** A 200 capture can still be a login wall, cookie wall, Cloudflare challenge or maintenance page. Reject pages where no plan or price is found, and don't record them as "prices disappeared".

## 3. Errors and connection resets

This is almost certainly rate limiting. The Internet Archive throttles aggressive clients and may block an IP temporarily if you keep going after errors. I believe the commonly cited guidance is around 15 requests per minute for replay (recalled, not verified; check the Internet Archive's current documentation or help pages), so "a few hundred requests, then resets" fits.

What to change:

- **Go slow and sequential.** One request at a time, sleeping about 4–5 seconds between requests. Once dedupe cuts 1,400 captures down to a few dozen, the whole run takes a few minutes anyway.
- **Use one `requests.Session`** so connections are reused, and set an honest `User-Agent` with contact info.
- **Retry with exponential backoff and jitter** on 429, 5xx and connection errors. Honor `Retry-After` if it's present. After repeated 429s, stop the run rather than hammering.
- **Cache every raw response to disk**, keyed by timestamp. Before fetching, check whether the file already exists. Reruns become free, and you can iterate on your parser without touching the network.

## Suggested structure

Split the one loop into three independent stages:

```
Stage 1: CDX query       -> captures.json    (one request, deduped by digest)
Stage 2: fetch raw (id_) -> raw/<ts>.html    (throttled, resumable, cached)
Stage 3: parse offline   -> prices.csv       (re-run freely, no network)
          then diff consecutive rows -> changelog
```

Sketch:

```python
import json, random, time
from pathlib import Path
import requests

UA = "pricing-history-research/1.0 (you@example.com)"
RAW = Path("raw"); RAW.mkdir(exist_ok=True)
s = requests.Session()
s.headers["User-Agent"] = UA

def get(url, max_tries=6):
    for attempt in range(max_tries):
        try:
            r = s.get(url, timeout=60)
            if r.status_code == 200:
                return r
            if r.status_code in (429, 500, 502, 503, 504):
                wait = float(r.headers.get("Retry-After", 0)) or (2 ** attempt) * 5
            else:
                r.raise_for_status()
        except (requests.ConnectionError, requests.Timeout):
            wait = (2 ** attempt) * 5
        time.sleep(wait + random.uniform(0, 3))
    raise RuntimeError(f"giving up on {url}")

# Stage 1: CDX, deduped by content digest
cdx = get(
    "https://web.archive.org/cdx/search/cdx"
    "?url=acme-analytics.io/pricing&from=2023&to=2026&output=json"
    "&fl=timestamp,original,statuscode,mimetype,digest"
    "&filter=statuscode:200&filter=mimetype:text/html&collapse=digest"
).json()
header, rows = cdx[0], cdx[1:]
seen, captures = set(), []
for row in rows:
    rec = dict(zip(header, row))
    if rec["digest"] not in seen:
        seen.add(rec["digest"])
        captures.append(rec)
Path("captures.json").write_text(json.dumps(captures, indent=1))
print(f"{len(rows)} rows -> {len(captures)} unique captures")

# Stage 2: fetch raw originals, resumable
for rec in captures:
    out = RAW / f"{rec['timestamp']}.html"
    if out.exists():
        continue
    url = f"https://web.archive.org/web/{rec['timestamp']}id_/{rec['original']}"
    out.write_bytes(get(url).content)
    time.sleep(4 + random.uniform(0, 2))

# Stage 3: parse offline (separate script) -- try extractors in order,
# normalize (plan, price, period), hash the normalized tuple,
# and emit a row only when that hash changes.
```

Two caveats about the output:

- **A capture date isn't a change date.** A change happened somewhere between the last capture showing the old price and the first showing the new one. Report it as an interval ("between 2024-03-02 and 2024-03-19"), especially when captures are sparse.
- **Crawl coverage is uneven.** Crawl frequency varies a lot over time, so a gap in the archive doesn't mean the page didn't change. For extra coverage, archive.today may have captures Wayback missed, and so may the pricing endpoint's own CDX entries if the prices load from an API.
