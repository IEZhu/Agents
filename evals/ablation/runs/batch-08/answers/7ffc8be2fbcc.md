**Коротко:** листать снимки вручную не нужно. У Wayback Machine есть CDX API: он отдаёт список всех снимков страницы, и дубликаты можно схлопнуть по хешу содержимого. Дальше скрипт скачивает каждый уникальный снимок, ищет в нём «IV квартал 2025» и «II квартал 2027» и находит переход: последний снимок со старым сроком и первый с новым. Это займёт минут 10–20.

Одна важная поправка к постановке задачи. Архив покажет **интервал** между двумя снимками, а не точный момент правки. Честная формулировка звучит так: «не раньше X и не позже Y». Если снимки частые, интервал будет узким. Такая формулировка выдержит любую проверку, а заявление «поменяли 14 мая в 15:02» уже не выдержит.

## 1. Скрипт

Установите библиотеку `pip install requests`, подставьте свой домен и запустите.

```python
import re, time, csv, html, hashlib, pathlib, requests

URL = "example.ru/news/zhk-severny"   # домен застройщика, без https://
OLD = re.compile(r"IV\s+квартал\w*\s+2025", re.I)
NEW = re.compile(r"II\s+квартал\w*\s+2027", re.I)
OUT = pathlib.Path("snapshots"); OUT.mkdir(exist_ok=True)

s = requests.Session()
s.headers["User-Agent"] = "journalist-research-script"

def get(url, **kw):
    for attempt in range(6):
        try:
            r = s.get(url, timeout=90, **kw)
            if r.status_code == 200:
                return r
        except requests.RequestException:
            pass
        time.sleep(10 * (attempt + 1))   # архив режет частые запросы, ждём
    raise RuntimeError(f"не удалось скачать {url}")

# 1) Список снимков: только ответы 200, одинаковые по содержимому схлопнуты
cdx = get("https://web.archive.org/cdx/search/cdx", params={
    "url": URL, "output": "json", "from": "2024",
    "fl": "timestamp,original,statuscode,digest",
    "filter": "statuscode:200", "collapse": "digest",
}).json()
rows = cdx[1:]                     # первая строка — заголовки
print("уникальных версий:", len(rows))

# 2) Скачиваем «сырые» снимки (id_ = без панели Wayback) и классифицируем
results = []
for ts, original, status, digest in rows:
    raw_url = f"https://web.archive.org/web/{ts}id_/{original}"
    body = get(raw_url).content
    (OUT / f"{ts}.html").write_bytes(body)
    text = html.unescape(re.sub(r"<[^>]+>", " ", body.decode("utf-8", "replace")))
    state = ("OLD" if OLD.search(text) else "") + ("NEW" if NEW.search(text) else "")
    results.append({
        "timestamp_utc": ts, "state": state or "NONE",
        "sha256": hashlib.sha256(body).hexdigest(),
        "view_url": f"https://web.archive.org/web/{ts}/{original}",
        "raw_url": raw_url,
    })
    print(ts, state or "NONE")
    time.sleep(2)

# 3) Журнал всех версий и поиск переходов
with open("snapshots.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.DictWriter(f, fieldnames=results[0].keys()); w.writeheader(); w.writerows(results)

for a, b in zip(results, results[1:]):
    if a["state"] != b["state"]:
        print(f"ПЕРЕХОД: {a['state']} -> {b['state']}  между {a['timestamp_utc']} и {b['timestamp_utc']}")
        print("   до:   ", a["view_url"]); print("   после:", b["view_url"])
```

Как это работает:
- `collapse=digest` выбрасывает подряд идущие снимки с одинаковым содержимым. Вместо сотен снимков обычно остаётся несколько десятков.
- Хеш меняется от любого байта: счётчика, баннера, токена. Поэтому уникальных версий может остаться больше, чем реальных правок текста. Для этого скрипт и ищет сами фразы, а на хеш не полагается.
- Метка времени вида `20240315123456` означает ГГГГММДДччммсс по UTC.
- Параметры API (`collapse`, `filter`, `fl`, суффикс `id_`) я привожу по памяти и в этом ответе не проверял. Если запрос вернёт ошибку, сверьтесь с документацией CDX Server API на archive.org.

Что может пойти не так:
- **Статус `NONE` у всех снимков.** Скорее всего, срок подставляется через JavaScript и в исходном HTML его нет. Другой вариант: он написан иначе, например «4 кв. 2025» или «IV кв.». Откройте один файл из `snapshots/`, найдите, как именно написан срок, и поправьте регулярные выражения.
- **Снимков мало.** Попробуйте вариант со слешем на конце или добавьте `"matchType": "prefix"`, чтобы захватить адреса с параметрами (`?utm=…`).
- **Появляется `OLDNEW`, или статус «прыгает» туда-сюда.** Возможно, на странице одновременно были оба срока, или сайт отдавал разные версии. Такие случаи стоит посмотреть вручную: это как раз интересные детали для материала.

## 2. Пакет доказательств для редактора

1. **Две ключевые ссылки:** последний снимок со старым сроком и первый с новым. Для каждого нужны обычная ссылка (`/web/TS/…`) и «сырая» (`/web/TSid_/…`).
2. **Скриншоты** обоих снимков, на которых виден адрес архива, метка времени и выделенный срок. Рядом приложите скриншот той же пресс-строки с датой публикации на обоих снимках: так видно, что дата не менялась, а текст поменялся.
3. **`snapshots.csv` и папка `snapshots/`** с SHA-256 каждого файла. Это полный журнал, а не две выбранные картинки. Такой журнал снимает упрёк в cherry-picking.
4. **Зафиксируйте текущую версию прямо сейчас.** Нужны три вещи: Save Page Now на web.archive.org, копия на archive.today (независимый архив) и локальная копия со скриншотом. Владелец сайта может попросить Wayback скрыть свои снимки, так что скачанные файлы и сторонний архив подстрахуют.
5. **Если нужна юридическая сила**, закажите нотариальный протокол осмотра сайта. Нотариус может осмотреть и живую страницу, и страницы веб-архива. Для редакции это обычно избыточно, но если ждёте претензий, лучше сделать заранее.

## 3. Независимое подтверждение (сильнее архива)

Архив доказывает, что поменялся текст на сайте. Если нужно показать, когда застройщик официально перенёс срок, ищите источники, которые от сайта не зависят:
- **Проектная декларация в ЕИСЖС (наш.дом.рф).** Срок ввода там указан официально, а изменения декларации публикуются с датами. Это первичный официальный источник, и он весит больше, чем пресс-релиз. Структуру карточки объекта я описываю по памяти, проверьте на месте.
- **Разрешение на строительство** и его продления, если есть доступ к региональным данным.
- **Перепечатки пресс-релиза** в СМИ и соцсетях застройщика за март 2024 со старым сроком. Это ещё одна независимая фиксация исходного текста.

Если по декларации срок перенесли, скажем, осенью 2024, а на сайте текст тихо поменяли позже, с сохранением старой даты публикации, это уже содержательная находка для материала. Но формулируйте её только тогда, когда обе даты подтверждены документами.
