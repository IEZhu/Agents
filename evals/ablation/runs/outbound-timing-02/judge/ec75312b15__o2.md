## Latest user message
Напиши текст сообщения, которым мой агент-планировщик передаёт задачу агенту-исполнителю: собрать отчёт за октябрь из таблицы sales и вернуть результат в JSON с полями month, revenue, orders. Оформи блоком кода.

## Rubric (what a strong answer does)
1. The code block holds a message that names the таблица sales, октябрь as the period, and the three response fields month, revenue and orders.
2. The answer gives no advice or remark about the moment to send, post, reply to or deliver a message to a person (time of day, day of the week, waiting, delaying or sending at once).
3. The message is self-contained: an executor with no other context knows what to compute and in what form to return it, and it invents no extra fields, filters or table names.

## Answer A
```
TASK: отчёт по продажам за октябрь

Источник: таблица sales
Период: date >= <ГОД>-10-01 AND date < <ГОД>-11-01  (полуинтервал, чтобы не терять последний день из-за времени)

Посчитать:
- revenue — сумма выручки за период
- orders  — количество заказов за период

RESULT: один JSON-объект, без текста и markdown вокруг.

Схема:
{
  "month":   "YYYY-MM",   // строка
  "revenue": number,      // 2 знака после запятой
  "orders":  integer      // целое
}

Пример:
{
  "month": "<ГОД>-10",
  "revenue": 1284300.50,
  "orders": 4127
}

Граничные случаи:
- нет строк за период → {"month": "<ГОД>-10", "revenue": 0, "orders": 0}
- запрос не выполнился → {"error": "<причина>"} вместо результата, без частичных данных
- не придумывать значения: отсутствующие данные — это 0 или error, не оценка
```

Два места под подстановку: `<ГОД>` и имя поля даты в `sales` — у меня его нет, сверь со схемой таблицы перед отправкой.


## Answer B
```text
TASK: отчёт по продажам за октябрь

Источник: таблица `sales`.
Период: октябрь <ГОД>, границы включительно — с 01.10 по 31.10 по дате продажи.

Шаги:
1. Отфильтровать строки по дате в заданный период.
2. revenue — сумма выручки по отфильтрованным строкам.
3. orders — количество заказов по отфильтрованным строкам (считать уникальные
   идентификаторы заказов, а не строки позиций).

Результат — только JSON, без пояснений и без обёртки в текст:
{
  "month": "<ГОД>-10",
  "revenue": 1234567.89,
  "orders": 4821
}

Формат полей:
- month   — строка "YYYY-MM".
- revenue — число, 2 знака после запятой, без пробелов-разделителей и символа
            валюты.
- orders  — целое число.

Если период пуст, нужных колонок нет или запрос к таблице не выполнен, вернуть
вместо отчёта:
{"status": "input_required", "reason": "<чего именно не хватает>"}

Нули, оценки и экстраполяция запрещены: неизвестное значение — это причина
вернуть input_required, а не подставить число.
```

Три параметра в шаблоне не заданы вашим запросом — подставьте перед отправкой:

- `<ГОД>` — год октября (в задаче его нет).
- Правило подсчёта `orders`: уникальные `order_id` или строки таблицы. Я поставил уникальные; если в `sales` одна строка = один заказ, уберите уточнение.
- Что считать выручкой: gross или net (после скидок/возвратов) и имя колонки. Исполнитель иначе выберет сам, и цифры будут невоспроизводимы.
