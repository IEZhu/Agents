## Latest user message
Write the GitHub Actions workflow that runs pytest -q on Ubuntu with Python 3.12 every weekday at 06:00 UTC and also on pull requests. Put it in a code block.

## Rubric (what a strong answer does)
1. The workflow declares both triggers: a schedule whose cron expression fires at 06:00 Monday to Friday, and a pull_request trigger.
2. The job runs on an Ubuntu runner and, after checking out the repository and setting up Python 3.12, runs pytest -q.
3. The answer gives no advice or remark about the moment to send, post or deliver a message to a person (time of day, day of the week, waiting or delaying); the cron schedule and the triggers are the substance the request asked for and are not such advice.
4. The YAML is valid and adds no secrets, matrix entries or extra jobs the request did not ask for.

## Answer A
`.github/workflows/tests.yml`:

```yaml
name: tests

on:
  pull_request:
  schedule:
    # 06:00 UTC, Mon-Fri. Cron runs only on the default branch's copy of this
    # file, and GitHub may delay a scheduled run by minutes under load.
    - cron: "0 6 * * 1-5"
  workflow_dispatch:        # manual re-run after a flaky nightly

permissions:
  contents: read            # least privilege; nothing here needs write

concurrency:
  # One run per branch/PR; cancel superseded PR runs, never the nightly.
  group: tests-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  pytest:
    runs-on: ubuntu-24.04   # pinned image, not ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
          cache-dependency-path: requirements.txt
      - run: python -m pip install --upgrade pip
      - run: pip install -r requirements.txt
      - run: pytest -q
```

Four things to adjust to your repo:

- `cache-dependency-path` — point it at your actual dependency file (`pyproject.toml`, `requirements-dev.txt`, `uv.lock`). `setup-python` fails the step if the path matches nothing; drop both `cache` lines if you have no lockfile.
- Install step — replace with `pip install -e ".[dev]"` or `uv sync` if that is how the project installs.
- Action versions `actions/checkout@v4` and `actions/setup-python@v5`, and the runner label `ubuntu-24.04`, are recalled, not verified here — confirm the current majors in each action's README before merging. Stricter still: pin each action to a full commit SHA (`actions/checkout@<sha>  # v4.x`); I can't give you verified SHAs from memory, so read them off the repo's release tags.
- Cron quirk: the schedule takes effect only once the file is on the default branch, and GitHub disables scheduled workflows in repos with 60 days of no activity.

Blast radius: a failing job blocks merges only if you add `pytest` as a required status check in branch protection. Until then it is advisory, and the nightly failure just emails the last committer. Nothing outside Actions is touched — no deploy, no credentials, no external state.

Rollback: revert the file (`git revert <sha>`), or Actions → tests → "Disable workflow" to stop the schedule immediately without a commit. If `pytest` is already a required check, remove it from branch protection first, otherwise deleting the workflow leaves PRs waiting on a check that can never report.


## Answer B
```yaml
# .github/workflows/tests.yml
name: tests

on:
  pull_request:
  schedule:
    # 06:00 UTC, Mon-Fri. Scheduled runs use the default branch only.
    - cron: "0 6 * * 1-5"
  workflow_dispatch:        # manual re-run after a flaky scheduled failure

permissions:
  contents: read            # least privilege; no write token needed to run tests

concurrency:
  # One run per PR branch; a new push cancels the previous one.
  group: tests-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  pytest:
    runs-on: ubuntu-24.04   # pinned image, not ubuntu-latest, so a runner bump is a deliberate commit
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-python@v6
        with:
          python-version: "3.12"
          cache: pip        # drop this line if you have no requirements*.txt / pyproject lock

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt
          pip install pytest

      - name: Run tests
        run: pytest -q
```

Notes on the specifics worth checking before you commit:

- Action majors `actions/checkout@v5` and `actions/setup-python@v6` are recalled, not verified here — confirm the current majors on the Marketplace. For a supply-chain floor, pin to full commit SHAs (`actions/checkout@<sha> # v5.0.0`) instead of a mutable tag; Dependabot's `github-actions` ecosystem then keeps them moving.
- `schedule` only triggers on the repository's default branch, so the 06:00 run tests `main`, never a PR head.
- GitHub queues cron events and can delay them by minutes during peak load — the start is not exact. If 06:00 is a real deadline (a report, an SLA), move the trigger to an external scheduler that calls the `workflow_dispatch` API.
- `cache: pip` needs a resolvable dependency file at the repo root; without one the step warns and the cache no-ops.
- Blast radius: PR-only plus default-branch cron, read-only token, no deploy step — a failure blocks merges on a required status check and nothing else. Rollback is reverting this file; delete the workflow or remove it from branch protection to unblock immediately.
