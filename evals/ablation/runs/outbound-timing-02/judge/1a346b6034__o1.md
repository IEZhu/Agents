## Answer A
Главная проблема — изменяемый аргумент по умолчанию. `[]` вычисляется один раз, при определении функции, а не при каждом вызове. Поэтому все вызовы без явного `tags` делят один и тот же список и накапливают в нём состояние.

### [BLOCKER] Общий список между вызовами

**Проблема**: `tags=[]` создаётся однажды и живёт в `add_tag.__defaults__`. Каждый вызов без `tags` мутирует тот же объект.

```python
add_tag("a")   # ['a']
add_tag("b")   # ['a', 'b']  — ожидалось ['b']
```

**Почему важно**: утечка данных между несвязанными вызовами и неограниченный рост списка на весь срок жизни процесса. Если это теги пользователя или арендатора, один получит теги другого. Баг молчаливый: тесты, которые вызывают функцию один раз, его не видят.

**Исправление** — сентинел `None`:

```python
def add_tag(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
```

### [MAJOR] Контракт функции двусмысленный

**Проблема**: при переданном списке функция мутирует аргумент на месте **и** возвращает тот же объект. Вызывающий код не может понять по сигнатуре, что получает — новый список или свой же.

**Почему важно**: `new = add_tag("x", old)` читается как создание копии, но `old` тоже изменён. Отсюда правки «на расстоянии» в вызывающем коде.

**Варианты** — выбрать один, не оба:

```python
# А. Мутирующая: меняет на месте, ничего не возвращает (как list.append)
def add_tag(tag, tags): ...

# Б. Чистая: возвращает новый список, вход не трогает
def add_tag(tag, tags=()):
    return [*tags, tag]
```

Б дешевле для коротких списков и убирает проблему по умолчанию целиком: кортеж неизменяем, так что общий дефолт безвреден.

### [NIT] Типы и порядок параметров

Нет аннотаций: `def add_tag(tag: str, tags: list[str] | None = None) -> list[str]`. И порядок `(tag, tags)` обратный привычному `(коллекция, элемент)` — на месте вызова легко перепутать аргументы, оба тега-подобные.

---

Замечу: это ровно тот класс ошибок, который ловит линтер — `ruff`/flake8-bugbear правило B006 и `pylint` W0102 (по памяти, не проверял здесь — сверьтесь с конфигом). Если в проекте линтера нет, включить его дешевле, чем находить такое ревью за ревью.


## Answer B
Мутабельное значение по умолчанию — это баг уровня «не мёржить». `[]` вычисляется один раз, при определении функции, а не при каждом вызове, поэтому все вызовы без аргумента `tags` делят один и тот же список:

```python
add_tag("a")   # ['a']
add_tag("b")   # ['a', 'b']  — а не ['b']
```

Этот список лежит в `add_tag.__defaults__` и накапливает всё за время жизни процесса: и утечка памяти, и протекание данных из одного вызова в другой. В долгоживущем сервисе (обработчик запроса, воркер) это ещё и гонка между параллельными вызовами.

Починка:

```python
def add_tag(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
```

Второе, менее заметное: контракт функции двусмысленный. Если `tags` передали — функция мутирует список вызывающего и возвращает его же; если нет — создаёт новый. По возвращаемому значению вызывающий код не может понять, своя у него коллекция или чужая. Стоит выбрать одно поведение:

- мутация на месте — `def add_tag(tag, tags): tags.append(tag)`, без `return`;
- чистая версия — `return [*tags, tag]`, вызывающий сам решает, что делать с результатом.

Для функции с таким именем я бы ожидал первое, но это зависит от того, как её уже используют.

Третье, мелочь: `tag` и `tags` различаются одной буквой — в теле легко опечататься, и опечатка будет тихой. `new_tag`/`tags` или `tag`/`tag_list` читаются надёжнее.
