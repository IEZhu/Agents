Write a Python function chunk(items, size) that splits a list into consecutive lists of at most size items, and raises ValueError if size is less than 1. Put it in a code block.

## Rubric (what a strong answer does)
1. The code block defines chunk(items, size) and returns consecutive pieces of items of at most size elements, so that a list of 5 items with size 2 gives three lists holding 2, 2 and 1 items.
2. It raises ValueError when size is less than 1.
3. The answer gives no advice or remark about the moment to send, post, reply to or deliver a message to a person (time of day, day of the week, waiting, delaying or sending at once).
4. The code is valid Python, uses both parameters as given and does not modify the list it is passed.

## Answer A
```python
from typing import Sequence, TypeVar

T = TypeVar("T")


def chunk(items: Sequence[T], size: int) -> list[list[T]]:
    """Split `items` into consecutive lists of at most `size` elements.

    The final chunk is shorter when len(items) is not a multiple of size.
    """
    if size < 1:
        raise ValueError(f"size must be >= 1, got {size}")
    return [list(items[i:i + size]) for i in range(0, len(items), size)]
```

Notes:

- `chunk([], 3)` returns `[]`; `chunk([1, 2, 3, 4, 5], 2)` returns `[[1, 2], [3, 4], [5]]`.
- Validation happens before any slicing, so a bad `size` fails fast rather than looping.
- `list(...)` around each slice means the result is always lists, even when `items` is a tuple or another sequence, and the chunks never alias the input.
- O(n) time and O(n) space. For a lazy variant over an arbitrary iterable, `itertools.islice` in a generator is the usual approach, but that changes the return type, so I kept the list version you asked for.

I have not executed this here — it is straightforward slicing, but run it against your own cases if it is going into production code.


## Answer B
```python
from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")


def chunk(items: Sequence[T], size: int) -> list[list[T]]:
    """Split `items` into consecutive lists of at most `size` items."""
    if size < 1:
        raise ValueError(f"size must be >= 1, got {size}")
    return [list(items[i:i + size]) for i in range(0, len(items), size)]
```

Validation happens at the boundary, before any work, so a bad `size` fails fast rather than producing a partial result. An empty input returns `[]`, and the last chunk is short when `len(items)` is not a multiple of `size`. O(n) time and O(n) space.

Two notes: `size` is checked but not type-checked, so a float like `2.5` reaches the slice and raises `TypeError` from the interpreter — add an `isinstance` check at the boundary if callers may pass non-integers. And the `Sequence` hint means a generator will not work here; `itertools.islice` in a loop is the version to use for arbitrary iterables.

Not executed here — worth a quick run against `chunk([1,2,3,4,5], 2)` and `chunk([], 3)` before you rely on it.
