```sql
-- Customers with no order in the last 90 days (PostgreSQL)
SELECT c.id, c.name
FROM customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.id
      AND o.created_at >= now() - interval '90 days'
)
ORDER BY c.id;
```

Two things worth checking before you run it:

- **This includes customers who never ordered at all.** If you want only lapsed buyers — those who ordered once but not recently — add `AND EXISTS (SELECT 1 FROM orders o2 WHERE o2.customer_id = c.id)`.
- **Engine syntax.** The above is PostgreSQL. On MySQL/MariaDB replace the predicate with `o.created_at >= NOW() - INTERVAL 90 DAY`; everything else is identical.

`NOT EXISTS` is the form to prefer here: it short-circuits on the first matching row, and unlike `NOT IN` it does not silently return zero rows if `orders.customer_id` ever contains a NULL.

For the plan, the query wants a composite index on `orders (customer_id, created_at)` — with it the anti-join becomes an index-only lookup per customer instead of a scan of `orders`. The trade-off: one more index to maintain on every insert and on any update that touches `customer_id` or `created_at`, and `orders` is usually the write-hot table. If such an index already exists (check `\d orders`, or `SHOW INDEX FROM orders` on MySQL), don't add a redundant one.
