Отполируй, пожалуйста, текст уведомления для клиентов, он пойдёт баннером в личном кабинете. Ограничения: не больше 500 символов с пробелами, без канцелярита, в конце один понятный призыв к действию. Все факты должны сохраниться.

Исходник:
"Уважаемые клиенты! Доводим до вашего сведения, что в связи с проведением плановых технических работ по обновлению платформы до версии 4.2.1, 14 октября в период с 02:00 до 02:30 по московскому времени будет осуществляться простой сервиса продолжительностью до 30 минут. В рамках данного обновления будет произведено отключение API версии v1. Просим вас в срок до 1 ноября осуществить переход на API v2, документация по которому размещена в разделе «Разработчикам». Приносим извинения за доставленные неудобства."

## Rubric (what a strong answer does)
1. Points out to the user that API v1 is turned off during the 14 October update while the migration deadline is 1 November (after v1 is already off), and asks which is right or clearly marks the chosen wording as an assumption; it does not silently ship the contradiction
2. The rewritten notice keeps every fact: version 4.2.1, 14 October, 02:00-02:30 Moscow time, downtime of up to 30 minutes, API v1 being turned off, the move to API v2 with the 1 November deadline (or the user's clarified date), and the docs in the «Разработчикам» section
3. The notice is plausibly within 500 characters, drops bureaucratic phrasing (for example «доводим до вашего сведения», «осуществить переход»), and ends with exactly one clear call to action
4. The answer is in Russian and gives a ready-to-use final text, not just advice on how to rewrite it

## Answer A
**Текст баннера** (около 290 символов с пробелами):

> 14 октября с 02:00 до 02:30 по московскому времени мы проводим плановое обновление платформы до версии 4.2.1. Сервис будет недоступен до 30 минут, извините за неудобства. В рамках обновления отключаем API v1. Перейдите на API v2 до 1 ноября: документация в разделе «Разработчикам».

**Что изменилось**
- Убрал канцелярит: «доводим до вашего сведения», «будет осуществляться простой», «будет произведено отключение», «в срок до».
- Дату и время поставил в начало, потому что клиенту это важнее всего.
- Извинение перенёс в середину, чтобы текст заканчивался одним призывом к действию: «Перейдите на API v2 до 1 ноября».
- Все факты на месте: плановые работы, версия 4.2.1, 14 октября, 02:00–02:30 МСК, простой до 30 минут, отключение API v1, переход до 1 ноября, раздел «Разработчикам».

**Проверьте один момент в исходнике.** По тексту выходит, что API v1 отключат во время обновления 14 октября, но перейти на v2 просят до 1 ноября. Если v1 отключат 14-го, срок 1 ноября уже не нужен. Если v1 будет работать до 1 ноября, лучше написать это прямо. Тогда предпоследнее предложение стоит заменить так:

> …извините за неудобства. API v1 отключим 1 ноября. Перейдите на API v2 до этой даты: документация в разделе «Разработчикам».


## Answer B
**Вариант для баннера** (около 250 символов с пробелами):

> 14 октября с 02:00 до 02:30 по МСК мы обновим платформу до версии 4.2.1. Сервис будет недоступен до 30 минут — извините за неудобства. С этим обновлением отключается API v1. Перейдите на API v2 до 1 ноября — документация в разделе «Разработчикам».

В тексте остались все факты: версия 4.2.1, дата, время по МСК, простой до 30 минут, отключение API v1, срок перехода до 1 ноября и где лежит документация. Призыв к действию один, и он стоит в конце.

**Проверьте один момент до публикации.** В исходнике есть противоречие. Если API v1 отключается в ходе обновления 14 октября, срок «до 1 ноября» не имеет смысла: после 14-го v1 уже не будет работать. Клиенты могут понять это по-разному и пропустить настоящий срок. Уточните, какой вариант верный:

- **v1 отключается 14 октября.** Тогда срок перехода — до 14 октября, и последнюю фразу нужно заменить: «Перейдите на API v2 до 14 октября — документация в разделе «Разработчикам»».
- **v1 работает до 1 ноября.** Тогда третью фразу лучше заменить на «API v1 перестанет работать 1 ноября», а призыв поправить так: «Перейдите на API v2 до этой даты — документация в разделе «Разработчикам»».
