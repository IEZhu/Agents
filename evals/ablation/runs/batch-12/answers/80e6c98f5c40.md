Предыдущий вариант не работает из-за двоичного представления float, а не из-за формулы. Литерал `2.675` хранится как `2.67499999999999982236431605997495353221893310546875`, поэтому `2.675 * 100` даёт `267.49999999999997`, и `floor(... + 0.5)` возвращает 267. С `1.005` то же самое: `100.49999999999999`. С float-арифметикой это не исправить. Любые `+ 1e-9` будут ломаться на других значениях.

Правильный путь: взять десятичное представление, которое было в JSON, и округлить уже его через `decimal`.

```python
import math
from decimal import Decimal, ROUND_HALF_UP

_CENT = Decimal("0.01")


def round_money(x: float) -> float:
    """Округляет сумму до копеек по правилу «половина вверх» (от нуля)."""
    if not math.isfinite(x):
        raise ValueError(f"round_money: expected a finite number, got {x!r}")
    # repr(float) даёт кратчайшую строку, которая превращается обратно в тот же float,
    # то есть '2.675', а не 2.67499999... Округляем именно эту десятичную запись.
    return float(Decimal(repr(x)).quantize(_CENT, rounding=ROUND_HALF_UP))
```

Как это работает на ваших тестах:

| вход | `repr(x)` | после `quantize` | результат |
|---|---|---|---|
| `2.675` | `'2.675'` | `2.68` | `2.68` |
| `0.125` | `'0.125'` | `0.13` | `0.13` |
| `1.005` | `'1.005'` | `1.01` | `1.01` |
| `3.14159` | `'3.14159'` | `3.14` | `3.14` |

`float(Decimal("2.68"))` даёт тот же float, что и литерал `2.68`, поэтому `==` в ваших assert'ах выполнится.

Что стоит знать перед выкладкой:

- **Важно не использовать `Decimal(x)` напрямую.** `Decimal(2.675)` берёт точное двоичное значение `2.67499999…` и округлит его до `2.67`. Нужно именно `Decimal(repr(x))` (или `str(x)`, в Python 3 это одно и то же).
- **Отрицательные суммы.** `ROUND_HALF_UP` в `decimal` округляет от нуля: `-2.675` станет `-2.68`. Обычно в бухгалтерии нужно именно так. Если нужно в сторону +∞, скажите, поменяем на другую логику.
- **NaN/inf** вызывают `ValueError` сразу, не доходя до `InvalidOperation`.
- **Когда подход работает.** Он опирается на то, что в JSON число записано не более чем с ~15 значащими цифрами. Для денежных сумм это так. Тогда `repr` вернёт ту же запись, что была в JSON.
- **На будущее.** Формат JSON менять не нужно, чтобы вообще не иметь дела с float: можно парсить через `json.loads(data, parse_float=Decimal)` и держать суммы в `Decimal` до самого вывода. Это надёжнее, если суммы потом ещё складываются или умножаются. Для задачи в текущем виде хватит функции выше.

Регрессионные тесты, включая граничные случаи:

```python
import math
import pytest

@pytest.mark.parametrize("x, expected", [
    (2.675, 2.68),
    (0.125, 0.13),
    (1.005, 1.01),
    (3.14159, 3.14),
    (0.0, 0.0),
    (10.0, 10.0),
    (0.005, 0.01),
    (0.0049, 0.0),
    (-2.675, -2.68),
    (1234567.895, 1234567.9),
])
def test_round_money(x, expected):
    assert round_money(x) == expected

@pytest.mark.parametrize("bad", [math.nan, math.inf, -math.inf])
def test_round_money_rejects_non_finite(bad):
    with pytest.raises(ValueError):
        round_money(bad)
```
