**Коротко:** одним промптом формат на 100% не удержать, даже капсом. Надёжная схема держится на двух вещах: (1) промпт с жёстким контрактом, примером и prefill, (2) валидатор в скрипте с retry. Ещё надёжнее просить у модели JSON и собирать markdown самому в коде. Тогда `##` против `###`, обёртки ```` ``` ```` и лишние разделы исключены конструктивно.

## Почему текущий промпт «плывёт»

- Инструкция, шаблон и данные лежат одной кашей в user-сообщении. Модель не видит, где кончается шаблон и начинается вход.
- Нет ни одного примера готового выхода. «Строго соблюдай формат» — абстракция, а пример — конкретика.
- Не сказано, **что делать с пустыми/неизвестными полями**. Отсюда модель добавляет «Возможные причины» и сама придумывает ссылки на Grafana.
- Ответ модель начинает с нуля, поэтому «Конечно! Вот…» — самый вероятный первый токен.
- Капс работает слабо: он говорит, чего *не* делать, но не показывает, что делать.

## Вариант A (рекомендую): JSON → markdown в коде

Модель возвращает только поля, а шаблон рендерит Python. Бот получает байт-в-байт одинаковый формат.

**System prompt:**

```text
Ты генерируешь данные для карточки дежурного по одному Prometheus-алерту.
Результат парсит программа, человек его не читает.

Верни ОДИН JSON-объект строго по схеме, без текста до или после, без ```:

{
  "alert_name": string,          // точно как в поле alert: правила
  "severity": "critical" | "warning" | "info",  // из labels.severity; если нет — "warning"
  "what_broke": string,          // 1-2 предложения по-русски: что сломалось и чем это грозит
  "first_action": string,        // ОДНО действие для восстановления сервиса, одна команда
  "diagnostics": [string],       // 2-4 команды kubectl, каждая — одна строка, с -n <namespace>
  "grafana": string              // annotations.dashboard_url из правила, иначе "нет"
}

Правила:
- Используй плейсхолдеры <namespace>, <pod>, <deployment>. Не выдумывай реальные имена.
- Не придумывай ссылки. Grafana — только если URL есть в правиле.
- Никаких дополнительных полей (причины, заметки и т.п.).
```

**User message:**

```text
<rule>
{rule_yaml}
</rule>
```

**Рендер и проверка в скрипте:**

```python
import json

REQUIRED = {"alert_name", "severity", "what_broke", "first_action", "diagnostics", "grafana"}

def render(d: dict) -> str:
    diag = "\n".join(f"- `{c.strip('`')}`" for c in d["diagnostics"])
    return (
        f"## {d['alert_name']}\n"
        f"**Severity:** {d['severity']}\n"
        f"**Что сломалось:** {d['what_broke']}\n"
        f"**Первое действие:** {d['first_action']}\n"
        f"**Диагностика:**\n{diag}\n"
        f"**Grafana:** {d['grafana']}\n"
    )

def parse(raw: str) -> dict:
    raw = raw.strip().removeprefix("```json").removeprefix("```").removesuffix("```").strip()
    d = json.loads(raw)
    if set(d) != REQUIRED or d["severity"] not in {"critical", "warning", "info"}:
        raise ValueError(f"bad keys/severity: {sorted(d)}")
    return d
```

Если провайдер поддерживает structured outputs / JSON schema mode (у OpenAI это `response_format` с `json_schema`, у Anthropic — tool use с `input_schema`; названия параметров привожу по памяти, сверьтесь с документацией вашего SDK), передавайте туда эту же схему. Тогда невалидный JSON исключается на уровне API.

## Вариант B: оставить markdown, но зажать формат

Если по какой-то причине нужен именно текст от модели, вот готовый вариант для `KubePodCrashLooping`.

**System prompt:**

```text
Ты — генератор карточек для дежурных SRE. Твой вывод без изменений парсит бот
и загружает в Confluence. Любой символ вне шаблона ломает бота.

Выводи РОВНО 7 блоков в этом порядке и ничего больше:

## <имя алерта>
**Severity:** <critical|warning|info>
**Что сломалось:** <1-2 предложения>
**Первое действие:** <одна команда или действие>
**Диагностика:**
- `<команда kubectl>`
**Grafana:** <ссылка или "нет">

Правила заполнения:
1. Имя алерта — точно из поля `alert:` правила. Заголовок строго второго уровня: "## ".
2. Severity — из labels.severity. Если его нет — warning.
3. Первое действие — одно действие для восстановления сервиса, не диагностика.
4. Диагностика — 2-4 строки, каждая начинается с "- `kubectl" и содержит -n <namespace>.
5. Grafana — значение annotations.dashboard_url из правила. Если его нет — слово нет. Ссылки не выдумывать.
6. Плейсхолдеры: <namespace>, <pod>, <deployment>.
7. Запрещено: вступления, пояснения после карточки, блоки ```, дополнительные разделы
   (причины, заметки, рекомендации), заголовки других уровней.
   Последняя строка ответа — строка **Grafana:**.

Пример правильного ответа для другого алерта:

## KubeDeploymentReplicasMismatch
**Severity:** warning
**Что сломалось:** Deployment не может поднять нужное число реплик дольше 15 минут, сервис работает с урезанной ёмкостью.
**Первое действие:** `kubectl rollout undo deployment/<deployment> -n <namespace>`
**Диагностика:**
- `kubectl describe deployment <deployment> -n <namespace>`
- `kubectl get events -n <namespace> --sort-by='.lastTimestamp'`
- `kubectl get pods -n <namespace> -o wide`
**Grafana:** нет
```

**User message** (для CrashLooping):

```text
<rule>
- alert: KubePodCrashLooping
  annotations:
    description: 'Pod {{ $labels.namespace }}/{{ $labels.pod }} ({{ $labels.container }}) is in waiting state (reason: "CrashLoopBackOff").'
    runbook_url: https://runbooks.prometheus-operator.dev/runbooks/kubernetes/kubepodcrashlooping

  expr: |
    max_over_time(kube_pod_container_status_waiting_reason{reason="CrashLoopBackOff", job="kube-state-metrics"}[5m]) >= 1
  for: 15m
  labels:

Выведи карточку для этого правила.
```

(YAML правила выше — по памяти из kubernetes-mixin, для примера. В скрипте подставляется ваш реальный `{rule_yaml}`.)

**Prefill:** начните ответ ассистента сами строкой `## KubePodCrashLooping\n`, а имя возьмите из YAML в коде. Модель физически не сможет начать с «Конечно!» или ```` ``` ````, и уровень заголовка зафиксирован. В Anthropic API это делается последним сообщением с `role: "assistant"`. Учтите, что у части новых моделей prefill может не поддерживаться, это надо проверить для вашей. В OpenAI chat API полноценного prefill, насколько я знаю, нет, так что там лучше вариант A.

Ожидаемый вывод:

```markdown
## KubePodCrashLooping
**Severity:** warning
**Что сломалось:** Контейнер пода постоянно падает и перезапускается (CrashLoopBackOff) дольше 15 минут, сервис работает с меньшим числом реплик или недоступен.
**Первое действие:** `kubectl rollout undo deployment/<deployment> -n <namespace>` (если падения начались после деплоя)
**Диагностика:**
- `kubectl describe pod <pod> -n <namespace>`
- `kubectl logs <pod> -n <namespace> --previous --tail=50`
- `kubectl get events -n <namespace> --sort-by='.lastTimestamp'`
- `kubectl top pod <pod> -n <namespace>`
**Grafana:** нет
```

## Страховка в скрипте (обязательна для обоих вариантов)

```python
import re

CARD_RE = re.compile(
    r"\A## \S+\n"
    r"\*\*Severity:\*\* (critical|warning|info)\n"
    r"\*\*Что сломалось:\*\* .+\n"
    r"\*\*Первое действие:\*\* .+\n"
    r"\*\*Диагностика:\*\*\n"
    r"(- `kubectl [^\n]+`\n)+"
    r"\*\*Grafana:\*\* \S.*\Z"
)

def clean(text: str) -> str:
    text = text.strip()
    text = re.sub(r"\A```\w*\n|\n```\Z", "", text)   # снять обёртку
    start = text.find("## ")
    return text[start:].strip() if start != -1 else text

def generate(rule_yaml, alert_name, retries=2):
    for attempt in range(retries + 1):
        out = clean(call_llm(rule_yaml, alert_name))   # ваш вызов
        if CARD_RE.match(out):
            return out
        # в retry добавьте в user-сообщение: "Предыдущий ответ не прошёл валидацию: <что не так>. Выведи только карточку."
    raise ValueError(f"{alert_name}: format failed after {retries + 1} attempts")
```

Плюс `temperature=0`: на 140 однотипных вызовах это заметно снижает разброс.

## Что это даст

- Вариант A + JSON schema mode: сбоев формата практически нет, остаются только проблемы содержания.
- Вариант B + prefill + валидатор + retry: оценочно (не мерил) должен остаться примерно 1% ручных разборов, а не 15-20%, и бот больше не падает, потому что невалидное до него не доходит.

Тексты «Что сломалось» и «Первое действие» всё равно стоит один раз просмотреть глазами для critical-алертов. Формат валидатор проверит, а правильность команды — нет.
