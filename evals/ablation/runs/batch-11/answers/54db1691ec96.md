**Коротко:** капс и «НЕ ПИШИ НИЧЕГО КРОМЕ» почти не помогают. Формат стабилизируют четыре вещи:

1. Формат задаётся в system prompt, а данные идут отдельно в user message.
2. В промпте есть один полный эталонный пример (few-shot) и закрытый список полей.
3. Ответ модели заранее начат с `## ` (prefill), если API это позволяет.
4. **Главное:** ответ валидируется в коде и при ошибке перегенерируется.

Ещё надёжнее вообще не просить у модели Markdown: пусть она возвращает JSON, а шаблон рендерит Python. Оба варианта ниже.

---

## Почему текущий промпт «плывёт»

| Симптом | Причина | Лечение |
|:---|:---|:---|
| «Конечно! Вот карточка…» | Режим чат-ассистента, ответ ничем не заякорен | Prefill `## ` или JSON-режим |
| Обёртка в ` ```markdown ` | Модель считает, что «шаблон» надо показать как код | Прямо запретить и показать пример **без** обёртки |
| `###` вместо `##` | Шаблон описан словами, а не показан буквально | Эталонный пример и regex-проверка |
| Добавляет «Возможные причины» | Список полей не закрыт, модель «помогает» | Явно написать «ровно 6 полей, других нет» и отбрасывать лишнее в коде |
| (скрытая проблема) Grafana-ссылки | Модель не знает ваших URL и **выдумает** их | Передавать ссылку из кода или требовать `нет` |

---

## Вариант A (рекомендую): JSON + рендер в Python

Модель заполняет поля, `##` и `**Severity:**` пишет ваш код. Сломать разметку модели просто нечем.

**System prompt:**

```text
Ты SRE, который пишет карточки для дежурных по алертам Prometheus.
Дежурный работает со своего ноутбука через kubectl, без SSH на ноды.

Верни ОДИН JSON-объект и ничего больше: без пояснений и без ```-обёртки.
Схема (все поля обязательны, других полей нет):
{
  "alert_name": string,        // ровно значение поля alert из правила
  "severity": "critical" | "warning" | "info",  // из labels.severity правила
  "what_broke": string,        // 1-2 предложения: что сломалось и чем это грозит пользователям
  "first_action": string,      // ОДНА команда или действие для восстановления сервиса
  "diagnostics": [string],     // 2-4 команды kubectl, всегда с -n <namespace>
  "grafana": string            // значение из <grafana_url>, если оно задано; иначе "нет"
}
Никогда не придумывай URL. Если данных для поля не хватает, заполни его по смыслу правила, но не добавляй новых полей.
```

**User message** (шаблон в скрипте):

```text
<alert_rule>
{rule_yaml}
</alert_rule>
<grafana_url>{grafana_url_or_empty}</grafana_url>
```

**Рендер и проверка:**

```python
import json

REQUIRED = {"alert_name", "severity", "what_broke", "first_action", "diagnostics", "grafana"}

def render(raw: str) -> str:
    raw = raw.strip().removeprefix("```json").removeprefix("```").removesuffix("```").strip()
    d = json.loads(raw)
    if set(d) != REQUIRED or d["severity"] not in {"critical", "warning", "info"}:
        raise ValueError(f"bad fields: {set(d) ^ REQUIRED}")
    diag = "\n".join(f"- `{c}`" for c in d["diagnostics"])
    return (
        f"## {d['alert_name']}\n"
        f"**Severity:** {d['severity']}\n"
        f"**Что сломалось:** {d['what_broke']}\n"
        f"**Первое действие:** {d['first_action']}\n"
        f"**Диагностика:**\n{diag}\n"
        f"**Grafana:** {d['grafana']}"
    )
```

Если ваш провайдер умеет structured outputs или tool calling со схемой (у OpenAI и Anthropic это есть), передайте схему туда. Тогда валидный JSON гарантирует API, а не промпт. Точные названия параметров зависят от SDK и версии, поэтому сверьтесь с документацией вашего клиента.

## Вариант B: оставить Markdown, но зажать формат

Если бот должен получать именно текст от модели, используйте такую связку.

**System prompt:**

```text
Ты SRE, который пишет карточки для дежурных по алертам Prometheus.
Дежурный работает со своего ноутбука через kubectl, без SSH на ноды.

Твой ответ целиком машинно парсится ботом. Любой текст вне карточки ломает парсер.

Формат ответа — ровно 6 полей, в этом порядке, других строк и разделов нет:
1. Строка "## " + имя алерта (ровно два символа #).
2. "**Severity:** " + critical, warning или info (из labels.severity правила).
3. "**Что сломалось:** " + 1-2 предложения.
4. "**Первое действие:** " + одна команда или одно действие для восстановления сервиса.
5. "**Диагностика:**", затем 2-4 строки вида "- `kubectl ...`", всегда с -n <namespace>.
6. "**Grafana:** " + значение из <grafana_url>, если оно задано, иначе слово нет.

Ответ начинается с "## " и заканчивается строкой Grafana.
Без вступления, без заключения, без ```-обёртки, без разделов "Возможные причины", "Примечания" и т.п.

Пример корректного ответа для другого алерта:

## KubeDeploymentReplicasMismatch
**Severity:** warning
**Что сломалось:** Deployment не может поднять нужное число реплик уже более 15 минут. Сервис работает с урезанной ёмкостью и может не выдержать пик нагрузки.
**Первое действие:** `kubectl rollout undo deployment/<deployment> -n <namespace>`, если проблема началась после релиза
**Диагностика:**
- `kubectl describe deployment <deployment> -n <namespace>`
- `kubectl get pods -n <namespace> -l app=<app>`
- `kubectl get events -n <namespace> --sort-by=.lastTimestamp`
**Grafana:** нет
```

**User message для KubePodCrashLooping:**

```text
<alert_rule>
- alert: KubePodCrashLooping
  annotations:
    description: 'Pod {{ $labels.namespace }}/{{ $labels.pod }} ({{ $labels.container }}) is in waiting state (reason: "CrashLoopBackOff").'
    summary: Pod is crash looping.
  expr: |
    max_over_time(kube_pod_container_status_waiting_reason{reason="CrashLoopBackOff", job="kube-state-metrics"}[5m]) >= 1
  for: 15m
  labels:
    severity: warning
</alert_rule>
<grafana_url>https://grafana.example.com/d/<uid>/kubernetes-compute-resources-pod</grafana_url>
```

Правило здесь взято по памяти из kubernetes-mixin и не сверено. Подставьте то, что у вас реально лежит в prometheus-rules. URL Grafana тоже пример: берите его из своего маппинга «алерт → дашборд».

**Prefill (assistant message):** `## `

Модель продолжит со слова `KubePodCrashLooping`, и вступление физически негде вставить. В коде склейте `"## " + completion`. Учтите, что prefill поддерживают не все API и модели: у Anthropic он исторически был, но на части новых моделей его могли ограничить. Это не проверено, так что уточните в доку вашей модели. Если prefill недоступен, остаются пример и валидация.

**Ожидаемый ответ:**

```markdown
## KubePodCrashLooping
**Severity:** warning
**Что сломалось:** Контейнер в поде постоянно падает и перезапускается (CrashLoopBackOff) дольше 15 минут. Сервис работает с меньшим числом реплик или недоступен, если реплика одна.
**Первое действие:** `kubectl rollout undo deployment/<deployment> -n <namespace>`, если падения начались после релиза; иначе `kubectl delete pod <pod> -n <namespace>`
**Диагностика:**
- `kubectl logs <pod> -n <namespace> --previous --tail=50`
- `kubectl describe pod <pod> -n <namespace>`
- `kubectl get events -n <namespace> --sort-by=.lastTimestamp`
- `kubectl top pod <pod> -n <namespace>`
**Grafana:** https://grafana.example.com/d/<uid>/kubernetes-compute-resources-pod
```

**Валидатор и retry (обязательно):**

```python
import re

CARD_RE = re.compile(
    r"\A## \S+\n"
    r"\*\*Severity:\*\* (critical|warning|info)\n"
    r"\*\*Что сломалось:\*\* .+\n"
    r"\*\*Первое действие:\*\* .+\n"
    r"\*\*Диагностика:\*\*\n(- `kubectl [^\n]+`\n){1,6}"
    r"\*\*Grafana:\*\* \S.*\Z"
)

def clean(text: str) -> str:
    text = text.strip()
    text = re.sub(r"\A```\w*\n|\n```\Z", "", text).strip()  # снять обёртку
    i = text.find("## ")                                      # отрезать вступление
    text = text[i:] if i >= 0 else text
    text = re.sub(r"\A#{3,} ", "## ", text)                   # ### -> ##
    m = re.search(r"^\*\*Grafana:\*\*.*$", text, re.M)        # отрезать хвост после Grafana
    return text[: m.end()] if m else text

def get_card(rule_yaml, grafana_url, retries=2):
    for _ in range(retries + 1):
        card = clean(call_llm(rule_yaml, grafana_url))  # temperature=0
        if CARD_RE.match(card):
            return card
    raise ValueError("card format failed")  # в лог, на ручную проверку
```

## Что ещё сделать

- **`temperature=0`**: для 140 однотипных генераций креативность не нужна.
- **Убрать капс.** С примером и prefill он лишний, а явное «НЕ …» иногда даже провоцирует нарушение.
- **`severity` брать из YAML в коде**, а не просить модель: это детерминированное поле.
- **Логировать провалы валидации.** Если после всех правок останется 1-2%, это решает retry, а не дальнейшая шлифовка промпта.

По опыту, вариант A с schema-режимом API снимает проблему практически полностью. Вариант B с prefill, примером и `clean()` плюс retry, скорее всего, тоже доведёт брак до единичных случаев, но гарантий меньше.
