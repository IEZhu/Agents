### Analysis

**Root cause:** `round(total_cents / n)` computes one share and hands it to everyone, so any remainder (`total_cents % n`) is either lost or over-allocated. The bug goes both ways, not only under-charging:

- `split_amount(1000, 3)` → `round(333.33)` = 333 → sum **999** (1 cent lost)
- `split_amount(1000, 6)` → `round(166.67)` = 167 → sum **1002** (2 cents over-charged)

The existing test (`900, 3`) divides evenly, which is why it never caught this. Using float division on money also adds risk you don't need: stay in integers.

**Fix:** use `divmod` to get the base share and the remainder, then give one extra cent to each of the first `remainder` people.

### Implementation

```python
def split_amount(total_cents: int, n: int) -> list[int]:
    """Split total_cents into n integer shares that sum exactly to total_cents.

    Leftover cents go one each to the first people in the list, so shares
    differ by at most 1 cent and are in non-increasing order.
    """
    if n < 1:
        raise ValueError(f"n must be a positive integer, got {n}")
    if total_cents < 0:
        raise ValueError(f"total_cents must be non-negative, got {total_cents}")

    base_share, leftover_cents = divmod(total_cents, n)
    return [base_share + 1] * leftover_cents + [base_share] * (n - leftover_cents)
```

Notes:
- **Integer-only arithmetic**, so there's no float rounding at all. This is O(n) time and space, which is the minimum since you have to return n items.
- **Negative totals:** I rejected them explicitly. `divmod` floors toward negative infinity, so `divmod(-1000, 3)` gives `(-334, 2)`, and the result `[-333, -333, -334]` still sums correctly but gives the "extra" to the *last* person. If you split refunds with this function, tell me and I'll handle the sign on purpose (split `abs(total)` and negate it) rather than rely on floor semantics.
- **`n < 1`** used to raise `ZeroDivisionError` for 0 and return `[]` for negative values. It now fails fast with a clear message. This is a small behavior change for any caller that relied on the old exception type.

import pytest

from your_module import split_amount  # adjust import path


@pytest.mark.parametrize(

        (1234, 1, [1234]),

def test_split_amount_examples(total_cents, n, expected):
    assert split_amount(total_cents, n) == expected


@pytest.mark.parametrize("total_cents", [0, 1, 99, 1000, 10_001, 123_456_789])
@pytest.mark.parametrize("n", [1, 2, 3, 7, 13, 100])
def test_split_amount_invariants(total_cents, n):
    shares = split_amount(total_cents, n)
    assert len(shares) == n
    assert sum(shares) == total_cents            # no cents lost or created
    assert max(shares) - min(shares) <= 1        # fair split
    assert shares == sorted(shares, reverse=True)  # leftovers go to the first people


@pytest.mark.parametrize("n", [0, -1])
def test_split_amount_rejects_non_positive_n(n):
    with pytest.raises(ValueError):
        split_amount(100, n)

    with pytest.raises(ValueError):
        split_amount(-100, 3)
