## What's going on

`ConfirmRF:InvokeClient(player, ...)` **yields the server thread until that client returns a value, and it has no timeout.** If the client never answers, your Touched handler waits forever at that line. `pad.Busy = false` never runs, so the pad stays locked for every player until the server restarts. Nothing errors because nothing failed: the handler is still waiting.

Some ways the client can end up never answering:

- **The client ignores the popup.** If your UI returns only after a button is pressed, a player who walks away, alt-tabs or closes the GUI some other way never returns a value.
- **`OnClientInvoke` isn't hooked up yet**, for example when the player touches the pad before the LocalScript has loaded, or the GUI failed to load. As I recall, the invoke then waits until a callback is assigned, and it can wait forever. I haven't verified that here, so check the RemoteFunction page on create.roblox.com.
- **An exploiter does it on purpose.** They set `OnClientInvoke` to a function that never returns and lock any pad they want. This is why Roblox's docs warn against `InvokeClient` in general.
- **Disconnects or client errors.** From memory (not verified), these make `InvokeClient` *throw* on the server rather than hang. Your code has no `pcall`, so an error also skips the cleanup line and leaves `Busy = true`, though that case should at least print something to Output.

There's also a design problem: `pad.Busy` is a **global lock for a per-player question.** One player's unanswered popup blocks the pad for everyone.

## The right pattern

Don't block a server thread waiting on a client. Make the purchase a small request/response over **two RemoteEvents** that never yield:

1. Server → client: "Here's offer `#abc`: Dropper Lv2, 500 cash." The server stores the pending offer **per player** and gives it an expiry.
2. Client → server: "Offer `#abc`: yes/no."
3. The server checks that the offer exists, belongs to this player, hasn't expired and that the player is still near the pad. It then **re-reads the price from its own config** and the cash from its own data, and deducts.

There's no shared lock to get stuck, and an unanswered offer simply expires.

### Server (ServerScriptService/Systems/UpgradePadSystem)

```lua
local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local HttpService = game:GetService("HttpService")

local Remotes = ReplicatedStorage:WaitForChild("Remotes")
local PromptPurchase = Remotes:WaitForChild("PromptPurchase") -- RemoteEvent, server -> client
local AnswerPurchase = Remotes:WaitForChild("AnswerPurchase") -- RemoteEvent, client -> server

-- Single source of truth for prices; the client never tells us the price.
local Upgrades = {
	DropperLv2 = { DisplayName = "Dropper Lv2", Price = 500 },
}

local OFFER_TIMEOUT_SECONDS = 15
local MAX_PAD_DISTANCE = 20

type Offer = {
	id: string,
	upgradeId: string,
	pad: BasePart,
	expiresAt: number,
}

local pendingOffers: { [Player]: Offer } = {}

local function isNearPad(player: Player, pad: BasePart): boolean
	local character = player.Character
	local root = character and character:FindFirstChild("HumanoidRootPart")
	return root ~= nil and (root.Position - pad.Position).Magnitude <= MAX_PAD_DISTANCE
end

local function tryPurchase(player: Player, upgradeId: string)
	local upgrade = Upgrades[upgradeId]
	local cash = player:FindFirstChild("leaderstats") and player.leaderstats:FindFirstChild("Cash")
	if not upgrade or not cash then return end
	if cash.Value < upgrade.Price then return end -- re-check NOW, they may have spent it meanwhile

	cash.Value -= upgrade.Price
	-- TODO: mark upgrade as owned in your tycoon/data module and spawn the dropper
end

local function offerUpgrade(player: Player, pad: BasePart, upgradeId: string)
	if pendingOffers[player] then return end -- per-player debounce, not per-pad

	local upgrade = Upgrades[upgradeId]
	if not upgrade then return end

	local offer: Offer = {
		id = HttpService:GenerateGUID(false),
		upgradeId = upgradeId,
		pad = pad,
		expiresAt = os.clock() + OFFER_TIMEOUT_SECONDS,
	}
	pendingOffers[player] = offer
	PromptPurchase:FireClient(player, offer.id, upgrade.DisplayName, upgrade.Price)

	-- Auto-expire so an ignored popup can never lock anything
	task.delay(OFFER_TIMEOUT_SECONDS, function()
		if pendingOffers[player] == offer then
			pendingOffers[player] = nil
		end
	end)
end

AnswerPurchase.OnServerEvent:Connect(function(player: Player, offerId: unknown, accepted: unknown)
	local offer = pendingOffers[player]
	if not offer or typeof(offerId) ~= "string" or offerId ~= offer.id then return end
	pendingOffers[player] = nil -- consume first: one answer per offer, no double-buy spam

	if accepted ~= true then return end
	if os.clock() > offer.expiresAt then return end
	if not isNearPad(player, offer.pad) then return end

	tryPurchase(player, offer.upgradeId)
end)

Players.PlayerRemoving:Connect(function(player)
	pendingOffers[player] = nil
end)

-- Hook up a pad
local function setupPad(pad: BasePart, upgradeId: string)
	pad.Touched:Connect(function(hit)
		local player = Players:GetPlayerFromCharacter(hit.Parent)
		if not player then return end
		-- TODO: also check that this player owns this tycoon and doesn't already own the upgrade
		offerUpgrade(player, pad, upgradeId)
	end)
end
```

### Client (StarterPlayerScripts/Client/PurchasePromptController)

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Remotes = ReplicatedStorage:WaitForChild("Remotes")
local PromptPurchase = Remotes:WaitForChild("PromptPurchase")
local AnswerPurchase = Remotes:WaitForChild("AnswerPurchase")

-- assume a ScreenGui "PurchasePrompt" with Frame, Label, YesButton, NoButton
local gui = script.Parent:WaitForChild("PurchasePrompt") -- adjust path to your setup
local frame = gui.Frame

local currentOfferId: string? = nil

local function answer(accepted: boolean)
	if not currentOfferId then return end
	AnswerPurchase:FireServer(currentOfferId, accepted)
	currentOfferId = nil
	frame.Visible = false
end

PromptPurchase.OnClientEvent:Connect(function(offerId: string, displayName: string, price: number)
	currentOfferId = offerId
	frame.Label.Text = string.format("Buy %s for %d cash?", displayName, price)
	frame.Visible = true
end)

frame.YesButton.Activated:Connect(function() answer(true) end)
frame.NoButton.Activated:Connect(function() answer(false) end)
```

## Why this holds up

- **Nothing on the server ever waits on a client.** The worst an ignored popup or an exploiter can do is let *their own* offer expire.
- **The server owns everything important.** It sets the price, checks cash when the answer arrives, checks distance and allows one answer per offer ID. A forged `FireServer(randomId, true)` does nothing, and replaying an answer does nothing either because the offer was already consumed.
- **Locks are per player.** Two players can use the same pad (or neighbouring pads) without blocking each other.

## If you really want to keep InvokeClient

You'd have to race it against a timeout, e.g. run the invoke in `task.spawn` and release the lock after N seconds whichever finishes first, and wrap it in `pcall`. That fixes the pad lock, but the stuck thread still hangs around forever for every ignored or malicious prompt, and you still depend on a client for flow control. For a purchase flow, the two-RemoteEvent version is cleaner.

**Tip:** for a tycoon, a `ProximityPrompt` ("Hold E to buy Dropper Lv2 – 500") is often a better fit than Touched + popup. It fires `Triggered` on the server with the player, so you can skip the confirmation round-trip entirely. It also works well on mobile and gamepad.

## Testing it

2. Ignore the popup for longer than 15 s, then click Yes. Nothing should be bought.
3. Step on the pad, walk far away, then click Yes. It should be rejected by the distance check.
4. Spam Yes and make sure the price is deducted only once.
