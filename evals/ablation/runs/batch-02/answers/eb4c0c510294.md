Ниже `get_duration` в том же стиле, что `get_int`/`get_bool`: `default=None` означает, что ключ обязателен, а ошибки формата поднимают `ConfigError` с именем ключа и исходным значением. Разбор сделан одной регуляркой с фиксированным порядком единиц `h → m → s → ms`, каждая встречается не больше одного раза.

### Реализация (`app/config.py`)

```python
import os
import re

# Units must appear in descending order, each at most once: "1h30m", "2m15s", "1s500ms".
# "ms" has its own group after "s", so "500ms" is not mistaken for "500m" + "s".
_NUMBER = r"(\d+(?:\.\d+)?)"
_DURATION_RE = re.compile(
    rf"(?:{_NUMBER}h)?(?:{_NUMBER}m)?(?:{_NUMBER}s)?(?:{_NUMBER}ms)?"
)
_UNIT_SECONDS = (3600.0, 60.0, 1.0, 0.001)  # h, m, s, ms — same order as the groups


def _parse_duration(raw: str) -> float | None:
    """Return seconds for a duration string, or None if it is malformed."""
    if not raw:
        return None
    match = _DURATION_RE.fullmatch(raw)
    if match is None:
        return None
    return sum(
        float(value) * factor
        for value, factor in zip(match.groups(), _UNIT_SECONDS)
        if value is not None
    )


def get_duration(key: str, default: float | None = None) -> float:
    """Read a duration like '1h30m', '45s', '2m', '500ms' and return seconds."""
    raw = os.environ.get(key)
    if raw is None:
        if default is None:
            raise ConfigError(f"{key} is required")
        return default
    seconds = _parse_duration(raw)
    if seconds is None:
        raise ConfigError(
            f"{key}: expected duration like '1h30m', '45s' or '500ms', got {raw!r}"
        )
    return seconds
```

Решения, которые стоит проверить, подходят ли они вам:

- **Пустая строка** отклоняется. Регулярка из одних опциональных групп совпала бы с `""` и вернула бы 0, отсюда явная проверка `if not raw`.
- **Дробные значения** разрешены (`1.5h`, `0.5s`), отрицательные нет: в регулярке нет знака.
- **Порядок единиц строгий.** `30m1h` и `5m5m` считаются ошибкой, а не складываются. На мой взгляд, это скорее опечатка, которую лучше поймать при старте.
- **Число без единицы (`30`) отклоняется.** Здесь важна обратная совместимость: если `REQUEST_TIMEOUT` сейчас читается через `get_int` и в окружениях лежит `30`, после перехода на `get_duration` сервис упадёт на старте. Если такие окружения есть, можно либо считать голое число секундами (добавить `(?:{_NUMBER})?` как отдельную ветку), либо сначала обновить значения в деплое. Скажите, какой вариант нужен.
- **Регистр и пробелы** не нормализуются, как и в `get_int`: `1H` и `" 45s"` будут ошибкой.

### Тесты (`tests/test_config.py`)

```python
import pytest

from app.config import ConfigError, get_duration

KEY = "REQUEST_TIMEOUT"


@pytest.mark.parametrize(
    ("raw", "expected"),
    [
        ("45s", 45.0),
        ("2m", 120.0),
        ("500ms", 0.5),
        ("1h30m", 5400.0),
        ("1h", 3600.0),
        ("1m500ms", 60.5),
        ("1h2m3s4ms", 3723.004),
        ("1.5h", 5400.0),
        ("0s", 0.0),
    ],
)
def test_get_duration_parses_valid_values(monkeypatch, raw, expected):
    monkeypatch.setenv(KEY, raw)
    assert get_duration(KEY) == pytest.approx(expected)


@pytest.mark.parametrize(
    "raw",
    ["", "30", "abc", "1d", "-5s", "30m1h", "5m5m", "1H", " 45s", "1.s", ".5s", "s"],
)
def test_get_duration_rejects_malformed(monkeypatch, raw):
    monkeypatch.setenv(KEY, raw)
    with pytest.raises(ConfigError, match=KEY):
        get_duration(KEY)


def test_get_duration_returns_default_when_missing(monkeypatch):
    monkeypatch.delenv(KEY, raising=False)
    assert get_duration(KEY, default=10.0) == 10.0


def test_get_duration_requires_value_without_default(monkeypatch):
    monkeypatch.delenv(KEY, raising=False)
    with pytest.raises(ConfigError, match="is required"):
        get_duration(KEY)
```

`pytest.approx` нужен из-за float: `0.004` в `1h2m3s4ms` не представляется в двоичном виде точно.

Разбор работает за O(n) от длины строки. Регулярка без вложенных квантификаторов, так что катастрофического backtracking нет.

Код и тесты я не запускал: разбор `500ms`, `1m500ms` и пустой строки проверил только вручную. Прогоните `pytest tests/test_config.py -q` перед мержем.
