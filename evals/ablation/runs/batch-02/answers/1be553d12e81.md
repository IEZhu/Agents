Your writer has two separate bugs, and each one explains one of the symptoms. The mesh in Blender is fine. The file you write out is not.

## Bug 1: "every other triangle is missing" is caused by `p.vertices[:3]`

Your shell is made of quads (32 sides × 80 rings, each face joining two rings). `p.vertices[:3]` keeps the first three corners of each quad and throws away the fourth. A quad `A B C D` should become two triangles, `A B C` and `A C D`. You only write `A B C`, so half of every face is missing. On a grid that looks exactly like a checkerboard of triangular holes, and every hole produces open edges.

**Fix:** triangulate before writing. Blender already keeps a triangulation for this: `mesh.loop_triangles`. Don't slice polygons yourself.

## Bug 2: "paper-thin" happens because `obj.data` is the mesh before modifiers

`obj.data` is the original mesh datablock, which here is your single surface. The Solidify modifier is non-destructive. It only exists in the evaluated result, which the viewport draws. That's why the viewport looks solid while the file contains a zero-thickness sheet. A single surface with no thickness is also non-manifold by definition, which adds more open-edge warnings.

**Fix:** read the evaluated mesh from the depsgraph. This includes Solidify and any other modifiers, and you don't need to change the selection or apply anything.

## Third, smaller issue: object transform

`me.vertices[i].co` is in local space. If the object has location, rotation or scale that you haven't applied, the STL will ignore them. Multiply by `obj.matrix_world`.

## Corrected writer

```python
import bpy
from pathlib import Path


def write_ascii_stl(obj: bpy.types.Object, path: str | Path, name: str = "shade") -> int:
    """Write the evaluated (post-modifier), world-space, triangulated mesh of obj.

    Returns the number of triangles written.
    """
    depsgraph = bpy.context.evaluated_depsgraph_get()
    obj_eval = obj.evaluated_get(depsgraph)
    mesh = obj_eval.to_mesh()          # temporary mesh WITH Solidify applied
    try:
        mesh.calc_loop_triangles()
        mw = obj_eval.matrix_world
        normal_mat = mw.to_3x3().inverted_safe().transposed()
        verts_world = [mw @ v.co for v in mesh.vertices]

        with open(path, "w", encoding="ascii") as f:
            f.write(f"solid {name}\n")
            for tri in mesh.loop_triangles:
                n = (normal_mat @ tri.normal).normalized()
                f.write(f"facet normal {n.x:.6e} {n.y:.6e} {n.z:.6e}\n  outer loop\n")
                for vi in tri.vertices:
                    c = verts_world[vi]
                    f.write(f"    vertex {c.x:.6e} {c.y:.6e} {c.z:.6e}\n")
                f.write("  endloop\nendfacet\n")
            f.write(f"endsolid {name}\n")
        return len(mesh.loop_triangles)
    finally:
        obj_eval.to_mesh_clear()       # free the temporary mesh
```

API notes: I wrote this from memory and haven't run it in 4.2 here. `evaluated_depsgraph_get()`, `evaluated_get()`, `to_mesh()` / `to_mesh_clear()`, `calc_loop_triangles()` and `MeshLoopTriangle.normal` / `.vertices` all exist in the 4.x API as far as I know. Please check them against the Blender 4.2 Python API docs if something throws.

Quick sanity check: after running, the returned triangle count should be roughly 2 × (the evaluated mesh's quad count). For a solidified 32×80 shell that's about 4 × 32 × 79 triangles for the two skins, plus the rim triangles. If you get about half of that, the triangulation isn't being used.

Unit note: Blender writes whatever values are in the scene. If your scene is in meters with 1 unit = 1 m and you modeled a "150" lampshade as 0.15, PrusaSlicer will read 0.15 mm. Keep `unit_settings.scale_length = 0.001` with the geometry in mm, or scale the coordinates when you write them.

## Printability comments

- **0.6 mm wall with a 0.4 nozzle is borderline.** PrusaSlicer will usually slice it as one or two thin perimeters, or fill it with gap fill, and depending on settings parts of it may disappear. For a lampshade I'd either:
  - use **0.8 mm** (two clean 0.4 perimeters), or
  - skip Solidify, export a closed-bottom single surface and print in **Spiral vase mode** with a wider extrusion (for example 0.6–0.7 mm). This is often the nicest option for twisted shades, with no seam and very smooth walls.
- **Twist and overhang:** the rotation per ring adds to the wall's overhang angle. If the twist gets steep (above about 45–50° from vertical, taking the flare and twist together), expect drooping on the underside of the ribs.
- **Check Solidify settings:** "Even Thickness" helps keep the wall consistent where the twist shears the faces, and "Fill Rim" must stay on or the top and bottom edges stay open.
- **Validate before export:** run the 3D-Print Toolbox "Non-Manifold" check on the evaluated result (or apply a copy of the modifier) to confirm the shell itself is watertight. After the two fixes above, PrusaSlicer's open-edge warning should go away. If it doesn't, the problem is in the geometry, not the writer.

If you batch-export many variants, a **binary** STL is about 5× smaller and faster to write. The same `loop_triangles` loop works with `struct.pack("<12fH", ...)` per triangle after an 80-byte header and a `uint32` triangle count.
