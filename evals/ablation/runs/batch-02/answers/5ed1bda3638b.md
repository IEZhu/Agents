**Cause:** the loop deletes keys from `sessions` while it is still iterating over `sessions.items()`. Python doesn't allow a dict to change size while it's being iterated, and CPython raises `RuntimeError: dictionary changed size during iteration` on the next iteration step after the first deletion. This fits your regression: the loop only crashes when at least one session has expired, so it would have started failing once the expiry logic went in and a nightly run found an expired entry.

## Fix

First collect the expired keys, then delete them:

```python
def purge_expired(sessions: dict[str, Session], now: float) -> None:
    expired = [sid for sid, s in sessions.items() if s.expires_at < now]
    for sid in expired:
        del sessions[sid]
```

Why this version:

- **It mutates in place.** Your signature returns `None`, so callers depend on the same dict object being changed. Rebuilding it with `sessions = {k: v for ...}` inside the function would only rebind the local name, and the purge would do nothing without any error.
- **It only copies expired keys.** `for sid, s in list(sessions.items()):` also works, but it copies every entry. Collecting just the expired keys is O(n) time with O(k) extra memory, where k is the number of expired sessions.

If other threads or async tasks touch `sessions` while the purge runs, this change doesn't make it safe. You would still need a lock around the purge. Nothing you've shown suggests that, but it's worth checking for a shared session store.
