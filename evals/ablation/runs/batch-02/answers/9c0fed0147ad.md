Your writer has two separate bugs. Each one explains one of the symptoms.

## 1. "Paper-thin + open edges": you're exporting the mesh without its modifiers

`obj.data` is the **base mesh**, before any modifier runs. The Solidify modifier only exists in the evaluated (depsgraph) result. The viewport shows that evaluated result, so it looks solid there. Your writer reads the raw single surface, so the file has no thickness, and every border edge of the open shell is a non-manifold edge. PrusaSlicer is reporting exactly that.

Fix: read the evaluated mesh with `obj.evaluated_get(depsgraph).to_mesh()`, or apply the modifier before exporting.

## 2. "Every other triangle missing": you're truncating quads

Your bmesh grid (32 sides × 80 rings) is made of **quads**. `p.vertices[:3]` keeps only the first 3 vertices of each quad, so you write half of each quad and drop the other half. That gives the checkerboard of triangular gaps. It also means the normal you write is the quad's normal, not the triangle's.

Fix: triangulate first. `mesh.calc_loop_triangles()` gives you `mesh.loop_triangles`, which splits each polygon properly into triangles.

## Corrected writer

```python
import bpy


def write_ascii_stl(obj: bpy.types.Object, path: str, name: str = "shade") -> int:
    """Write the evaluated (modifiers applied), world-space, triangulated mesh as ASCII STL.
    Returns the triangle count."""
    depsgraph = bpy.context.evaluated_depsgraph_get()
    obj_eval = obj.evaluated_get(depsgraph)
    mesh = obj_eval.to_mesh()          # temporary copy with Solidify applied
    try:
        mesh.transform(obj.matrix_world)   # bake location/rotation/scale into coordinates
        mesh.calc_loop_triangles()         # triangulate quads/n-gons
        verts = mesh.vertices
        with open(path, "w") as f:
            f.write(f"solid {name}\n")
            for tri in mesh.loop_triangles:
                n = tri.normal
                f.write(f"facet normal {n.x:.6e} {n.y:.6e} {n.z:.6e}\n  outer loop\n")
                for vi in tri.vertices:
                    c = verts[vi].co
                    f.write(f"    vertex {c.x:.6e} {c.y:.6e} {c.z:.6e}\n")
                f.write("  endloop\nendfacet\n")
            f.write(f"endsolid {name}\n")
        return len(mesh.loop_triangles)
    finally:
        obj_eval.to_mesh_clear()           # free the temporary mesh
```

Notes:
- **World transform:** `vertex.co` is in local space. Without `matrix_world`, any object rotation or scale is silently lost. If the object has a **negative scale**, the transform flips the triangle winding and the normals will point inward. Apply the scale in the scene first if that applies to you.
- **Units:** STL has no units. The numbers are written in Blender units as they are. If you modeled so that 1 BU = 1 mm, PrusaSlicer will read the size correctly.
- **API check:** I'm recalling these calls from the 2.8+ API rather than checking them against the 4.2 docs: `evaluated_get`, `to_mesh`/`to_mesh_clear`, `Mesh.transform`, `calc_loop_triangles`/`loop_triangles`. I'm not aware of any change to them in 4.x, but if one throws, check it in the 4.2 API reference.

## How to confirm the fix

1. **Triangle count:** it should be about 2× the face count of the *evaluated* mesh. Solidify roughly doubles the faces and adds rim faces at the two open ends. Compare the returned count with `len(obj.data.polygons)`. If the count is only about 1×, the modifier is still missing.
2. **Manifold check:** run the evaluated mesh through a `bmesh` check before exporting. After Solidify it should have 0 edges where `not e.is_manifold`. Load it with `bm.from_object(obj, depsgraph)` so the modifiers are included, not `bm.from_mesh(obj.data)`.
3. **In PrusaSlicer:** the open-edge warning should go away and the part should show real wall thickness in the cross-section preview.

## One printability issue beyond the export bug

**0.6 mm is too thin for a 0.4 mm nozzle.** PrusaSlicer will probably fit only one perimeter there, possibly with gaps. Depending on its thin-wall and Arachne settings, it may also drop parts of the wall on the steeper twisted sections. Use **0.8 mm** (two clean perimeters) as the minimum, or 1.2 mm if the shade needs to be stiff.

Also on Solidify:
- Set it to **Even Thickness**. On a twisted surface, uneven offset makes the wall visibly thinner where the twist is sharpest.
- Keep **Fill Rim** on, so the top and bottom openings are closed off and the part stays watertight.
- Use **Offset -1 or 1** so the wall grows in a predictable direction.

**Alternative worth considering:** for a lampshade you could skip Solidify and export a closed solid. Then print it in PrusaSlicer's **spiral vase mode**, where the wall is exactly one extrusion wide (about 0.45 mm with a 0.4 nozzle). That's fast and light-transmissive, which suits a lampshade. The catch is that vase mode adds a solid bottom, so for an open-ended shade you'd have to cut it out after printing or design the part around that bottom.
