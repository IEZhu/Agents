## Latest user message
I'm generating a twisted lampshade procedurally in Blender 4.2 for my Prusa MK4 (0.4 nozzle). The script builds a single-surface shell with bmesh (32 sides, 80 rings, each ring rotated a bit), then adds a Solidify modifier with thickness 0.6 so it's printable. Because I wanted batch export without touching selection, I wrote a small ASCII STL writer:

```python
me = obj.data
with open(path, 'w') as f:
    f.write('solid shade\n')
    for p in me.polygons:
        v = [me.vertices[i].co for i in p.vertices[:3]]
        f.write(f'facet normal {p.normal.x} {p.normal.y} {p.normal.z}\n outer loop\n')
        for c in v:
            f.write(f'  vertex {c.x} {c.y} {c.z}\n')
        f.write(' endloop\nendfacet\n')
    f.write('endsolid shade\n')
```

PrusaSlicer imports it but shows it as paper-thin with a warning about open edges, and the surface is full of triangular gaps, like every other triangle is missing. In the viewport it looks perfectly solid. What's going on?

## Answer A
Your writer has two separate bugs. Each one explains one of the symptoms.

## 1. "Paper-thin + open edges": you're exporting the mesh without its modifiers

`obj.data` is the **base mesh**, before any modifier runs. The Solidify modifier only exists in the evaluated (depsgraph) result. The viewport shows that evaluated result, so it looks solid there. Your writer reads the raw single surface, so the file has no thickness, and every border edge of the open shell is a non-manifold edge. PrusaSlicer is reporting exactly that.

Fix: read the evaluated mesh with `obj.evaluated_get(depsgraph).to_mesh()`, or apply the modifier before exporting.

## 2. "Every other triangle missing": you're truncating quads

Your bmesh grid (32 sides × 80 rings) is made of **quads**. `p.vertices[:3]` keeps only the first 3 vertices of each quad, so you write half of each quad and drop the other half. That gives the checkerboard of triangular gaps. It also means the normal you write is the quad's normal, not the triangle's.

Fix: triangulate first. `mesh.calc_loop_triangles()` gives you `mesh.loop_triangles`, which splits each polygon properly into triangles.

## Corrected writer

```python
import bpy


def write_ascii_stl(obj: bpy.types.Object, path: str, name: str = "shade") -> int:
    """Write the evaluated (modifiers applied), world-space, triangulated mesh as ASCII STL.
    Returns the triangle count."""
    depsgraph = bpy.context.evaluated_depsgraph_get()
    obj_eval = obj.evaluated_get(depsgraph)
    mesh = obj_eval.to_mesh()          # temporary copy with Solidify applied
    try:
        mesh.transform(obj.matrix_world)   # bake location/rotation/scale into coordinates
        mesh.calc_loop_triangles()         # triangulate quads/n-gons
        verts = mesh.vertices
        with open(path, "w") as f:
            f.write(f"solid {name}\n")
            for tri in mesh.loop_triangles:
                n = tri.normal
                f.write(f"facet normal {n.x:.6e} {n.y:.6e} {n.z:.6e}\n  outer loop\n")
                for vi in tri.vertices:
                    c = verts[vi].co
                    f.write(f"    vertex {c.x:.6e} {c.y:.6e} {c.z:.6e}\n")
                f.write("  endloop\nendfacet\n")
            f.write(f"endsolid {name}\n")
        return len(mesh.loop_triangles)
    finally:
        obj_eval.to_mesh_clear()           # free the temporary mesh
```

Notes:
- **World transform:** `vertex.co` is in local space. Without `matrix_world`, any object rotation or scale is silently lost. If the object has a **negative scale**, the transform flips the triangle winding and the normals will point inward. Apply the scale in the scene first if that applies to you.
- **Units:** STL has no units. The numbers are written in Blender units as they are. If you modeled so that 1 BU = 1 mm, PrusaSlicer will read the size correctly.
- **API check:** I'm recalling these calls from the 2.8+ API rather than checking them against the 4.2 docs: `evaluated_get`, `to_mesh`/`to_mesh_clear`, `Mesh.transform`, `calc_loop_triangles`/`loop_triangles`. I'm not aware of any change to them in 4.x, but if one throws, check it in the 4.2 API reference.

## How to confirm the fix

1. **Triangle count:** it should be about 2× the face count of the *evaluated* mesh. Solidify roughly doubles the faces and adds rim faces at the two open ends. Compare the returned count with `len(obj.data.polygons)`. If the count is only about 1×, the modifier is still missing.
2. **Manifold check:** run the evaluated mesh through a `bmesh` check before exporting. After Solidify it should have 0 edges where `not e.is_manifold`. Load it with `bm.from_object(obj, depsgraph)` so the modifiers are included, not `bm.from_mesh(obj.data)`.
3. **In PrusaSlicer:** the open-edge warning should go away and the part should show real wall thickness in the cross-section preview.

## One printability issue beyond the export bug

**0.6 mm is too thin for a 0.4 mm nozzle.** PrusaSlicer will probably fit only one perimeter there, possibly with gaps. Depending on its thin-wall and Arachne settings, it may also drop parts of the wall on the steeper twisted sections. Use **0.8 mm** (two clean perimeters) as the minimum, or 1.2 mm if the shade needs to be stiff.

Also on Solidify:
- Set it to **Even Thickness**. On a twisted surface, uneven offset makes the wall visibly thinner where the twist is sharpest.
- Keep **Fill Rim** on, so the top and bottom openings are closed off and the part stays watertight.
- Use **Offset -1 or 1** so the wall grows in a predictable direction.

**Alternative worth considering:** for a lampshade you could skip Solidify and export a closed solid. Then print it in PrusaSlicer's **spiral vase mode**, where the wall is exactly one extrusion wide (about 0.45 mm with a 0.4 nozzle). That's fast and light-transmissive, which suits a lampshade. The catch is that vase mode adds a solid bottom, so for an open-ended shade you'd have to cut it out after printing or design the part around that bottom.


## Answer B
Your writer has two separate bugs, and each one explains one of the symptoms. The mesh in Blender is fine. The file you write out is not.

## Bug 1: "every other triangle is missing" is caused by `p.vertices[:3]`

Your shell is made of quads (32 sides × 80 rings, each face joining two rings). `p.vertices[:3]` keeps the first three corners of each quad and throws away the fourth. A quad `A B C D` should become two triangles, `A B C` and `A C D`. You only write `A B C`, so half of every face is missing. On a grid that looks exactly like a checkerboard of triangular holes, and every hole produces open edges.

**Fix:** triangulate before writing. Blender already keeps a triangulation for this: `mesh.loop_triangles`. Don't slice polygons yourself.

## Bug 2: "paper-thin" happens because `obj.data` is the mesh before modifiers

`obj.data` is the original mesh datablock, which here is your single surface. The Solidify modifier is non-destructive. It only exists in the evaluated result, which the viewport draws. That's why the viewport looks solid while the file contains a zero-thickness sheet. A single surface with no thickness is also non-manifold by definition, which adds more open-edge warnings.

**Fix:** read the evaluated mesh from the depsgraph. This includes Solidify and any other modifiers, and you don't need to change the selection or apply anything.

## Third, smaller issue: object transform

`me.vertices[i].co` is in local space. If the object has location, rotation or scale that you haven't applied, the STL will ignore them. Multiply by `obj.matrix_world`.

## Corrected writer

```python
import bpy
from pathlib import Path


def write_ascii_stl(obj: bpy.types.Object, path: str | Path, name: str = "shade") -> int:
    """Write the evaluated (post-modifier), world-space, triangulated mesh of obj.

    Returns the number of triangles written.
    """
    depsgraph = bpy.context.evaluated_depsgraph_get()
    obj_eval = obj.evaluated_get(depsgraph)
    mesh = obj_eval.to_mesh()          # temporary mesh WITH Solidify applied
    try:
        mesh.calc_loop_triangles()
        mw = obj_eval.matrix_world
        normal_mat = mw.to_3x3().inverted_safe().transposed()
        verts_world = [mw @ v.co for v in mesh.vertices]

        with open(path, "w", encoding="ascii") as f:
            f.write(f"solid {name}\n")
            for tri in mesh.loop_triangles:
                n = (normal_mat @ tri.normal).normalized()
                f.write(f"facet normal {n.x:.6e} {n.y:.6e} {n.z:.6e}\n  outer loop\n")
                for vi in tri.vertices:
                    c = verts_world[vi]
                    f.write(f"    vertex {c.x:.6e} {c.y:.6e} {c.z:.6e}\n")
                f.write("  endloop\nendfacet\n")
            f.write(f"endsolid {name}\n")
        return len(mesh.loop_triangles)
    finally:
        obj_eval.to_mesh_clear()       # free the temporary mesh
```

API notes: I wrote this from memory and haven't run it in 4.2 here. `evaluated_depsgraph_get()`, `evaluated_get()`, `to_mesh()` / `to_mesh_clear()`, `calc_loop_triangles()` and `MeshLoopTriangle.normal` / `.vertices` all exist in the 4.x API as far as I know. Please check them against the Blender 4.2 Python API docs if something throws.

Quick sanity check: after running, the returned triangle count should be roughly 2 × (the evaluated mesh's quad count). For a solidified 32×80 shell that's about 4 × 32 × 79 triangles for the two skins, plus the rim triangles. If you get about half of that, the triangulation isn't being used.

Unit note: Blender writes whatever values are in the scene. If your scene is in meters with 1 unit = 1 m and you modeled a "150" lampshade as 0.15, PrusaSlicer will read 0.15 mm. Keep `unit_settings.scale_length = 0.001` with the geometry in mm, or scale the coordinates when you write them.

## Printability comments

- **0.6 mm wall with a 0.4 nozzle is borderline.** PrusaSlicer will usually slice it as one or two thin perimeters, or fill it with gap fill, and depending on settings parts of it may disappear. For a lampshade I'd either:
  - use **0.8 mm** (two clean 0.4 perimeters), or
  - skip Solidify, export a closed-bottom single surface and print in **Spiral vase mode** with a wider extrusion (for example 0.6–0.7 mm). This is often the nicest option for twisted shades, with no seam and very smooth walls.
- **Twist and overhang:** the rotation per ring adds to the wall's overhang angle. If the twist gets steep (above about 45–50° from vertical, taking the flare and twist together), expect drooping on the underside of the ribs.
- **Check Solidify settings:** "Even Thickness" helps keep the wall consistent where the twist shears the faces, and "Fill Rim" must stay on or the top and bottom edges stay open.
- **Validate before export:** run the 3D-Print Toolbox "Non-Manifold" check on the evaluated result (or apply a copy of the modifier) to confirm the shell itself is watertight. After the two fixes above, PrusaSlicer's open-edge warning should go away. If it doesn't, the problem is in the geometry, not the writer.

If you batch-export many variants, a **binary** STL is about 5× smaller and faster to write. The same `loop_triangles` loop works with `struct.pack("<12fH", ...)` per triangle after an 80-byte header and a `uint32` triangle count.
