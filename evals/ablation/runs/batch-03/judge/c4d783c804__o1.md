## Latest user message
У нас небольшой сервис на FastAPI (Python 3.11), оплата идёт только через ЮKassa, и других провайдеров в планах на этот год нет. Сейчас вся логика в одном модуле payments.py:

```python
import httpx

YOOKASSA_URL = "https://api.yookassa.ru/v3/payments"

async def create_payment(order_id: int, amount_rub: float, return_url: str) -> str:
    async with httpx.AsyncClient(auth=(settings.SHOP_ID, settings.SECRET_KEY), timeout=10) as client:
        resp = await client.post(
            YOOKASSA_URL,
            json={
                "amount": {"value": f"{amount_rub:.2f}", "currency": "RUB"},
                "confirmation": {"type": "redirect", "return_url": return_url},
                "capture": True,
                "metadata": {"order_id": order_id},
            },
            headers={"Idempotence-Key": f"order-{order_id}"},
        )
        resp.raise_for_status()
        return resp.json()["confirmation"]["confirmation_url"]
```

Тимлид сказал «сделай по-взрослому, чтобы потом можно было легко добавить Stripe, CloudPayments, Тинькофф». Я хочу сделать абстрактный базовый класс PaymentProvider с методами create_payment / refund / get_status / handle_webhook, фабрику ProviderFactory с реестром через декоратор, отдельный DTO на каждый запрос и ответ и конфиг выбора провайдера через env. Накидай, пожалуйста, эту структуру целиком, с кодом.

## Rubric (what a strong answer does)
1. Explicitly says that an abstract base class, factory and decorator registry for a single provider, with no second provider planned, is premature, and names a concrete cost (e.g. more code to maintain, or an abstraction guessed from one provider may not fit the next one).
2. Offers a concrete lighter alternative (e.g. keep a small module or one class behind a simple function or Protocol, and extract the abstraction when a second provider actually arrives) rather than only refusing.
3. Does not present the full requested scaffold (ABC with four methods + decorator registry + per-request DTOs + env-based provider selection) as the primary recommendation without any caveat.
4. Technical remarks on the existing code are correct, e.g. noting that float is risky for money amounts and Decimal is preferable; the answer introduces no errors.

## Answer A
Структуру ниже я сделал целиком. Сначала одно возражение по сути, потом код.

## Что здесь полезно, а что преждевременно

Провайдер у вас один, и других в этом году не планируется. Поэтому часть запрошенной гибкости останется мёртвым кодом:

- **Полезно уже сейчас: ABC и DTO.** Бизнес-логика перестаёт зависеть от JSON ЮKassa, провайдера легко подменить фейком в тестах, а `Decimal` вместо `float` убирает реальный баг.
- **Преждевременно: реестр через декоратор, фабрика и выбор провайдера через env.** При одном провайдере значение переменной всегда одно и то же. Когда появится второй, это ~20 строк, которые пишутся за полчаса.
- **Главный риск: интерфейс, придуманный по одному провайдеру, почти наверняка окажется неправильным.** У Stripe, CloudPayments и Тинькофф разные модели вебхуков (подпись, HMAC, токен, у ЮKassa вообще без подписи), разные статусы, двухстадийные платежи, рекурренты и чеки по 54-ФЗ. Интерфейс лучше уточнить, когда рядом будет второй реальный провайдер.

Мой совет тимлиду: оставить ABC + DTO, а реестр и env-переключение не делать. Я всё же включил их в код, потому что вы просили именно так. Это отдельные небольшие файлы, их легко выкинуть.

## Баги в текущем коде (стоит починить при любой архитектуре)

1. **`float` для денег.** Нужен `Decimal`.
2. **`Idempotence-Key: order-{order_id}`.** Если пользователь не оплатил и платёж отменён, повторная попытка с тем же ключом вернёт тот же старый платёж. Насколько я помню, у ЮKassa ключ действует 24 часа (по памяти, не проверял, сверьтесь с документацией). Ключ нужен на каждую попытку оплаты, а не на заказ.
3. **Новый `AsyncClient` на каждый запрос.** Каждый раз заново открываются TCP- и TLS-соединения. Лучше один клиент на всё приложение, созданный в `lifespan`.
4. **`raise_for_status()` без контекста.** Ошибка теряет тело ответа ЮKassa, а из него видно, что именно не так.

from dataclasses import dataclass
from decimal import Decimal
from enum import StrEnum


class PaymentStatus(StrEnum):
    PENDING = "pending"
    WAITING_FOR_CAPTURE = "waiting_for_capture"
    SUCCEEDED = "succeeded"
    CANCELED = "canceled"


class RefundStatus(StrEnum):
    PENDING = "pending"
    SUCCEEDED = "succeeded"
    CANCELED = "canceled"


@dataclass(frozen=True, slots=True)
class Money:
    amount: Decimal
    currency: str = "RUB"

    def __post_init__(self) -> None:
        if self.amount <= 0:
            raise ValueError(f"Money amount must be positive, got {self.amount}")


@dataclass(frozen=True, slots=True)

    amount: Money
    return_url: str

@dataclass(frozen=True, slots=True)
class CreatePaymentResponse:
    payment_id: str
    status: PaymentStatus
    confirmation_url: str | None


@dataclass(frozen=True, slots=True)
class RefundRequest:
    payment_id: str
    amount: Money
    idempotency_key: str


@dataclass(frozen=True, slots=True)
class RefundResponse:
    refund_id: str
    status: RefundStatus


@dataclass(frozen=True, slots=True)
class PaymentInfo:
    payment_id: str
    status: PaymentStatus
    amount: Money

### `base.py`

```python
from abc import ABC, abstractmethod
from collections.abc import Mapping
from typing import ClassVar, Self

from .config import PaymentSettings
from .dto import (
    CreatePaymentRequest,
    CreatePaymentResponse,
    PaymentInfo,
    RefundRequest,
    RefundResponse,
    WebhookEvent,
)


class PaymentProvider(ABC):
    name: ClassVar[str]

    @classmethod
    @abstractmethod
    def from_settings(cls, settings: PaymentSettings) -> Self:
        """У каждого провайдера свои креды, поэтому конструирует себя сам."""

    @abstractmethod
    async def create_payment(self, request: CreatePaymentRequest) -> CreatePaymentResponse: ...

    @abstractmethod
    async def refund(self, request: RefundRequest) -> RefundResponse: ...

    @abstractmethod
    async def get_status(self, payment_id: str) -> PaymentInfo: ...

    @abstractmethod
    async def parse_webhook(
        self, body: bytes, headers: Mapping[str, str], client_ip: str | None
    ) -> WebhookEvent:
        """Проверить подлинность и нормализовать событие.

        Бизнес-логику (пометить заказ оплаченным) здесь НЕ делаем:
        это задача сервиса заказов, одинаковая для всех провайдеров.
        """

    async def aclose(self) -> None:  # noqa: B027 - необязательный хук
        return None
```

`handle_webhook` я намеренно переименовал в `parse_webhook`. Если провайдер сам «обрабатывает» вебхук, логика заказов расползётся по всем реализациям.

### `registry.py`

```python
from collections.abc import Callable
from typing import TypeVar

from .base import PaymentProvider
from .config import PaymentSettings
from .errors import UnknownProviderError

_P = TypeVar("_P", bound=type[PaymentProvider])
_REGISTRY: dict[str, type[PaymentProvider]] = {}


def register_provider(name: str) -> Callable[[_P], _P]:
    def decorator(cls: _P) -> _P:
        if name in _REGISTRY:
            raise ValueError(f"Payment provider {name!r} is already registered")
        cls.name = name
        _REGISTRY[name] = cls
        return cls

    return decorator


class ProviderFactory:
    @staticmethod
    def create(settings: PaymentSettings) -> PaymentProvider:
        try:
            provider_cls = _REGISTRY[settings.payment_provider]
        except KeyError:
            raise UnknownProviderError(
                f"Unknown payment provider {settings.payment_provider!r}; "
                f"registered: {sorted(_REGISTRY)}"
            ) from None
        return provider_cls.from_settings(settings)
```

### `providers/yookassa.py`

```python
import ipaddress
import json
from collections.abc import Mapping
from decimal import Decimal
from typing import Any, Self

import httpx

from ..base import PaymentProvider
from ..config import PaymentSettings
from ..dto import (
    CreatePaymentRequest,
    CreatePaymentResponse,
    Money,
    PaymentInfo,
    PaymentStatus,
    RefundRequest,
    RefundResponse,
    RefundStatus,
    WebhookEvent,
)
from ..errors import PaymentProviderError, WebhookVerificationError
from ..registry import register_provider

YOOKASSA_API = "https://api.yookassa.ru/v3"

# Список IP для уведомлений ЮKassa по памяти, НЕ проверен.
# Сверьтесь с актуальной документацией перед продом.
_TRUSTED_NETWORKS = tuple(
    ipaddress.ip_network(n)
    for n in (
        "185.71.76.0/27",
        "185.71.77.0/27",
        "77.75.153.0/25",
        "77.75.156.11/32",
        "77.75.156.35/32",
        "77.75.154.128/25",
        "2a02:5180::/32",
    )
)


def _money_to_api(money: Money) -> dict[str, str]:
    return {"value": str(money.amount.quantize(Decimal("0.01"))), "currency": money.currency}


def _money_from_api(data: Mapping[str, Any]) -> Money:
    return Money(amount=Decimal(data["value"]), currency=data["currency"])


def _to_payment_info(data: Mapping[str, Any]) -> PaymentInfo:
    raw_order_id = data.get("metadata", {}).get("order_id")
    return PaymentInfo(
        payment_id=data["id"],
        status=PaymentStatus(data["status"]),
        amount=_money_from_api(data["amount"]),
        order_id=int(raw_order_id) if raw_order_id is not None else None,
    )


def _is_trusted_ip(client_ip: str | None) -> bool:
    if client_ip is None:
        return False
    try:
        addr = ipaddress.ip_address(client_ip)
    except ValueError:
        return False
    return any(addr in net for net in _TRUSTED_NETWORKS)


@register_provider("yookassa")
class YooKassaProvider(PaymentProvider):
    def __init__(self, client: httpx.AsyncClient) -> None:
        self._client = client

    @classmethod
    def from_settings(cls, settings: PaymentSettings) -> Self:
        if not settings.yookassa_shop_id or not settings.yookassa_secret_key.get_secret_value():
            raise ValueError("YOOKASSA_SHOP_ID and YOOKASSA_SECRET_KEY must be set")
        client = httpx.AsyncClient(
            base_url=YOOKASSA_API,
            auth=(settings.yookassa_shop_id, settings.yookassa_secret_key.get_secret_value()),
            timeout=settings.yookassa_timeout_s,
        )
        return cls(client)

    async def create_payment(self, request: CreatePaymentRequest) -> CreatePaymentResponse:
        payload: dict[str, Any] = {
            "amount": _money_to_api(request.amount),
            "confirmation": {"type": "redirect", "return_url": request.return_url},
            "capture": True,
            "metadata": {"order_id": str(request.order_id)},
        }
        if request.description:
            payload["description"] = request.description

        data = await self._request(
            "POST", "/payments", json=payload, idempotency_key=request.idempotency_key
        )
        return CreatePaymentResponse(
            payment_id=data["id"],
            status=PaymentStatus(data["status"]),
            confirmation_url=data.get("confirmation", {}).get("confirmation_url"),
        )

    async def refund(self, request: RefundRequest) -> RefundResponse:
        data = await self._request(
            "POST",
            "/refunds",
            json={"payment_id": request.payment_id, "amount": _money_to_api(request.amount)},
            idempotency_key=request.idempotency_key,
        )
        return RefundResponse(refund_id=data["id"], status=RefundStatus(data["status"]))

    async def get_status(self, payment_id: str) -> PaymentInfo:
        return _to_payment_info(await self._request("GET", f"/payments/{payment_id}"))

    async def parse_webhook(
        self, body: bytes, headers: Mapping[str, str], client_ip: str | None
    ) -> WebhookEvent:
        # ЮKassa, насколько я знаю, не подписывает уведомления. Защита такая:
        # allowlist IP + перечитать объект из API, а телу вебхука не доверять.
        if not _is_trusted_ip(client_ip):
            raise WebhookVerificationError(f"Untrusted webhook source IP: {client_ip}")
        try:
            event = json.loads(body)
            event_type: str = event["event"]
            obj = event["object"]
            payment_id: str = obj["payment_id"] if event_type.startswith("refund.") else obj["id"]
        except (ValueError, KeyError, TypeError) as exc:
            raise WebhookVerificationError("Malformed YooKassa webhook payload") from exc

        return WebhookEvent(event_type=event_type, payment=await self.get_status(payment_id))

    async def aclose(self) -> None:
        await self._client.aclose()

    async def _request(
        self,
        method: str,
        path: str,
        *,
        json: dict[str, Any] | None = None,
        idempotency_key: str | None = None,
    ) -> dict[str, Any]:
        headers = {"Idempotence-Key": idempotency_key} if idempotency_key else None
        try:
            resp = await self._client.request(method, path, json=json, headers=headers)
            resp.raise_for_status()
        except httpx.HTTPStatusError as exc:
            raise PaymentProviderError(
                self.name,
                f"{method} {path} -> {exc.response.status_code}: {exc.response.text[:500]}",
            ) from exc
        except httpx.HTTPError as exc:
            raise PaymentProviderError(self.name, f"{method} {path} failed: {exc!r}") from exc
        return resp.json()
```

### `dependencies.py`

from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

from fastapi import FastAPI, Request

from . import providers  # noqa: F401  (регистрация провайдеров)
from .base import PaymentProvider
from .config import PaymentSettings
from .registry import ProviderFactory


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    provider = ProviderFactory.create(PaymentSettings())  # fail fast при старте
    app.state.payment_provider = provider
    try:
        yield
    finally:
        await provider.aclose()


def get_payment_provider(request: Request) -> PaymentProvider:
    return request.app.state.payment_provider

### `webhooks.py`

```python
import logging

from fastapi import APIRouter, Depends, HTTPException, Request, Response

from .base import PaymentProvider
from .dependencies import get_payment_provider
from .errors import PaymentProviderError, WebhookVerificationError

logger = logging.getLogger(__name__)
router = APIRouter()


@router.post("/webhooks/payments")
async def payment_webhook(
    request: Request, provider: PaymentProvider = Depends(get_payment_provider)
) -> Response:
    client_ip = request.client.host if request.client else None
    try:
        event = await provider.parse_webhook(await request.body(), request.headers, client_ip)
    except WebhookVerificationError as exc:
        logger.warning("Rejected payment webhook: %s", exc)
        raise HTTPException(status_code=400) from exc
    except PaymentProviderError:
        logger.exception("Failed to re-fetch payment status for webhook")
        raise HTTPException(status_code=502)  # не 2xx, значит провайдер повторит доставку

    await apply_payment_event(event)  # ваш сервис заказов; ДОЛЖЕН быть идемпотентным
    return Response(status_code=200)
```

## Answer B
Эту структуру целиком я бы сейчас делать не стал. Вы сами написали: провайдер один, других в этом году не будет. ABC + фабрика с реестром через декоратор + DTO на каждый запрос + выбор провайдера через env — это инфраструктура под три интеграции, которых нет. Это классический YAGNI, и у него здесь две конкретные цены:

1. **Абстракция, выведенная из одного провайдера, почти наверняка окажется неправильной.** У ЮKassa модель «создал платёж → редирект → webhook». У Stripe другая: PaymentIntent, подтверждение на клиенте через `client_secret`, подписанные webhook-и, свои статусы. Интерфейс `create_payment(...) -> str`, придуманный сейчас, при подключении Stripe придётся переделывать. То есть платите сейчас, а потом всё равно переписываете.
2. **Env-переключатель провайдера сегодня переключает между одним вариантом.** Это мёртвая конфигурация, и её придётся поддерживать и тестировать.

«По-взрослому» для платёжного модуля — это прежде всего надёжность, а не иерархия классов. В текущем коде настоящие проблемы вот какие:

| Проблема | Почему важно |
|---|---|
| `amount_rub: float` | Деньги во float — ошибки округления. Нужен `Decimal`. |
| Новый `AsyncClient` на каждый вызов | Нет переиспользования соединений: каждый раз новый TLS-handshake. |
| Наружу возвращается только URL | Теряется `payment_id`, без него не сделать ни `get_status`, ни refund, ни сверку webhook-а. |
| `Idempotence-Key: order-{order_id}` | Если первый платёж по заказу отменён и пользователь платит снова, ЮKassa по тому же ключу вернёт старый ответ. Ключ нужен на **попытку оплаты**, а не на заказ. (Точный срок жизни ключа по памяти около 24 часов, не проверял — сверьтесь с документацией.) |
| `raise_for_status()` наружу | Роуты ловят `httpx.HTTPStatusError`, и детали транспорта протекают в бизнес-логику. Нужна своя ошибка с контекстом. |
| Webhook-а нет | Webhook-и ЮKassa, насколько я помню, не подписываются. Телу уведомления нельзя доверять, статус надо перезапрашивать через API. (Не проверено — сверьтесь с разделом про уведомления в документации ЮKassa.) |

Ниже вариант, который закрывает всё это и остаётся простым. Расширяемость в нём тоже есть: роуты зависят от клиента через `Depends`, поэтому второй провайдер подключается локально.

## `yookassa.py`

```python
from decimal import Decimal
from typing import Any

import httpx

from .models import Payment, PaymentError, PaymentStatus

API_BASE = "https://api.yookassa.ru/v3"
_KOPECKS = Decimal("0.01")


class YooKassaClient:
    def __init__(self, http: httpx.AsyncClient) -> None:
        self._http = http

    async def create_payment(
        self, *, order_id: int, amount: Decimal, return_url: str, idempotence_key: str
    ) -> Payment:
        body = {
            "amount": _money(amount),
            "confirmation": {"type": "redirect", "return_url": return_url},
            "capture": True,
            "metadata": {"order_id": order_id},
        }
        data = await self._request("POST", "/payments", json=body, idempotence_key=idempotence_key)
        return _to_payment(data)

    async def get_payment(self, payment_id: str) -> Payment:
        return _to_payment(await self._request("GET", f"/payments/{payment_id}"))

    async def refund(self, *, payment_id: str, amount: Decimal, idempotence_key: str) -> str:
        """Создаёт возврат и возвращает его id."""
        data = await self._request(
            "POST",
            "/refunds",
            json={"payment_id": payment_id, "amount": _money(amount)},
            idempotence_key=idempotence_key,
        )
        return data["id"]

    async def _request(
        self,
        method: str,
        path: str,
        *,
        json: dict[str, Any] | None = None,
        idempotence_key: str | None = None,
    ) -> dict[str, Any]:
        headers = {"Idempotence-Key": idempotence_key} if idempotence_key else None
        try:
            resp = await self._http.request(method, path, json=json, headers=headers)
            resp.raise_for_status()
            return resp.json()
        except httpx.HTTPStatusError as exc:
            raise PaymentError(
                f"YooKassa {method} {path} -> {exc.response.status_code}: {exc.response.text[:500]}"
            ) from exc
        except httpx.HTTPError as exc:
            raise PaymentError(f"YooKassa {method} {path} failed: {exc!r}") from exc


def _money(amount: Decimal) -> dict[str, str]:
    if amount <= 0:
        raise ValueError(f"amount must be positive, got {amount}")
    return {"value": str(amount.quantize(_KOPECKS)), "currency": "RUB"}


def _to_payment(data: dict[str, Any]) -> Payment:
    try:
        order_id = data.get("metadata", {}).get("order_id")
        return Payment(
            id=data["id"],
            status=PaymentStatus(data["status"]),
            amount=Decimal(data["amount"]["value"]),
            order_id=int(order_id) if order_id is not None else None,
            confirmation_url=(data.get("confirmation") or {}).get("confirmation_url"),
        )
    except (KeyError, ValueError, TypeError) as exc:
        raise PaymentError(f"Unexpected YooKassa payment payload: {exc!r}") from exc
```

`int(order_id)` стоит не случайно: насколько я помню, ЮKassa возвращает значения `metadata` строками.

## `deps.py`

```python
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

import httpx
from fastapi import FastAPI, Request

from app.config import settings
from .yookassa import API_BASE, YooKassaClient


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    async with httpx.AsyncClient(
        base_url=API_BASE,
        auth=(settings.SHOP_ID, settings.SECRET_KEY),
        timeout=10,
    ) as http:
        app.state.yookassa = YooKassaClient(http)
        yield


def get_yookassa(request: Request) -> YooKassaClient:
    return request.app.state.yookassa
```

Подключается через `FastAPI(lifespan=lifespan)`. Если lifespan уже есть, вложите этот контекст в него.

## `routes.py`

```python
import uuid
from decimal import Decimal

from fastapi import APIRouter, Depends, HTTPException, Request
from pydantic import BaseModel, Field, HttpUrl

from .deps import get_yookassa
from .models import PaymentError
from .yookassa import YooKassaClient
from app import orders  # ваш слой работы с заказами

router = APIRouter()


class CreatePaymentIn(BaseModel):
    order_id: int
    amount: Decimal = Field(gt=0, decimal_places=2)
    return_url: HttpUrl


class CreatePaymentOut(BaseModel):
    payment_id: str
    confirmation_url: str


@router.post("/payments", response_model=CreatePaymentOut)
async def create_payment(
    body: CreatePaymentIn, client: YooKassaClient = Depends(get_yookassa)
) -> CreatePaymentOut:
    # Ключ на попытку оплаты. Сохраните его вместе с попыткой,
    # чтобы ретрай этой же попытки шёл с тем же ключом.
    attempt_key = str(uuid.uuid4())
    try:
        payment = await client.create_payment(
            order_id=body.order_id,
            amount=body.amount,
            return_url=str(body.return_url),
            idempotence_key=attempt_key,
        )
    except PaymentError as exc:
        raise HTTPException(status_code=502, detail="Payment provider unavailable") from exc

    await orders.attach_payment(body.order_id, payment.id)
    if payment.confirmation_url is None:
        raise HTTPException(status_code=502, detail="Provider returned no confirmation URL")
    return CreatePaymentOut(payment_id=payment.id, confirmation_url=payment.confirmation_url)


@router.post("/webhooks/yookassa")
async def yookassa_webhook(
    request: Request, client: YooKassaClient = Depends(get_yookassa)
) -> dict:
    event = await request.json()
    payment_id = (event.get("object") or {}).get("id")
    if not payment_id:
        raise HTTPException(status_code=400, detail="No payment id in notification")

    # Телу уведомления не доверяем: берём актуальный статус из API.
    payment = await client.get_payment(payment_id)
    await orders.apply_payment_status(payment)  # должно быть идемпотентным: webhook-и приходят повторно
    return {}
```

Если `get_payment` упадёт с `PaymentError`, роут вернёт 5xx, и ЮKassa повторит уведомление. Здесь это нужное поведение.

Одно замечание: если в проекте реальные суммы и так приходят из заказа, а не от клиента, уберите `amount` из `CreatePaymentIn` и берите её из БД. Сумма от клиента в эндпоинте оплаты — дыра.

## Как это расширяется, когда Stripe действительно понадобится

- Роуты уже зависят от клиента через `Depends(get_yookassa)`, а не от глобальной функции. Точка замены одна.
- При появлении второго провайдера нужно выделить `typing.Protocol` из **реальных** методов двух клиентов, а не из догадок. Это полдня работы. Выбор провайдера тогда, скорее всего, будет не через env, а по заказу, валюте или стране. Ещё одна причина не фиксировать это решение сейчас.
- Фабрика с реестром через декоратор, скорее всего, не понадобится и тогда: для 2–4 провайдеров хватит обычного `dict[str, Provider]`, собранного в lifespan.

Тимлиду можно так и сформулировать: «сделал Decimal, общий клиент, типизированные ошибки, идемпотентность на попытку, проверяемые webhook-и и тесты; точка расширения одна — dependency; интерфейс выделим из двух реальных API, когда появится второй». Если он всё же настаивает на полной иерархии сейчас, могу накидать и её. Но я бы сначала обсудил аргумент про неверную абстракцию.
