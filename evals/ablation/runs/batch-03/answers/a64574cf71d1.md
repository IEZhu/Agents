Эту структуру целиком я бы сейчас делать не стал. Вы сами написали: провайдер один, других в этом году не будет. ABC + фабрика с реестром через декоратор + DTO на каждый запрос + выбор провайдера через env — это инфраструктура под три интеграции, которых нет. Это классический YAGNI, и у него здесь две конкретные цены:

1. **Абстракция, выведенная из одного провайдера, почти наверняка окажется неправильной.** У ЮKassa модель «создал платёж → редирект → webhook». У Stripe другая: PaymentIntent, подтверждение на клиенте через `client_secret`, подписанные webhook-и, свои статусы. Интерфейс `create_payment(...) -> str`, придуманный сейчас, при подключении Stripe придётся переделывать. То есть платите сейчас, а потом всё равно переписываете.
2. **Env-переключатель провайдера сегодня переключает между одним вариантом.** Это мёртвая конфигурация, и её придётся поддерживать и тестировать.

«По-взрослому» для платёжного модуля — это прежде всего надёжность, а не иерархия классов. В текущем коде настоящие проблемы вот какие:

| Проблема | Почему важно |
|---|---|
| `amount_rub: float` | Деньги во float — ошибки округления. Нужен `Decimal`. |
| Новый `AsyncClient` на каждый вызов | Нет переиспользования соединений: каждый раз новый TLS-handshake. |
| Наружу возвращается только URL | Теряется `payment_id`, без него не сделать ни `get_status`, ни refund, ни сверку webhook-а. |
| `Idempotence-Key: order-{order_id}` | Если первый платёж по заказу отменён и пользователь платит снова, ЮKassa по тому же ключу вернёт старый ответ. Ключ нужен на **попытку оплаты**, а не на заказ. (Точный срок жизни ключа по памяти около 24 часов, не проверял — сверьтесь с документацией.) |
| `raise_for_status()` наружу | Роуты ловят `httpx.HTTPStatusError`, и детали транспорта протекают в бизнес-логику. Нужна своя ошибка с контекстом. |
| Webhook-а нет | Webhook-и ЮKassa, насколько я помню, не подписываются. Телу уведомления нельзя доверять, статус надо перезапрашивать через API. (Не проверено — сверьтесь с разделом про уведомления в документации ЮKassa.) |

Ниже вариант, который закрывает всё это и остаётся простым. Расширяемость в нём тоже есть: роуты зависят от клиента через `Depends`, поэтому второй провайдер подключается локально.

## `models.py`

```python
from dataclasses import dataclass
from decimal import Decimal
from enum import StrEnum


class PaymentStatus(StrEnum):
    PENDING = "pending"
    WAITING_FOR_CAPTURE = "waiting_for_capture"
    SUCCEEDED = "succeeded"
    CANCELED = "canceled"


@dataclass(frozen=True, slots=True)
class Payment:
    id: str
    status: PaymentStatus
    amount: Decimal
    order_id: int | None
    confirmation_url: str | None = None


class PaymentError(Exception):
    """Сбой при обращении к платёжному провайдеру: сеть, 4xx/5xx или неожиданный формат ответа."""
```

## `yookassa.py`

```python
from decimal import Decimal
from typing import Any

import httpx

from .models import Payment, PaymentError, PaymentStatus

API_BASE = "https://api.yookassa.ru/v3"
_KOPECKS = Decimal("0.01")


class YooKassaClient:
    def __init__(self, http: httpx.AsyncClient) -> None:
        self._http = http

    async def create_payment(
        self, *, order_id: int, amount: Decimal, return_url: str, idempotence_key: str
    ) -> Payment:
        body = {
            "amount": _money(amount),
            "confirmation": {"type": "redirect", "return_url": return_url},
            "capture": True,
            "metadata": {"order_id": order_id},
        }
        data = await self._request("POST", "/payments", json=body, idempotence_key=idempotence_key)
        return _to_payment(data)

    async def get_payment(self, payment_id: str) -> Payment:
        return _to_payment(await self._request("GET", f"/payments/{payment_id}"))

    async def refund(self, *, payment_id: str, amount: Decimal, idempotence_key: str) -> str:
        """Создаёт возврат и возвращает его id."""
        data = await self._request(
            "POST",
            "/refunds",
            json={"payment_id": payment_id, "amount": _money(amount)},
            idempotence_key=idempotence_key,
        )
        return data["id"]

    async def _request(
        self,
        method: str,
        path: str,
        *,
        json: dict[str, Any] | None = None,
        idempotence_key: str | None = None,
    ) -> dict[str, Any]:
        headers = {"Idempotence-Key": idempotence_key} if idempotence_key else None
        try:
            resp = await self._http.request(method, path, json=json, headers=headers)
            resp.raise_for_status()
            return resp.json()
        except httpx.HTTPStatusError as exc:
            raise PaymentError(
                f"YooKassa {method} {path} -> {exc.response.status_code}: {exc.response.text[:500]}"
            ) from exc
        except httpx.HTTPError as exc:
            raise PaymentError(f"YooKassa {method} {path} failed: {exc!r}") from exc


def _money(amount: Decimal) -> dict[str, str]:
    if amount <= 0:
        raise ValueError(f"amount must be positive, got {amount}")
    return {"value": str(amount.quantize(_KOPECKS)), "currency": "RUB"}


def _to_payment(data: dict[str, Any]) -> Payment:
    try:
        order_id = data.get("metadata", {}).get("order_id")
        return Payment(
            id=data["id"],
            status=PaymentStatus(data["status"]),
            amount=Decimal(data["amount"]["value"]),
            order_id=int(order_id) if order_id is not None else None,
            confirmation_url=(data.get("confirmation") or {}).get("confirmation_url"),
        )
    except (KeyError, ValueError, TypeError) as exc:
        raise PaymentError(f"Unexpected YooKassa payment payload: {exc!r}") from exc
```

`int(order_id)` стоит не случайно: насколько я помню, ЮKassa возвращает значения `metadata` строками.

## `deps.py`

```python
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

import httpx
from fastapi import FastAPI, Request

from app.config import settings
from .yookassa import API_BASE, YooKassaClient


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    async with httpx.AsyncClient(
        base_url=API_BASE,
        auth=(settings.SHOP_ID, settings.SECRET_KEY),
        timeout=10,
    ) as http:
        app.state.yookassa = YooKassaClient(http)
        yield


def get_yookassa(request: Request) -> YooKassaClient:
    return request.app.state.yookassa
```

Подключается через `FastAPI(lifespan=lifespan)`. Если lifespan уже есть, вложите этот контекст в него.

## `routes.py`

```python
import uuid
from decimal import Decimal

from fastapi import APIRouter, Depends, HTTPException, Request
from pydantic import BaseModel, Field, HttpUrl

from .deps import get_yookassa
from .models import PaymentError
from .yookassa import YooKassaClient
from app import orders  # ваш слой работы с заказами

router = APIRouter()


class CreatePaymentIn(BaseModel):
    order_id: int
    amount: Decimal = Field(gt=0, decimal_places=2)
    return_url: HttpUrl


class CreatePaymentOut(BaseModel):
    payment_id: str
    confirmation_url: str


@router.post("/payments", response_model=CreatePaymentOut)
async def create_payment(
    body: CreatePaymentIn, client: YooKassaClient = Depends(get_yookassa)
) -> CreatePaymentOut:
    # Ключ на попытку оплаты. Сохраните его вместе с попыткой,
    # чтобы ретрай этой же попытки шёл с тем же ключом.
    attempt_key = str(uuid.uuid4())
    try:
        payment = await client.create_payment(
            order_id=body.order_id,
            amount=body.amount,
            return_url=str(body.return_url),
            idempotence_key=attempt_key,
        )
    except PaymentError as exc:
        raise HTTPException(status_code=502, detail="Payment provider unavailable") from exc

    await orders.attach_payment(body.order_id, payment.id)
    if payment.confirmation_url is None:
        raise HTTPException(status_code=502, detail="Provider returned no confirmation URL")
    return CreatePaymentOut(payment_id=payment.id, confirmation_url=payment.confirmation_url)


@router.post("/webhooks/yookassa")
async def yookassa_webhook(
    request: Request, client: YooKassaClient = Depends(get_yookassa)
) -> dict:
    event = await request.json()
    payment_id = (event.get("object") or {}).get("id")
    if not payment_id:
        raise HTTPException(status_code=400, detail="No payment id in notification")

    # Телу уведомления не доверяем: берём актуальный статус из API.
    payment = await client.get_payment(payment_id)
    await orders.apply_payment_status(payment)  # должно быть идемпотентным: webhook-и приходят повторно
    return {}
```

Если `get_payment` упадёт с `PaymentError`, роут вернёт 5xx, и ЮKassa повторит уведомление. Здесь это нужное поведение.

Одно замечание: если в проекте реальные суммы и так приходят из заказа, а не от клиента, уберите `amount` из `CreatePaymentIn` и берите её из БД. Сумма от клиента в эндпоинте оплаты — дыра.

## `tests/test_yookassa.py`

```python
import json
from decimal import Decimal

import httpx
import pytest

from app.payments.models import PaymentError, PaymentStatus
from app.payments.yookassa import API_BASE, YooKassaClient


def make_client(handler) -> YooKassaClient:
    return YooKassaClient(httpx.AsyncClient(base_url=API_BASE, transport=httpx.MockTransport(handler)))


@pytest.mark.anyio
async def test_create_payment_sends_decimal_amount_and_key():
    seen = {}

    def handler(request: httpx.Request) -> httpx.Response:
        seen["body"] = json.loads(request.content)
        seen["key"] = request.headers["Idempotence-Key"]
        return httpx.Response(200, json={
            "id": "pay_1", "status": "pending",
            "amount": {"value": "100.10", "currency": "RUB"},
            "metadata": {"order_id": "42"},
            "confirmation": {"confirmation_url": "https://pay.example/1"},
        })

    payment = await make_client(handler).create_payment(
        order_id=42, amount=Decimal("100.1"), return_url="https://shop/ret", idempotence_key="k1"
    )

    assert seen["body"]["amount"]["value"] == "100.10"
    assert seen["key"] == "k1"
    assert payment.status is PaymentStatus.PENDING
    assert payment.order_id == 42


@pytest.mark.anyio
async def test_http_error_is_wrapped():
    client = make_client(lambda r: httpx.Response(400, json={"code": "invalid_request"}))
    with pytest.raises(PaymentError, match="400"):
        await client.get_payment("pay_1")
```

(`@pytest.mark.anyio` требует плагин anyio, он ставится вместе с httpx. Если у вас `pytest-asyncio`, замените на `@pytest.mark.asyncio`.)

## Как это расширяется, когда Stripe действительно понадобится

- Роуты уже зависят от клиента через `Depends(get_yookassa)`, а не от глобальной функции. Точка замены одна.
- При появлении второго провайдера нужно выделить `typing.Protocol` из **реальных** методов двух клиентов, а не из догадок. Это полдня работы. Выбор провайдера тогда, скорее всего, будет не через env, а по заказу, валюте или стране. Ещё одна причина не фиксировать это решение сейчас.
- Фабрика с реестром через декоратор, скорее всего, не понадобится и тогда: для 2–4 провайдеров хватит обычного `dict[str, Provider]`, собранного в lifespan.

Тимлиду можно так и сформулировать: «сделал Decimal, общий клиент, типизированные ошибки, идемпотентность на попытку, проверяемые webhook-и и тесты; точка расширения одна — dependency; интерфейс выделим из двух реальных API, когда появится второй». Если он всё же настаивает на полной иерархии сейчас, могу накидать и её. Но я бы сначала обсудил аргумент про неверную абстракцию.
