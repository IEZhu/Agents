Нет, не хватит. Судя по логам, дело в первую очередь не в модели, а в цикле. Из того, что вы описали, видны три отдельных дефекта. Переход на Opus не исправит ни один из них, а полная история попыток в промпте ещё и сделает каждую ночь заметно дороже.

## Что на самом деле сломалось

| Симптом | Причина | Поможет ли Opus |
|---|---|---|
| $63 и ~380 итераций | `while True` без лимита итераций, бюджета и проверки на прогресс | Нет. Цикл будет крутиться так же, только каждый оборот обойдётся дороже |
| Три часа один и тот же патч к `test_invoice_rounding` | Нет детектора повторов и нет лимита попыток на один тест. Агент не умеет сдаться | Частично. Модель может предложить другой патч, но если тест упирается в неоднозначную спецификацию, она будет перебирать варианты до утра |
| 9 уже починенных тестов снова падают | Патч принимается без проверки на регрессии. Критерий только `returncode == 0` в конце, промежуточные состояния никто не сравнивает | Нет. Это ошибка в логике приёмки, а не в качестве патчей |

Про `Decimal('10.01') != Decimal('10.00')`: это типичная ошибка округления. Причина может быть в режиме округления (`ROUND_HALF_UP` против `ROUND_HALF_EVEN`), в том, что округляется построчно, а что от итоговой суммы, или в том, что где-то `Decimal` строится из `float`. Бывает, что правильный ответ зависит от бизнес-правила, которого нет ни в коде, ни в тесте. Тогда ни одна модель надёжно его не угадает, и такой тест нужно отдавать человеку, а не крутить на нём цикл. Предлагаю самому посмотреть этот тест: скорее всего, именно такой случай.

## Почему «вся история попыток в промпт» — плохая идея

- **Стоимость растёт квадратично.** На итерации *n* вы отправляете *n* предыдущих попыток, поэтому сумма токенов за ночь растёт примерно как n². Сейчас выходит около $0.17 за итерацию ($63 / 380). С Opus и растущим контекстом умножайте с запасом. Opus дороже Sonnet за токен в разы, точное соотношение смотрите в текущем прайсе Anthropic, я его здесь не проверял.
- **Длинный контекст не гарантирует, что модель не повторится.** Сырые диффы и логи размывают внимание модели. Лучше передавать сжатую выжимку.
- **Повторы надо ловить кодом, а не просить модель их избегать.** Хеш нормализованного диффа — дешёвая и детерминированная проверка.

Чтобы модель не повторялась, отдавайте ей короткую сводку только по текущему тесту, например: «Попытка 1: поменял режим округления на HALF_UP в `calc_total`, результат тот же 10.01. Попытка 2: …». Хватит 3–5 строк, а не всей истории.

## Как сделать цикл безопасным для ночного запуска

Главные правила:

1. **Жёсткие лимиты:** максимум итераций, бюджет в долларах (считайте по `usage` из ответа API) и таймаут на каждый прогон pytest.
2. **Приёмка патча по множеству тестов, а не по returncode.** Патч принимается, только если множество падающих тестов строго уменьшилось и ни один ранее зелёный тест не покраснел. Иначе откатываем.
3. **Git как чекпоинт.** Каждый принятый патч — отдельный коммит в отдельной ветке. Отклонённый откатывается через `git checkout -- . && git clean -fd`.
4. **Лимит попыток на тест.** Например, после 3–4 неудачных попыток тест попадает в `given_up` и дальше идёт в отчёт для человека.
5. **Детектор повторов.** Тот же хеш диффа для того же теста означает, что патч не применяется, а попытка засчитывается.
6. **Запрет на правку тестов.** Патч, который трогает `tests/`, `conftest.py` или конфиг pytest, отклоняется. Без этого ночной агент рано или поздно «починит» тест, поменяв ожидаемое значение на `10.01`.
7. **Остановка без прогресса.** Если за K итераций подряд ничего не принято, выходим.

Скелет:

```python
MAX_ITERS = 40
MAX_USD = 8.0
MAX_ATTEMPTS_PER_TEST = 4
NO_PROGRESS_LIMIT = 6
PROTECTED = ("tests/", "conftest.py", "pytest.ini", "pyproject.toml")

failing = run_pytest()                      # set of nodeids, parse --junitxml
attempts, seen, notes = defaultdict(int), defaultdict(set), defaultdict(list)
given_up, spent, stale = set(), 0.0, 0

for it in range(MAX_ITERS):
    candidates = sorted(failing - given_up)
    if not candidates or spent >= MAX_USD or stale >= NO_PROGRESS_LIMIT:
        break
    target = candidates[0]

    patch, cost = ask_model(target, failure_output(target), notes[target][-5:])
    spent += cost
    attempts[target] += 1

    sig = hash(normalize_diff(patch))
    if sig in seen[target] or touches(patch, PROTECTED) or not git_apply_check(patch):
        notes[target].append("rejected: duplicate/protected/invalid")
    else:
        seen[target].add(sig)
        git_apply(patch)
        new_failing = run_pytest(timeout=600)
        if new_failing < failing:           # strict subset: progress, no regressions
            git_commit(f"fix {target}")
            failing, stale = new_failing, 0
            continue
        git_revert_worktree()
        notes[target].append(summarize(patch, new_failing - failing, failure_output(target)))

    stale += 1
    if attempts[target] >= MAX_ATTEMPTS_PER_TEST:
        given_up.add(target)

write_report(failing, given_up, notes, spent)   # что починено, что сдано человеку и почему
```

Детали, которые легко упустить:

- **Итерация на одном тесте, приёмка на полном прогоне.** Для быстрого цикла «патч, проверка» можно гонять только `pytest path::test`, но решение о коммите принимать только по полному прогону, иначе регрессии вернутся.
- **Флаки-тесты.** Если какие-то из 9 «сломанных обратно» тестов на самом деле нестабильны (проверьте, перезапустив их на чистом коммите), условие строгого подмножества будет отклонять хорошие патчи. Такие тесты исключите из критерия или перезапускайте их повторно перед решением.
- **Песочница.** Для запуска без присмотра: отдельная ветка или worktree, без `git push`, без сетевых секретов в окружении. Код, который пишет модель, выполняется через pytest, и это обычный запуск непроверенного кода.

## Когда имеет смысл Opus

Как **эскалацию**, а не как замену. Sonnet делает первые 2 попытки на тест, а Opus подключается на 3-й и 4-й, если Sonnet не справился. Так вы платите за дорогую модель только на трудных случаях. Проверять стоит на данных: на ваших 14 тестах сравните долю починенных и стоимость на один починенный тест для «только Sonnet», «только Opus» и эскалации. Заранее я не возьмусь предсказать, какой вариант выиграет.

**Итог:** запускать на ночь без присмотра можно, но только после лимитов, отката при регрессиях и лимита попыток на тест. С таким циклом худший сценарий ночи — «потратил $8, починил 5 тестов, про 3 честно написал, что не смог», а не «$63 и сломал то, что было починено».
