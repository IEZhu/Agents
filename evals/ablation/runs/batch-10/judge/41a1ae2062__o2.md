def shipping_cost(weight_kg: float, region: str, is_member: bool, order_total: int) -> int:

            return 0
        elif weight_kg > 10:

    if region == "msk":
        return 200 if weight_kg <= 5 else 350

        if weight_kg > 5:

        return base

## Дыры в логике

### 1. Главная: заказ ≥ 5000 не из Москвы и без клуба — платит не 300 (баг)
По правилу таким клиентам положен фикс 300 ₽. В коде же 300 возвращается только при `weight_kg > 10`. При весе ≤ 10 кг выполнение уходит в обычный тариф, и клиент с крупным заказом платит **400–650 ₽**, то есть больше фикса. Кейс 3 это как раз показывает: 650 вместо 300. Похоже, `elif weight_kg > 10` остался от какого-то старого правила. Исправление:

```python
FREE_SHIPPING_THRESHOLD = 5000
FLAT_RATE_LARGE_ORDER = 300

if order_total >= FREE_SHIPPING_THRESHOLD:
    if region == "msk" or is_member:
        return 0
    return FLAT_RATE_LARGE_ORDER
```

После фикса кейс 3 должен давать **300**, остальные пять кейсов не меняются.

### 2. Нет валидации входа
- `weight_kg <= 0` или отрицательный `order_total` сейчас молча дают какую-то цену.
- `weight_kg = float("nan")`: все сравнения с NaN дают `False`, и регион получит 400 без надбавки.
- `weight_kg = float("inf")`: `math.ceil(inf)` бросит `OverflowError`.

Лучше проверять вход на границе функции и явно бросать `ValueError`, а для NaN/inf использовать `math.isfinite`.

### 3. Регион как свободная строка
`"MSK"`, `"msk "`, `"Moscow"` не равны `"msk"` и уйдут по региональному тарифу. Стоит сделать `Enum` региона или хотя бы нормализовать строку (`strip().lower()`) там, где данные входят в систему.

### 4. Float-вес и `ceil`
Если вес получается суммированием позиций во float, возможны значения вроде `7.000000000000001`. Тогда `ceil(2.000000000000001) = 3`, и клиент переплачивает 50 ₽ за несуществующий килограмм. Надёжнее хранить вес в граммах (`int`) или в `Decimal`. Если это пока не вариант, можно округлять вес до разумной точности перед `ceil`.

### 5. Вопросы к бизнесу (это не баги, но лучше уточнить)
- В Москве при заказе < 5000 скидка участника клуба не применяется, а в регионах применяется (−50%). Так задумано?
- В Москве тариф свыше 5 кг фиксированный (350) и не зависит от веса: 6 кг и 60 кг стоят одинаково. Так задумано?
- `order_total: int` — это рубли или копейки? Если копейки, порог должен быть `500_000`. Стоит отразить в имени параметра или в типе.

## Дыры в логике

### 1. Главная: фикс 300 ₽ срабатывает только при весе > 10 кг (критично)

По правилу при заказе от 5000 ₽ «остальным — фикс 300 ₽». В коде `return 300` стоит только в ветке `elif weight_kg > 10`. Если заказ не из Москвы, покупатель не в клубе и вес ≤ 10 кг, выполнение проваливается в обычный тариф. В итоге выходит 400–650 ₽, то есть больше, чем 300.

Получается абсурд: клиент с заказом на 6000 ₽ и посылкой 10 кг платит 650 ₽, а с посылкой 12 кг платит 300 ₽. Условие по весу, судя по всему, осталось от старой версии или было добавлено по ошибке. Исправление:

```python
FREE_SHIPPING_THRESHOLD = 5000
FLAT_RATE_ABOVE_THRESHOLD = 300

if order_total >= FREE_SHIPPING_THRESHOLD:
    if region == "msk" or is_member:
        return 0
    return FLAT_RATE_ABOVE_THRESHOLD
```

После исправления ожидание для №3 меняется на **300**. Этот кейс стоит оставить как регрессионный тест. Если условие про вес > 10 кг всё-таки задумано, его нужно внести в спецификацию, потому что в описанном правиле его нет.

### 2. Нет валидации входа (высокий приоритет)
- `region` сравнивается как точная строка. Значения `"MSK"`, `"Msk"` или `" msk"` молча получат тариф регионов. Лучше нормализовать строку (`region.strip().lower()`) или перейти на `Enum`.
- Вес ≤ 0 или отрицательный `order_total` сейчас дают осмысленные на вид цены. Лучше бросать `ValueError` на границе.

### 3. Непоследовательная скидка для участников клуба (уточнить у бизнеса)
В регионах участник клуба получает скидку 50%, а в Москве ветка `msk` вообще не смотрит на `is_member`: участник платит те же 200/350 ₽. Возможно, так и задумано, но выглядит как пропуск.

### 4. Москва без надбавки за вес (уточнить)
По Москве посылка 6 кг и посылка 100 кг стоят одинаково, 350 ₽. В регионах действует надбавка 50 ₽ за каждый начатый килограмм сверх 5. Если так задумано, это стоит явно записать.

### 5. Мелочи
- Магические числа (5000, 200, 350, 400, 50, 5, 10) лучше вынести в именованные константы или конфиг тарифов, чтобы менять цены без правки логики.
- `ceil` над разностью float может на граничных весах вроде `5.0000000001` добавить лишние 50 ₽. Для реальных данных с весами до граммов это обычно не проблема, но если вес приходит после арифметики, лучше хранить его в граммах (`int`).
- Округление `// 2` сейчас безопасно: база всегда равна 400 + 50k, и такое число делится на 2 без остатка. Если тарифы поменяются, это может сломаться незаметно.
