	Запрос = Новый Запрос;

	"ВЫБРАТЬ

	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Номенклатура = &Номенклатура И Склад = &Склад) КАК ТоварыНаСкладахОстатки";

В регистре ТоварыНаСкладах есть измерение ХарактеристикаНоменклатуры. Нужно, чтобы функция учитывала характеристику, если её передали, а если не передали — возвращала остаток по номенклатуре и складу, как раньше. Перепиши функцию.

## Rubric (what a strong answer does)
1. Adds an optional characteristic parameter and filters by ХарактеристикаНоменклатуры only when it is passed.
2. When no characteristic is passed, still returns the total over all characteristics: the filter stays in the virtual-table parameters, or СУММА is used if ХарактеристикаНоменклатуры appears in the outer query; never only the first characteristic's row.
3. Keeps the existing Russian identifiers (ПолучитьОстатокТовара, ТоварыНаСкладах, Номенклатура, Склад) exactly and writes valid 1C syntax.
4. Explains the change in Russian.

## Answer A
### Анализ

Характеристику добавляем необязательным параметром со значением по умолчанию `Неопределено`. Отбор по ней попадает в параметры виртуальной таблицы `Остатки` только тогда, когда её передали. Существующие вызовы `ПолучитьОстатокТовара(Номенклатура, Склад)` продолжат работать без изменений.

**В текущей функции есть ошибка, которую стоит исправить заодно.** Виртуальная таблица `Остатки` возвращает по строке на каждую комбинацию **всех** измерений регистра. Раз в регистре есть `ХарактеристикаНоменклатуры`, отбор только по номенклатуре и складу может вернуть несколько строк. `Выборка.Следующий()` берёт первую из них, то есть остаток одной случайной характеристики, а не общий остаток. Поэтому «как раньше» (без характеристики) нужно считать через `СУММА`. Иначе для товаров с характеристиками функция возвращает неверное число.

### Реализация

```bsl
// Возвращает остаток товара на складе.
// Если ХарактеристикаНоменклатуры не передана (Неопределено), возвращается
// суммарный остаток по всем характеристикам номенклатуры на складе.
Функция ПолучитьОстатокТовара(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено) Экспорт
	
	УсловиеОтбора = "Номенклатура = &Номенклатура
	|		И Склад = &Склад";
	
	Если ХарактеристикаНоменклатуры <> Неопределено Тогда
		УсловиеОтбора = УсловиеОтбора + "
		|		И ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры";
	КонецЕсли;
	
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ
	|	ЕСТЬNULL(СУММА(ТоварыНаСкладахОстатки.КоличествоОстаток), 0) КАК Остаток
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(
	|			,
	|			#УсловиеОтбора) КАК ТоварыНаСкладахОстатки";
	
	Запрос.Текст = СтрЗаменить(Запрос.Текст, "#УсловиеОтбора", УсловиеОтбора);
	
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	Запрос.УстановитьПараметр("ХарактеристикаНоменклатуры", ХарактеристикаНоменклатуры);
	
	Выборка = Запрос.Выполнить().Выбрать();
	
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
	
КонецФункции
```

Ключевые решения:

- **Условие собирается в тексте запроса, а не через `ИЛИ`.** Вариант `(&ОтборПоХарактеристике = ЛОЖЬ ИЛИ ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры)` тоже работает, но с `ИЛИ` в параметрах виртуальной таблицы СУБД хуже использует индексы. Условие без лишних веток проще и быстрее.
- **`СУММА` вместо первой строки выборки.** Запрос с агрегатом и без группировки всегда возвращает ровно одну строку. Если остатков нет, `СУММА` даёт `NULL`, и его закрывает `ЕСТЬNULL`.
- **Лишний параметр в запросе — не ошибка.** Если характеристики нет в условии, `УстановитьПараметр("ХарактеристикаНоменклатуры", ...)` ни на что не влияет, а код остаётся линейным.

**Нужно ваше решение: что значит «не передали».** Сейчас отбор не ставится только при `Неопределено`. Пустая ссылка (`Справочники.ХарактеристикиНоменклатуры.ПустаяСсылка()`) считается переданным значением и отбирает остаток товаров *без* характеристики. Обычно так и нужно. Но если вызывающий код передаёт пустую ссылку в смысле «характеристика не важна», замените проверку так:

```bsl
Если ЗначениеЗаполнено(ХарактеристикаНоменклатуры) Тогда
```

Учтите, что тогда по товарам без характеристики отдельно запросить остаток не получится.

### Проверка

Запустить код я здесь не мог, поэтому проверьте в конфигураторе или в консоли запросов:

1. Товар без характеристик: результат совпадает со старой функцией.
2. Товар с несколькими характеристиками, вызов без характеристики: результат равен сумме по всем характеристикам. Старая функция здесь возвращала остаток одной из них.
3. Тот же товар с конкретной характеристикой: результат равен остатку только этой характеристики.

5. Если в регистре есть другие измерения (например, серия или партия), п. 2 и 3 суммируют и по ним. Скорее всего, это и есть ожидаемое поведение.

Сложность для вызывающего кода не меняется: один запрос к виртуальной таблице остатков.

## Answer B
### Анализ

Характеристику добавляю как **необязательный третий параметр** со значением по умолчанию `Неопределено`. Существующие вызовы `ПолучитьОстатокТовара(Номенклатура, Склад)` продолжат работать без изменений. Условие по характеристике попадает в параметры виртуальной таблицы только тогда, когда характеристику передали.

Важно: «как раньше» работало неправильно. Виртуальная таблица `Остатки` группирует данные по **всем** измерениям регистра. Раз в регистре есть `ХарактеристикаНоменклатуры`, исходный запрос возвращает по строке на каждую характеристику, а `Выборка.Следующий()` берёт только первую. Если у товара на складе несколько характеристик, функция возвращала остаток одной случайной из них, а не общий. В новой версии остатки суммируются через `СУММА`.

### Реализация

```bsl
// Возвращает остаток товара на складе.
// Если ХарактеристикаНоменклатуры не передана (Неопределено) — суммарный остаток
// по всем характеристикам номенклатуры на складе.
Функция ПолучитьОстатокТовара(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено) Экспорт
	
	УсловиеОтбора = "Номенклатура = &Номенклатура И Склад = &Склад";
	Если ХарактеристикаНоменклатуры <> Неопределено Тогда
		УсловиеОтбора = УсловиеОтбора + " И ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры";
	КонецЕсли;
	
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ
	|	ЕСТЬNULL(СУММА(ТоварыНаСкладахОстатки.КоличествоОстаток), 0) КАК Остаток
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, &УсловиеОтбора) КАК ТоварыНаСкладахОстатки";
	Запрос.Текст = СтрЗаменить(Запрос.Текст, "&УсловиеОтбора", УсловиеОтбора);
	
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	Запрос.УстановитьПараметр("ХарактеристикаНоменклатуры", ХарактеристикаНоменклатуры);
	
	Выборка = Запрос.Выполнить().Выбрать();
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
	
КонецФункции
```

Пояснения к решениям:

- **Сборка текста условия, а не `ИЛИ` в запросе.** Можно написать одно статическое условие вида `(НЕ &ОтборПоХарактеристике ИЛИ ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры)`, но `ИЛИ` в параметрах виртуальной таблицы обычно мешает СУБД использовать индекс таблицы итогов. Собранное условие проще и предсказуемее по плану запроса. В условие подставляется только фиксированный текст, а значения по-прежнему передаются через параметры, поэтому инъекции здесь нет.
- **`СУММА` без `СГРУППИРОВАТЬ ПО`** всегда даёт ровно одну строку (`NULL`, если данных нет, отсюда и `ЕСТЬNULL`). Проверку `Выборка.Следующий()` я оставил как защиту.
- **Неопределено и пустая ссылка — это разные случаи.** «Не передали» означает `Неопределено`. Пустая ссылка характеристики считается переданным значением и даёт остаток по записям *без* характеристики. Если в вашей конфигурации пустая ссылка тоже должна означать «по всем характеристикам», замените условие на `Если ЗначениеЗаполнено(ХарактеристикаНоменклатуры) Тогда`. Но тогда остаток именно «без характеристики» этой функцией получить будет нельзя.

2. Тот же товар с конкретной характеристикой: остаток только по ней.
