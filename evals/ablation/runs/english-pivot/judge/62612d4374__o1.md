Нужна регулярка (Python, re) для проверки российского мобильного номера. Должны проходить варианты вроде +7 912 345-67-89, 8 (912) 345-67-89, 89123456789 и +79123456789: пробелы, скобки и дефисы необязательны. Номер после +7 или 8 должен начинаться с 9. Дай регулярку и несколько проверок.

3. It is anchored to the whole string (re.fullmatch or ^...\Z) and comes with a few test cases.

## Answer A
Регулярка для `re.fullmatch` (поэтому якоря `^`/`$` не нужны):

```python
import re

RU_MOBILE_RE = re.compile(
    r"""
    (?:\+7|8)            # код страны: +7 или 8
    [ -]?                # необязательный разделитель
    (?:\(9\d{2}\)|9\d{2})  # код оператора 9XX, либо целиком в скобках, либо без них
    [ -]?
    \d{3}
    [ -]?
    \d{2}
    [ -]?
    \d{2}
    """,
    re.VERBOSE,
)


def is_ru_mobile(phone: str) -> bool:
    return RU_MOBILE_RE.fullmatch(phone) is not None
```

Однострочный вариант:

```python
r"(?:\+7|8)[ -]?(?:\(9\d{2}\)|9\d{2})[ -]?\d{3}[ -]?\d{2}[ -]?\d{2}"
```

Почему именно так:

- Скобки сделаны альтернативой `\(9\d{2}\)|9\d{2}`, а не через `\(?9\d{2}\)?`. Иначе прошли бы номера с одной скобкой, например `8 (912 345-67-89`.
- `fullmatch` вместо `match` с `$`: в Python `$` совпадает и перед завершающим `\n`, так что строка `"89123456789\n"` прошла бы проверку.
- Разделитель — только пробел или дефис, и не больше одного между группами. Если нужно разрешить табы или двойные пробелы, замените `[ -]?` на `[\s-]*`.

Проверки:

```python
valid = [
    "+7 912 345-67-89",
    "8 (912) 345-67-89",
    "89123456789",
    "+79123456789",
    "+7(912)3456789",
    "8-912-345-67-89",
]

invalid = [
    "+7 812 345-67-89",    # код не начинается с 9
    "8 (912 345-67-89",    # незакрытая скобка
    "8 912) 345-67-89",    # лишняя закрывающая скобка
    "7 912 345-67-89",     # 7 без плюса
    "+8 912 345-67-89",    # неверный код страны
    "8912345678",          # 10 цифр
    "891234567890",        # 12 цифр
    "89123456789\n",       # завершающий перевод строки
    "8  912 345 67 89",    # двойной пробел
    "",
]

for p in valid:
    assert is_ru_mobile(p), f"должен пройти: {p!r}"
for p in invalid:
    assert not is_ru_mobile(p), f"не должен пройти: {p!r}"
print("ok")
```

## Answer B
Вот регулярка. Её стоит использовать с `fullmatch`, а не с `match` + `$`, потому что `$` пропускает строку с завершающим `\n`.

```python
import re

RU_MOBILE_RE = re.compile(
    r"""
    (?:\+7|8)              # код страны: +7 или 8
    [ -]?                  # необязательный разделитель
    (?:\(9\d{2}\)|9\d{2})  # код оператора 9XX: в скобках или без, скобки только парные
    [ -]?
    \d{3}
    [ -]?
    \d{2}
    [ -]?
    \d{2}
    """,
    re.VERBOSE | re.ASCII,
)


def is_ru_mobile(phone: str) -> bool:
    return RU_MOBILE_RE.fullmatch(phone) is not None
```

Та же регулярка в одну строку:

```python
r"(?:\+7|8)[ -]?(?:\(9\d{2}\)|9\d{2})[ -]?\d{3}[ -]?\d{2}[ -]?\d{2}"
```

Почему она устроена именно так:
- Код оператора задан альтернативой `\(9\d{2}\)|9\d{2}`, а не `\(?9\d{2}\)?`. Иначе прошла бы строка с непарной скобкой, например `8 (912 345-67-89`.
- Разделитель `[ -]?` разрешает между группами не больше одного пробела или дефиса. Двойные пробелы, табы и переводы строк не проходят. Если нужно разрешить любые пробельные символы, замените его на `[\s-]?`.
- Флаг `re.ASCII` нужен потому, что без него `\d` в Python совпадает и с не-ASCII цифрами, например арабско-индийскими `٩`.
- В режиме `re.VERBOSE` пробел внутри символьного класса `[ -]` сохраняется, так что многострочная и однострочная версии равнозначны.

Проверки:

```python
valid = [
    "+7 912 345-67-89",
    "8 (912) 345-67-89",
    "89123456789",
    "+79123456789",
    "+7(912)3456789",
    "8-912-345-67-89",
    "+7 (999) 000 00 00",
]

invalid = [
    "+7 812 345-67-89",    # код не начинается с 9 (городской номер)
    "7 912 345-67-89",     # нет плюса перед 7
    "+8 912 345-67-89",    # неверный код страны
    "8 (912 345-67-89",    # непарная скобка
    "8 912) 345-67-89",    # непарная скобка
    "8912345678",          # 10 цифр
    "891234567890",        # 12 цифр
    "+7  912 345-67-89",   # двойной пробел
    "89123456789\n",       # завершающий перевод строки
    "8 ٩12 345-67-89",     # не-ASCII цифра
    "",
]

for s in valid:
    assert is_ru_mobile(s), f"должен пройти: {s!r}"
for s in invalid:
    assert not is_ru_mobile(s), f"не должен пройти: {s!r}"
print("OK")
```

Если номер потом нужно хранить или сравнивать, проще сначала проверить его этой регуляркой, а затем нормализовать: `"+7" + re.sub(r"\D", "", s)[-10:]`.

Сложность проверки линейная по длине строки. Квантификаторы фиксированной длины, поэтому катастрофического backtracking здесь нет.
