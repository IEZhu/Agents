### Анализ

Характеристику добавляю как **необязательный третий параметр** со значением по умолчанию `Неопределено`. Существующие вызовы `ПолучитьОстатокТовара(Номенклатура, Склад)` продолжат работать без изменений. Условие по характеристике попадает в параметры виртуальной таблицы только тогда, когда характеристику передали.

Важно: «как раньше» работало неправильно. Виртуальная таблица `Остатки` группирует данные по **всем** измерениям регистра. Раз в регистре есть `ХарактеристикаНоменклатуры`, исходный запрос возвращает по строке на каждую характеристику, а `Выборка.Следующий()` берёт только первую. Если у товара на складе несколько характеристик, функция возвращала остаток одной случайной из них, а не общий. В новой версии остатки суммируются через `СУММА`.

### Реализация

```bsl
// Возвращает остаток товара на складе.
// Если ХарактеристикаНоменклатуры не передана (Неопределено) — суммарный остаток
// по всем характеристикам номенклатуры на складе.
Функция ПолучитьОстатокТовара(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено) Экспорт
	
	УсловиеОтбора = "Номенклатура = &Номенклатура И Склад = &Склад";
	Если ХарактеристикаНоменклатуры <> Неопределено Тогда
		УсловиеОтбора = УсловиеОтбора + " И ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры";
	КонецЕсли;
	
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ
	|	ЕСТЬNULL(СУММА(ТоварыНаСкладахОстатки.КоличествоОстаток), 0) КАК Остаток
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, &УсловиеОтбора) КАК ТоварыНаСкладахОстатки";
	Запрос.Текст = СтрЗаменить(Запрос.Текст, "&УсловиеОтбора", УсловиеОтбора);
	
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	Запрос.УстановитьПараметр("ХарактеристикаНоменклатуры", ХарактеристикаНоменклатуры);
	
	Выборка = Запрос.Выполнить().Выбрать();
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
	
КонецФункции
```

Пояснения к решениям:

- **Сборка текста условия, а не `ИЛИ` в запросе.** Можно написать одно статическое условие вида `(НЕ &ОтборПоХарактеристике ИЛИ ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры)`, но `ИЛИ` в параметрах виртуальной таблицы обычно мешает СУБД использовать индекс таблицы итогов. Собранное условие проще и предсказуемее по плану запроса. В условие подставляется только фиксированный текст, а значения по-прежнему передаются через параметры, поэтому инъекции здесь нет.
- **`СУММА` без `СГРУППИРОВАТЬ ПО`** всегда даёт ровно одну строку (`NULL`, если данных нет, отсюда и `ЕСТЬNULL`). Проверку `Выборка.Следующий()` я оставил как защиту.
- **Неопределено и пустая ссылка — это разные случаи.** «Не передали» означает `Неопределено`. Пустая ссылка характеристики считается переданным значением и даёт остаток по записям *без* характеристики. Если в вашей конфигурации пустая ссылка тоже должна означать «по всем характеристикам», замените условие на `Если ЗначениеЗаполнено(ХарактеристикаНоменклатуры) Тогда`. Но тогда остаток именно «без характеристики» этой функцией получить будет нельзя.

### Проверка

Запустить код в базе я не могу, поэтому проверьте на копии вручную:

1. Товар с двумя и более характеристиками на складе, вызов без характеристики: должна получиться сумма по всем характеристикам. Старая версия здесь возвращала остаток только одной из них.
2. Тот же товар с конкретной характеристикой: остаток только по ней.
3. Товар без движений: `0` в обоих режимах.
4. Найдите вызовы через глобальный поиск по `ПолучитьОстатокТовара`. Если где-то код полагался на старое поведение «первая строка», результат там изменится. Скорее всего, это и есть исправление, но лучше его осознанно подтвердить.

Сложность: один запрос к таблице итогов регистра, производительность такая же, как у исходной версии.
