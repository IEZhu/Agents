Значение по умолчанию `bucket=[]` вычисляется **один раз**, когда интерпретатор выполняет `def`, а не при каждом вызове. Получается один список, который хранится в объекте функции (в `add_item.__defaults__`), и все вызовы без `bucket` используют именно его. Список изменяемый, а `append` меняет его на месте, поэтому элементы копятся от вызова к вызову:

```python
add_item(1)               # [1]
add_item(2)               # [1, 2] — тот же самый список
print(add_item.__defaults__)  # ([1, 2],)
```

Это не баг Python, а задокументированное поведение: значения по умолчанию вычисляются один раз, при определении функции.

### Как правильно

Стандартная идиома — использовать `None` как маркер «аргумент не передан» и создавать новый список уже внутри функции:

```python
def add_item(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

```python
add_item(1)          # [1]
add_item(2)          # [2]
my = [10]
add_item(3, my)      # [10, 3] — переданный список по-прежнему изменяется
```

С аннотациями типов:

```python
def add_item(item: int, bucket: list[int] | None = None) -> list[int]:
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

Пара замечаний:

- Пишите именно `if bucket is None`, а не `bucket = bucket or []`. Вариант с `or` молча заменит переданный пустой список на новый, и изменения не попадут в список вызывающего кода.
- Та же ловушка есть с любым изменяемым значением по умолчанию: `{}`, `set()`, экземплярами классов. Неизменяемые значения (`0`, `""`, `None`, кортежи) безопасны.
- Если функция не должна менять переданный список, верните новый вместо `append`: `return [*(bucket or []), item]`.
- Линтеры это ловят: в pylint это `dangerous-default-value` (W0102), в Ruff/flake8-bugbear — `B006` (коды привожу по памяти, сверьтесь с документацией вашего линтера).
