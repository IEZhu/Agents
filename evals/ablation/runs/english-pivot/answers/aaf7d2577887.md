Вот регулярка. Её стоит использовать с `fullmatch`, а не с `match` + `$`, потому что `$` пропускает строку с завершающим `\n`.

```python
import re

RU_MOBILE_RE = re.compile(
    r"""
    (?:\+7|8)              # код страны: +7 или 8
    [ -]?                  # необязательный разделитель
    (?:\(9\d{2}\)|9\d{2})  # код оператора 9XX: в скобках или без, скобки только парные
    [ -]?
    \d{3}
    [ -]?
    \d{2}
    [ -]?
    \d{2}
    """,
    re.VERBOSE | re.ASCII,
)


def is_ru_mobile(phone: str) -> bool:
    return RU_MOBILE_RE.fullmatch(phone) is not None
```

Та же регулярка в одну строку:

```python
r"(?:\+7|8)[ -]?(?:\(9\d{2}\)|9\d{2})[ -]?\d{3}[ -]?\d{2}[ -]?\d{2}"
```

Почему она устроена именно так:
- Код оператора задан альтернативой `\(9\d{2}\)|9\d{2}`, а не `\(?9\d{2}\)?`. Иначе прошла бы строка с непарной скобкой, например `8 (912 345-67-89`.
- Разделитель `[ -]?` разрешает между группами не больше одного пробела или дефиса. Двойные пробелы, табы и переводы строк не проходят. Если нужно разрешить любые пробельные символы, замените его на `[\s-]?`.
- Флаг `re.ASCII` нужен потому, что без него `\d` в Python совпадает и с не-ASCII цифрами, например арабско-индийскими `٩`.
- В режиме `re.VERBOSE` пробел внутри символьного класса `[ -]` сохраняется, так что многострочная и однострочная версии равнозначны.

Проверки:

```python
valid = [
    "+7 912 345-67-89",
    "8 (912) 345-67-89",
    "89123456789",
    "+79123456789",
    "+7(912)3456789",
    "8-912-345-67-89",
    "+7 (999) 000 00 00",
]

invalid = [
    "+7 812 345-67-89",    # код не начинается с 9 (городской номер)
    "7 912 345-67-89",     # нет плюса перед 7
    "+8 912 345-67-89",    # неверный код страны
    "8 (912 345-67-89",    # непарная скобка
    "8 912) 345-67-89",    # непарная скобка
    "8912345678",          # 10 цифр
    "891234567890",        # 12 цифр
    "+7  912 345-67-89",   # двойной пробел
    "89123456789\n",       # завершающий перевод строки
    "8 ٩12 345-67-89",     # не-ASCII цифра
    "",
]

for s in valid:
    assert is_ru_mobile(s), f"должен пройти: {s!r}"
for s in invalid:
    assert not is_ru_mobile(s), f"не должен пройти: {s!r}"
print("OK")
```

Если номер потом нужно хранить или сравнивать, проще сначала проверить его этой регуляркой, а затем нормализовать: `"+7" + re.sub(r"\D", "", s)[-10:]`.

Сложность проверки линейная по длине строки. Квантификаторы фиксированной длины, поэтому катастрофического backtracking здесь нет.
