Значение по умолчанию `bucket=[]` вычисляется **один раз**, когда интерпретатор выполняет строку `def`, а не при каждом вызове. Поэтому все вызовы без аргумента `bucket` получают один и тот же объект списка. `append` изменяет этот объект на месте, и изменения сохраняются между вызовами.

Это видно по атрибуту функции, где хранятся значения по умолчанию:

```python
def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

add_item(1)
add_item(2)
print(add_item.__defaults__)  # ([1, 2],) — тот самый общий список
```

Есть и менее заметный побочный эффект: `a = add_item(1)` и `b = add_item(2)` указывают на один и тот же объект (`a is b` → `True`), так что изменение `a` меняет и `b`.

## Как правильно

Стандартная идиома: использовать `None` как маркер и создавать новый список внутри функции:

```python
def add_item(item, bucket: list | None = None) -> list:
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket

add_item(1)  # [1]
add_item(2)  # [2]
```

Пишите именно `if bucket is None`, а не `bucket = bucket or []`. Вариант с `or` подменит пустой список, который передал вызывающий код, новым списком, и вызывающая сторона не увидит добавленный элемент.

Если функция не должна изменять переданный список, лучше возвращать новый:

```python
def add_item(item, bucket: list | None = None) -> list:
    return [*(bucket or []), item]
```

## Общее правило

Не используйте изменяемые объекты (`[]`, `{}`, `set()`, экземпляры своих классов) как значения по умолчанию. Неизменяемые (`None`, числа, строки, кортежи) безопасны. Ту же ловушку для dataclass закрывает `field(default_factory=list)`. Линтеры её тоже ловят: в Ruff/flake8-bugbear это правило `B006`, в pylint — `dangerous-default-value` (коды правил привожу по памяти, сверьтесь с документацией вашего линтера).
