В регистре ТоварыНаСкладах есть измерение ХарактеристикаНоменклатуры. Нужно, чтобы функция учитывала характеристику, если её передали, а если не передали — возвращала остаток по номенклатуре и складу, как раньше. Перепиши функцию.

## Rubric (what a strong answer does)
1. Adds an optional characteristic parameter and filters by ХарактеристикаНоменклатуры only when it is passed.
2. When no characteristic is passed, still returns the total over all characteristics: the filter stays in the virtual-table parameters, or СУММА is used if ХарактеристикаНоменклатуры appears in the outer query; never only the first characteristic's row.
3. Keeps the existing Russian identifiers (ПолучитьОстатокТовара, ТоварыНаСкладах, Номенклатура, Склад) exactly and writes valid 1C syntax.
4. Explains the change in Russian.

## Answer A
### Analysis

В запросах к `Остатки()` регистра накопления измерения, которые **не** указаны в фильтре, автоматически агрегируются (суммируются). Поэтому при отсутствии характеристики достаточно просто не включать её в условие — регистр сам просуммирует по всем характеристикам. При наличии — добавляем фильтр.

### Implementation

```1c
Функция ПолучитьОстатокТовара(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено) Экспорт
	Запрос = Новый Запрос;
	Если ХарактеристикаНоменклатуры = Неопределено Тогда
		Запрос.Текст =
		"ВЫБРАТЬ
		|	ЕСТЬNULL(ТоварыНаСкладахОстатки.КоличествоОстаток, 0) КАК Остаток
		|ИЗ
		|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Номенклатура = &Номенклатура И Склад = &Склад) КАК ТоварыНаСкладахОстатки";
	Иначе
		Запрос.Текст =
		"ВЫБРАТЬ
		|	ЕСТЬNULL(ТоварыНаСкладахОстатки.КоличествоОстаток, 0) КАК Остаток
		|ИЗ
		|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Номенклатура = &Номенклатура И Склад = &Склад И ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры) КАК ТоварыНаСкладахОстатки";
		Запрос.УстановитьПараметр("ХарактеристикаНоменклатуры", ХарактеристикаНоменклатуры);
	КонецЕсли;
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	Выборка = Запрос.Выполнить().Выбрать();
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
КонецФункции
```

### Что изменилось

| Аспект | Было | Стало |
|--------|------|-------|
| Сигнатура | `(Номенклатура, Склад)` | `(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено)` |
| Фильтр по характеристике | отсутствует | добавляется только при передаче значения |
| Поведение без характеристики | — | регистр агрегирует по всем характеристикам (сумма) |
| Обратная совместимость | — | все существующие вызовы `ПолучитьОстатокТовара(Ном, Скл)` работают без изменений |

### Почему два текста запроса, а не динамическая сборка

В 1C стандартный и самый читаемый паттерн для опционального измерения — ветвление с готовыми текстами. Динамическая конкатенация (`"..." + Условие + "..."`) усложняет отладку (в отладчике не видно итоговый SQL) и легко приводит к синтаксическим ошибкам в запросе. Дублирование двух строк — приемлемая цена за прозрачность.

### Confidence

**HIGH** — стандартный паттерн работы с регистрами накопления в 1C: неисключённое измерение агрегируется автоматически, опциональный параметр с `Неопределено` — идиоматичный способ «не передано».


## Answer B
### Analysis

Ключевой момент: в 1С измерения, не указанные в срезе `Остатки(...)`, автоматически агрегируются (суммируются). Поэтому при отсутствии характеристики достаточно оставить срез как в оригинале — 1С сама просуммирует по всем характеристикам. При наличии — добавляем условие в срез.

### Implementation

```1c
Функция ПолучитьОстатокТовара(Номенклатура, Склад, Характеристика = Неопределено) Экспорт
	Запрос = Новый Запрос;
	
	Если Характеристика <> Неопределено Тогда
		Запрос.Текст =
		"ВЫБРАТЬ
		|	ЕСТЬNULL(ТоварыНаСкладахОстатки.КоличествоОстаток, 0) КАК Остаток
		|ИЗ
		|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Номенклатура = &Номенклатура И Склад = &Склад И ХарактеристикаНоменклатуры = &Характеристика) КАК ТоварыНаСкладахОстатки";
		Запрос.УстановитьПараметр("Характеристика", Характеристика);
	Иначе
		Запрос.Текст =
		"ВЫБРАТЬ
		|	ЕСТЬNULL(ТоварыНаСкладахОстатки.КоличествоОстаток, 0) КАК Остаток
		|ИЗ
		|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Номенклатура = &Номенклатура И Склад = &Склад) КАК ТоварыНаСкладахОстатки";
	КонецЕсли;
	
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	Выборка = Запрос.Выполнить().Выбрать();
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
КонецФункции
```

### Что изменилось

| | Было | Стало |
|---|---|---|
| Сигнатура | `(Номенклатура, Склад)` | `(Номенклатура, Склад, Характеристика = Неопределено)` |
| Срез при наличии характеристики | — | `Остатки(, Номенклатура = … И Склад = … И ХарактеристикаНоменклатуры = …)` |
| Срез без характеристики | `Остатки(, Номенклатура = … И Склад = …)` | без изменений |

Параметр `Характеристика` имеет значение по умолчанию `Неопределено`, поэтому все существующие вызовы `ПолучитьОстатокТовара(Товар, Склад)` продолжают работать без изменений.

### Verification

- **Обратная совместимость**: вызов с двумя аргументами идёт в ветку `Иначе` — запрос идентичен оригиналу.
- **Корректность агрегации**: при отсутствии характеристики в срезе 1С суммирует остатки по всем значениям измерения `ХарактеристикаНоменклатуры` для заданной пары (Номенклатура, Склад) — это штатное поведение среза регистра.
- **Пустой остаток**: `ЕСТЬNULL(…, 0)` + `?(Выборка.Следующий(), …, 0)` покрывают случай, когда записей нет.

### Confidence

**HIGH** — стандартный паттерн 1С для опциональных измерений в срезе; логика агрегации по незаданным измерениям задокументирована в справочнике по языку запросов.
