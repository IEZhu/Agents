Не понимаю, что происходит. Есть функция:

def add_item(item, bucket=[]):

## Answer A
### Analysis

Классическая ловушка Python: **mutable default argument**. Значение по умолчанию (`[]`) создаётся **один раз** при определении функции (в момент `def`), а не при каждом вызове. Все вызовы, где `bucket` не передан явно, делят **один и тот же** объект списка.

### Implementation

```python
# ❌ Плохо: один и тот же list живёт всю жизнь функции
def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

add_item(1)  # [1]
add_item(2)  # [1, 2]  ← тот же список, а не новый
```

Проверка «одна ли это ссылка»:

```python
def f(a, b=[]):
    return b

f(1) is f(2)  # True — один и тот же объект
```

**Правильный вариант** — `None` как маркер «не передано», новый список создаём внутри:

```python
def add_item(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket

add_item(1)  # [1]
add_item(2)  # [2]
```

Если нужно, чтобы вызов с явным `bucket` всё равно не мутировал аргумент:

```python
def add_item(item, bucket=None):
    bucket = list(bucket) if bucket is not None else []
    bucket.append(item)
    return bucket
```

### Verification

| Сценарий | `bucket=[]` | `bucket=None` |
|---|---|---|
| `add_item(1)` | `[1]` | `[1]` |
| `add_item(2)` | `[1, 2]` ← баг | `[2]` |
| `add_item(3, bucket=[10])` | `[10, 3]` | `[10, 3]` |

Правило общее: в Python **никогда** не используйте мутируемые объекты (`[]`, `{}`, `set()`) как значения по умолчанию. Всегда `None` + инициализация внутри.

### Confidence

**HIGH** — поведение определено спецификацией языка (CPython evaluates default values at function definition time); проверено мысленно на каждом вызове выше.


## Answer B
### Анализ

Классическая ловушка Python: **mutable default argument**. Значение по умолчанию `[]` создаётся **один раз** при определении функции, а не при каждом вызове. Все вызовы, где `bucket` не передан, мутируют один и тот же список.

### Почему так работает

```python
def add_item(item, bucket=[]):   # ← [] создаётся ОДИН раз, при def
    bucket.append(item)
    return bucket
```

Можно это «увидеть» напрямую:

```python
def f(a, b=[]):
    return b

print(f(1) is f(2))  # True — оба вызова получили ОДИН и тот же объект
```

Ваш случай:

```
add_item(1)  →  [ ]  + 1  →  [1]        # общий список стал [1]
add_item(2)  →  [1] + 2  →  [1, 2]      # тот же список, уже содержит 1
```

### Правильно

Заменить дефолт на `None` и создавать список внутри:

```python
def add_item(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

Теперь каждый вызов без явного `bucket` получает **свой** новый список:

```python
add_item(1)  # [1]
add_item(2)  # [2]
```

### Альтернативы (если список нужен как аккумулятор)

Если вы **осознанно** хотите накопление (например, для кэширования), то лучше вынести контейнер явно, чтобы поведение не пряталось в сигнатуре:

```python
_items = []

def add_item(item):
    _items.append(item)
    return _items
```

Или использовать `functools.lru_cache` / декоратор, если речь о мемоизации — но это уже другой паттерн.

### Правило на будущее

> Никогда не используйте изменяемые объекты (`list`, `dict`, `set`) как значения по умолчанию в сигнатуре. Используйте `None` и инициализируйте внутри.

Это, пожалуй, самая распространённая «невидимая» баг-зона в Python после проблемы с `is` vs `==`.

### Верификация

```python
>>> add_item(1)
[1]
>>> add_item(2)
[2]
>>> add_item(3, [9])
[9, 3]
>>> add_item(4)
[4]
```

### Confidence

**HIGH** — поведение полностью определено спецификацией Python (PEP 3132 не меняет этого; значения по умолчанию вычисляются в момент `def`), проверено стандартным поведением интерпретатора.
