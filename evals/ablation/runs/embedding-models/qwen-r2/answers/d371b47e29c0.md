**Самая вероятная причина:** PostgreSQL слушает только на `127.0.0.1`. Параметр `listen_addresses` по умолчанию в многих дистрибутивах установлен в `localhost`, поэтому внешние TCP-подключения отклоняются ещё до того, как дойдут до самого Postgres.

### Диагностика (на сервере)

**1. Посмотреть, на каком адресе слушает PostgreSQL:**

```bash
# Ubuntu/Debian (Postgres 12+)
ss -tlnp | grep 5432
# или
netstat -tlnp 2>/dev/null | grep 5432
```

Что искать в выводе:

| Вывод | Значение |
|-------|----------|
| `127.0.0.1:5432` | Слушает только localhost → **это и есть проблема** |
| `0.0.0.0:5432` или `:::5432` | Слушает на всех интерфейсах → проблема в другом |
| `192.168.1.20:5432` | Слушает на конкретном интерфейсе → тоже ок |

**2. Подтвердить в конфиге:**

```bash
# Типичный путь (Debian/Ubuntu)
grep -n '^listen_addresses' /etc/postgresql/*/main/postgresql.conf

# RHEL/CentOS
grep -n '^listen_addresses' /var/lib/pgsql/data/postgresql.conf

# Homebrew / source
grep -n '^listen_addresses' ~/Postgres/*/postgresql.conf
```

Если строка закомментирована (`#listen_addresses`) — по умолчанию значение `localhost`.

### Исправление (если причина подтверждена)

```bash
# 1. Подключиться локально
sudo -u postgres psql

# 2. Убедиться, что pg_hba.conf разрешает доступ (см. ниже)
# 3. Изменить конфиг (либо через psql, либо в файле):
#    postgresql.conf → listen_addresses = '*'
#    (лучше указать конкретный IP, если это не dev-машина)

# Быстрый способ без перезапуска файла:
ALTER SYSTEM SET listen_addresses = '192.168.1.20';

# 4. Перезапустить (listen_addresses нельзя менять через pg_reload_conf — нужно restart)
sudo systemctl restart postgresql
```

**Важно:** `listen_addresses` требует **restart**, не reload. `pg_ctl reload` или `SELECT pg_reload_conf()` тут не сработают.

### Если слушает на всех интерфейсах, а соединение всё равно отказано

Тогда проблема в файрволе:

```bash
# UFW (Ubuntu)
sudo ufw status | grep 5432

# nftables / iptables
sudo nft list ruleset | grep 5432
sudo iptables -L INPUT -n -v | grep 5432

# firewalld (RHEL)
sudo firewall-cmd --list-ports
```

Открыть порт (на время диагностики):

```bash
sudo ufw allow 5432/tcp
# или
sudo iptables -I INPUT -p tcp --dport 5432 -j ACCEPT
```

### Про `pg_hba.conf`

`pg_hba.conf` не даёт "connection refused" — он даёт `FATAL: pg_hba.conf rejects connection`. Но раз уж ты уже в конфигах, проверь, что после исправления `listen_addresses` ты не упрёшься в auth-ошибку:

```
# pg_hba.conf — пример записи для LAN
host  all  app  192.168.1.0/24  scram-sha-256
```

### Быстрая проверка с клиента

```bash
# TCP-уровень: доходит ли порт?
nc -zv 192.168.1.20 5432

# После исправления:
psql -h 192.168.1.20 -p 5432 -U app -d yourdb
```

### Порядок действий (кратко)

1. `ss -tlnp | grep 5432` на сервере → видит ли он `127.0.0.1`
2. Да → `listen_addresses` → исправить → **restart**
3. Нет → файрвол → открыть 5432
4. После шага 2/3 → `nc -zv` с клиента → `psql`
5. Если `FATAL: pg_hba.conf` → добавить запись в `pg_hba.conf` → `pg_reload_conf()`

В 90% случаев это пункт 1.
