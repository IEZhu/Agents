### Analysis

В регистрах накопления 1С измерения, которые **не** указаны в фильтре секции `.Остатки()`, автоматически агрегируются (суммируются по всем своим значениям). Значит, чтобы вернуть остаток по конкретной характеристике — добавляем условие в фильтр, чтобы вернуть «как раньше» (по всем характеристикам) — не добавляем. Реализуем это конкатенацией текста запроса: стандартный идиоматичный подход в 1С для условных частей запроса.

### Implementation

```1c
Функция ПолучитьОстатокТовара(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено) Экспорт
    Запрос = Новый Запрос;

    ТекстЗапроса =
        "ВЫБРАТЬ
        |   ЕСТЬNULL(ТоварыНаСкладахОстатки.КоличествоОстаток, 0) КАК Остаток
        |ИЗ
        |   РегистрНакопления.ТоварыНаСкладах.Остатки(, Номенклатура = &Номенклатура И Склад = &Склад";

    Если ХарактеристикаНоменклатуры <> Неопределено Тогда
        ТекстЗапроса = ТекстЗапроса + " И ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры";
    КонецЕсли;

    ТекстЗапроса = ТекстЗапроса + ") КАК ТоварыНаСкладахОстатки";

    Запрос.Текст = ТекстЗапроса;
    Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
    Запрос.УстановитьПараметр("Склад", Склад);

    Если ХарактеристикаНоменклатуры <> Неопределено Тогда
        Запрос.УстановитьПараметр("ХарактеристикаНоменклатуры", ХарактеристикаНоменклатуры);
    КонецЕсли;

    Выборка = Запрос.Выполнить().Выбрать();
    Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
КонецФункции
```

### Как это работает

| Вызов | Что делает запрос |
|-------|-------------------|
| `ПолучитьОстатокТовара(Товар, Склад)` | Третий параметр = `Неопределено` → условие по характеристике **не** добавляется → 1С сам суммирует по всем характеристикам. Поведение как раньше. |
| `ПолучитьОстатокТовара(Товар, Склад, Хarakт)` | Условие добавляется → возвращается остаток именно по этой характеристике. |

### Что изменилось относительно исходника

1. **Новый параметр** `ХарактеристикаНоменклатуры` со значением по умолчанию `Неопределено` — обратно совместим: все существующие вызовы с двумя аргументами продолжают работать без изменений.
2. **Динамический текст запроса** — стандартный приём в 1С, когда часть фильтра зависит от условия. Параметр `&ХарактеристикаНоменклатуры` устанавливается в запрос только при необходимости (иначе платформа выдаст ошибку «параметр не найден»).
3. **Остальная логика** (`ЕСТЬNULL`, `?()`, структура секции) не тронута.

### Confidence

**HIGH** — используется штатный механизм агрегации нефильтруемых измерений в регистрах накопления 1С и стандартный паттерн условной конкатенации текста запроса; логика покрыта двумя ветвями (с параметром / без), обратная совместимость сохранена.
