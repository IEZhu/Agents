### Analysis

«Connection refused» (а не timeout) — это TCP RST: ядро сервера говорит «на этом интерфейсе/порту никого нет» или фаерволл активно отклоняет. Раз через localhost работает — процесс PostgreSQL жив. Значит, проблема в одном из трёх:

1. PostgreSQL слушает только `127.0.0.1` (самая частая причина).
2. `pg_hba.conf` не содержит правило для внешнего хоста (даёт ту же ошибку на уровне Postgres, если дошёл до него).
3. Фаерволл (`firewalld`/`nftables`/`iptables`) REJECT'ит порт 5432 на внешнем интерфейсе.

---

### Диагностика (выполнять на сервере `db.local`, 192.168.1.20)

**1. На каком адресе реально слушает Postgres**

```bash
ss -tlnp | grep 5432
```

Ожидаемый результат при проблеме:
```
LISTEN  0  128  127.0.0.1:5432  0.0.0.0:*  users:(("postgres",pid=...,fd=...))
```
Если видите только `127.0.0.1` — это и есть корень.

**2. `listen_addresses` в конфигурации**

```bash
# Найти файл
psql -U postgres -c "SHOW config_file;"
# Или стандартный путь
cat /var/lib/pgsql/data/postgresql.conf | grep -n listen_addresses
# RHEL/CentOS:
cat /var/lib/pgsql/16/data/postgresql.conf | grep -n listen_addresses
# Debian/Ubuntu:
cat /etc/postgresql/16/main/postgresql.conf | grep -n listen_addresses
```

По умолчанию: `listen_addresses = 'localhost'`.

**3. `pg_hba.conf`**

```bash
psql -U postgres -c "SHOW hba_file;"
# Посмотреть правила:
cat /var/lib/pgsql/16/data/pg_hba.conf | grep -v '^#' | grep -v '^$'
```

Убедитесь, что есть строка типа:
```
host    app    all    192.168.1.0/24    scram-sha-256
```
Если только `127.0.0.1/32` и `::1/128` — удалённый хост не пропущен.

**4. Фаерволл**

```bash
# firewalld (RHEL/CentOS/Fedora)
firewall-cmd --list-ports
firewall-cmd --list-all | grep 5432

# nftables (Debian/Ubuntu, если firewalld не стоит)
nft list ruleset | grep -A2 5432
# или
iptables -L -n --line-numbers | grep 5432
```

---

### Fix

**Шаг 1 — `postgresql.conf`** (путь уточните через `SHOW config_file;`):

```ini
# Было (по умолчанию):
# listen_addresses = 'localhost'

# Стало — либо конкретный IP, либо все:
listen_addresses = '192.168.1.20'
# или, если сервер принимает подключения из нескольких сетей:
# listen_addresses = '*'
```

**Шаг 2 — `pg_hba.conf`** — добавить правило **до** первой `reject`/`deny` (порядок строк важен, первое совпадение выигрывает):

```
# TYPE  DATABASE  USER  ADDRESS           METHOD
host    all       app   192.168.1.0/24    scram-sha-256
```

> Если метод аутентификации в кластере `md5` (старые версии), ставьте `md5`. С 16+ дефолт — `scram-sha-256`.

**Шаг 3 — перезапуск Postgres** (изменение `listen_addresses` требует рестарта, а не reload):

```bash
sudo systemctl restart postgresql-16   # Debian
# или
sudo systemctl restart postgresql-16.service  # RHEL
```

> **Примечание по безопасности:** перезапуск останавливает все активные сессии. Если это прод — согласуйте окно. Альтернатива для `pg_hba.conf` — `SELECT pg_reload_conf();` (но для `listen_addresses` не подойдёт).

**Шаг 4 — фаерволл** (если порт закрыт):

```bash
# firewalld
sudo firewall-cmd --permanent --add-port=5432/tcp
sudo firewall-cmd --reload

# nftables — добавить в соответствующий chain:
# nft add rule inet filter input tcp dport 5432 ip saddr 192.168.1.0/24 accept
```

> Не открывайте 5432 для `0.0.0.0/0`. Ограничьте subnet.

### Верификация

На **сервере**:

```bash
# Слушает на нужном интерфейсе:
ss -tlnp | grep 5432
# Ожидаем: 192.168.1.20:5432  (или 0.0.0.0:5432)
```

На **клиенте**:

```bash
# Быстрая проверка TCP до Postgres-уровня:
nc -zv db.local 5432

# Реальное подключение:
PGPASSWORD='ваш_пароль' psql -h db.local -p 5432 -U app -d appdb -c "SELECT 1;"
```

Если `nc` проходит, а `psql` говорит «role "app" does not exist» или «password authentication failed» — сетевой слой исправлен, осталось только аутентификация.

### Что было бы полезно, если не помогло

```bash
# На сервере — живой лог при попытке подключения:
tail -f /var/lib/pgsql/16/data/log/postgresql-*.log
# или (Debian):
tail -f /var/log/postgresql/postgresql-16-main.log
```

Там Postgres пишет причину отказа на уровне `pg_hba.conf` (`FATAL: pg_hba.conf rejects connection ...`) — это снимает все догадки.
