### Анализ

Классическая ловушка Python: **mutable default argument**. Значение по умолчанию `[]` создаётся **один раз** при определении функции, а не при каждом вызове. Все вызовы, где `bucket` не передан, мутируют один и тот же список.

### Почему так работает

```python
def add_item(item, bucket=[]):   # ← [] создаётся ОДИН раз, при def
    bucket.append(item)
    return bucket
```

Можно это «увидеть» напрямую:

```python
def f(a, b=[]):
    return b

print(f(1) is f(2))  # True — оба вызова получили ОДИН и тот же объект
```

Ваш случай:

```
add_item(1)  →  [ ]  + 1  →  [1]        # общий список стал [1]
add_item(2)  →  [1] + 2  →  [1, 2]      # тот же список, уже содержит 1
```

### Правильно

Заменить дефолт на `None` и создавать список внутри:

```python
def add_item(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

Теперь каждый вызов без явного `bucket` получает **свой** новый список:

```python
add_item(1)  # [1]
add_item(2)  # [2]
```

### Альтернативы (если список нужен как аккумулятор)

Если вы **осознанно** хотите накопление (например, для кэширования), то лучше вынести контейнер явно, чтобы поведение не пряталось в сигнатуре:

```python
_items = []

def add_item(item):
    _items.append(item)
    return _items
```

Или использовать `functools.lru_cache` / декоратор, если речь о мемоизации — но это уже другой паттерн.

### Правило на будущее

> Никогда не используйте изменяемые объекты (`list`, `dict`, `set`) как значения по умолчанию в сигнатуре. Используйте `None` и инициализируйте внутри.

Это, пожалуй, самая распространённая «невидимая» баг-зона в Python после проблемы с `is` vs `==`.

### Верификация

```python
>>> add_item(1)
[1]
>>> add_item(2)
[2]
>>> add_item(3, [9])
[9, 3]
>>> add_item(4)
[4]
```

### Confidence

**HIGH** — поведение полностью определено спецификацией Python (PEP 3132 не меняет этого; значения по умолчанию вычисляются в момент `def`), проверено стандартным поведением интерпретатора.
