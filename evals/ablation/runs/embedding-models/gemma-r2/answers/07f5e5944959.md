```sql
SELECT id, customer_id, created_at, amount
FROM (
    SELECT *,
           ROW_NUMBER() OVER (
               PARTITION BY customer_id 
               ORDER BY amount DESC, created_at ASC
           ) as rn
    FROM orders
) ranked_orders
WHERE rn = 2;
```

### Почему этот запрос корректен:

1.  **`ROW_NUMBER()`**: Присваивает уникальный порядковый номер каждой строке внутри группы. В отличие от `RANK()`, он гарантирует, что даже при абсолютно идентичных `amount` и `created_at` мы получим строго вторую строку, а не несколько строк с рангом «2».
2.  **`PARTITION BY customer_id`**: Сбрасывает счетчик для каждого нового клиента, позволяя искать «второй заказ» индивидуально для каждого.
3.  **`ORDER BY amount DESC, created_at ASC`**: Точно реализует условие сортировки: сначала самые дорогие заказы, затем (при равенстве сумм) — самые ранние по времени.
4.  **`WHERE rn = 2`**:
    *   Выбирает именно второй заказ.
    *   **Автоматически исключает** клиентов с одним заказом, так как для них максимальное значение `rn` будет равно 1, и условие `rn = 2` не выполнится.

**Рекомендация по производительности:**
Для оптимальной работы этого запроса на больших объемах данных рекомендуется создать составной индекс:
`CREATE INDEX idx_orders_customer_amount_date ON orders (customer_id, amount DESC, created_at ASC);`
Это позволит PostgreSQL выполнить поиск через **Index Only Scan**, избегая дорогостоящей сортировки в памяти (Sort) или на диске.
