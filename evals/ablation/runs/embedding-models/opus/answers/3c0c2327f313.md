### Analysis

Добавляю необязательный третий параметр `ХарактеристикаНоменклатуры = Неопределено`. Условие на характеристику попадает в параметры виртуальной таблицы `Остатки` только тогда, когда характеристику передали. Существующие вызовы с двумя параметрами продолжат работать без изменений.

Есть важный момент: **у текущей функции уже есть ошибка**. Виртуальная таблица `Остатки` возвращает строки в разрезе *всех* измерений регистра. Раз в регистре есть `ХарактеристикаНоменклатуры`, то для товара с несколькими характеристиками запрос вернёт несколько строк, а `Выборка.Следующий()` прочитает только первую из них. В итоге функция возвращает остаток по одной случайной характеристике, а не общий остаток. Поэтому в новой версии остаток суммируется через `СУММА`.

### Implementation

```bsl
// Возвращает остаток товара на складе.
// Если ХарактеристикаНоменклатуры не передана (Неопределено), возвращает
// суммарный остаток по всем характеристикам.
Функция ПолучитьОстатокТовара(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено) Экспорт
	
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ
	|	ЕСТЬNULL(СУММА(ТоварыНаСкладахОстатки.КоличествоОстаток), 0) КАК Остаток
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, &УсловиеОтбора) КАК ТоварыНаСкладахОстатки";
	
	УсловиеОтбора = "Номенклатура = &Номенклатура И Склад = &Склад";
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	
	Если ХарактеристикаНоменклатуры <> Неопределено Тогда
		УсловиеОтбора = УсловиеОтбора + " И ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры";
		Запрос.УстановитьПараметр("ХарактеристикаНоменклатуры", ХарактеристикаНоменклатуры);
	КонецЕсли;
	
	Запрос.Текст = СтрЗаменить(Запрос.Текст, "&УсловиеОтбора", УсловиеОтбора);
	
	Выборка = Запрос.Выполнить().Выбрать();
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
	
КонецФункции
```

Почему сделано именно так:

- **Текст условия собирается динамически.** Можно было бы обойтись без этого и написать `(&ОтборПоХарактеристике = ЛОЖЬ ИЛИ ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры)`. Но `ИЛИ` в параметрах виртуальной таблицы обычно мешает СУБД использовать индекс по измерению, и запрос замедляется на больших регистрах. Два чётких варианта условия работают быстрее.
- **Значение «не передали» — это только `Неопределено`.** Пустую ссылку на характеристику я считаю осмысленным значением: это движения по товарам без характеристик. Если в вашей конфигурации пустая характеристика тоже должна означать «по всем», замените проверку на `Если ЗначениеЗаполнено(ХарактеристикаНоменклатуры) Тогда`. Учтите, что тогда остаток именно по пустой характеристике получить уже не получится.
- **Агрегат без `СГРУППИРОВАТЬ ПО`** всегда возвращает одну строку, даже если движений нет (с `NULL`, который превращается в 0). Проверку `?(Выборка.Следующий(), ...)` я оставил для надёжности.

### Verification

Я не запускал этот код: платформы 1С здесь нет. Перед слиянием проверьте на копии базы:

1. Вызов с двумя параметрами для товара с несколькими характеристиками должен вернуть сумму по всем характеристикам. Если раньше этот вызов давал другое число, значит описанная выше ошибка действительно проявлялась.
2. Вызов с конкретной характеристикой должен вернуть остаток только по ней.
3. Для товара без движений функция должна вернуть 0 в обоих вариантах.
4. Если передать пустую ссылку на характеристику, функция должна вернуть остаток по товарам без характеристик.

Найдите все вызовы функции (глобальный поиск `ПолучитьОстатокТовара(`). Это нужно не для совместимости, её сохраняет параметр со значением по умолчанию. Это нужно, чтобы понять, какие места рассчитывали на старое поведение с «первой строкой».
