### Анализ

Добавляем третий **необязательный** параметр со значением по умолчанию `Неопределено`. Тогда все существующие вызовы `ПолучитьОстатокТовара(Номенклатура, Склад)` продолжат работать без изменений. Условие по характеристике добавляется в параметры виртуальной таблицы только тогда, когда характеристику передали. Кроме того, остаток нужно **суммировать**: в исходной версии есть скрытая ошибка, о ней ниже.

### Реализация

```bsl
// Возвращает остаток товара на складе.
// Если ХарактеристикаНоменклатуры не передана (Неопределено), возвращает
// суммарный остаток по всем характеристикам номенклатуры на складе.
Функция ПолучитьОстатокТовара(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено) Экспорт
	
	ОтборПоХарактеристике = (ХарактеристикаНоменклатуры <> Неопределено);
	
	УсловиеОтбора = "Номенклатура = &Номенклатура И Склад = &Склад";
	Если ОтборПоХарактеристике Тогда
		УсловиеОтбора = УсловиеОтбора + " И ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры";
	КонецЕсли;
	
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ
	|	ЕСТЬNULL(СУММА(ТоварыНаСкладахОстатки.КоличествоОстаток), 0) КАК Остаток
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, &УсловиеОтбора) КАК ТоварыНаСкладахОстатки";
	Запрос.Текст = СтрЗаменить(Запрос.Текст, "&УсловиеОтбора", УсловиеОтбора);
	
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	Если ОтборПоХарактеристике Тогда
		Запрос.УстановитьПараметр("ХарактеристикаНоменклатуры", ХарактеристикаНоменклатуры);
	КонецЕсли;
	
	Выборка = Запрос.Выполнить().Выбрать();
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
	
КонецФункции
```

Почему сделано именно так:

- **`СУММА(...)` вместо одного поля.** У регистра есть измерение `ХарактеристикаНоменклатуры`, поэтому по одной паре «номенклатура + склад» виртуальная таблица остатков может вернуть несколько строк, по одной на каждую характеристику. Исходная функция брала первую строку через `Выборка.Следующий()` и возвращала остаток **одной произвольной характеристики**, а не общий. Значит, «как раньше» на самом деле работало правильно только для номенклатуры без характеристик. С агрегатом запрос всегда возвращает ровно одну строку. Если остатков нет, `СУММА` даёт `NULL`, и `ЕСТЬNULL` превращает его в 0.
- **Условие собирается в тексте, а не через `ИЛИ`.** Можно было бы написать одним запросом вариант `(НЕ &ОтборПоХарактеристике ИЛИ ХарактеристикаНоменклатуры = &Характеристика)`. Но `ИЛИ` в параметрах виртуальной таблицы обычно мешает СУБД использовать индекс. В текст попадают только константные фрагменты, а значения по-прежнему передаются параметрами, поэтому инъекции здесь нет.
- **Почему `Неопределено`, а не `ЗначениеЗаполнено`.** Пустая ссылка на характеристику может быть настоящим значением измерения: так обычно записывают движения по номенклатуре без характеристик. Если передана пустая ссылка, функция вернёт остаток именно «без характеристики». Если же вы хотите, чтобы пустая характеристика означала «по всем», замените проверку на `ОтборПоХарактеристике = ЗначениеЗаполнено(ХарактеристикаНоменклатуры);`.

### Проверка

Запустить этот код я не мог, поэтому проверьте на базе следующие случаи:

1. Номенклатура без характеристик, вызов с двумя параметрами: результат должен совпасть со старой функцией.
2. Номенклатура с двумя характеристиками (например, остатки 5 и 3), вызов без характеристики: должно вернуться 8. Старая функция вернула бы 5 или 3.
3. Тот же товар с характеристикой: 5 или 3 соответственно.
4. Характеристика, по которой нет движений, или пустой склад: 0.
5. Поищите все вызовы функции (Ctrl+F по конфигурации). Сигнатура совместима, но из-за исправления в п. 2 вызывающий код, который неявно полагался на «первую строку», начнёт получать суммарный остаток. Скорее всего, именно этого от него и ждали, но лучше убедиться.
