Да, почти наверняка можно. `git reset --hard` двигает только указатель ветки, а сами коммиты остаются в репозитории. Найти их помогает reflog: это локальный журнал перемещений `HEAD` и веток. Пока вы не запускали `git gc --prune=now` и не чистили reflog вручную, коммиты на месте. По умолчанию недостижимые записи reflog живут около 30 дней (`gc.reflogExpireUnreachable`; значение по памяти, если важно, проверьте в `git help config`).

## Шаги

**0. Ничего не делайте в ветке до восстановления.** Не запускайте `git gc` и не делайте новых reset. Новые коммиты, в принципе, не помешают, но так проще.

**1. Посмотрите reflog ветки:**

```bash
git reflog show feature/payments
```

или общий журнал `HEAD`:

```bash
git reflog
```

Вы увидите примерно такое:

```
a1b2c3d feature/payments@{0}: reset: moving to HEAD~3
9f8e7d6 feature/payments@{1}: commit: Add refund handling
...
```

Вам нужна запись **сразу под** строкой `reset: moving to HEAD~3`, то есть состояние до reset. Обычно это `feature/payments@{1}` (или `HEAD@{1}`, если после reset вы ничего не делали).

**2. Убедитесь, что это нужные коммиты:**

```bash
git log --oneline -5 feature/payments@{1}
```

В выводе должны быть три пропавших коммита сверху. Если сомневаетесь, посмотрите содержимое через `git show <hash>`.

**3. (Рекомендую) Сделайте страховочную ветку:**

```bash
git branch backup/payments-before-restore feature/payments@{1}
```

Теперь коммиты доступны по имени ветки, и reflog больше не нужен.

**4. Верните ветку на прежнее место.** Убедитесь, что вы на `feature/payments` (`git status`) и что у вас нет незакоммиченных изменений, которые жалко потерять: `reset --hard` их снова сотрёт. Затем:

```bash
git reset --hard feature/payments@{1}
```

или по хэшу из шага 1:

```bash
git reset --hard 9f8e7d6
```

Если есть незакоммиченная работа, сначала сделайте `git stash`, а после восстановления `git stash pop`.

**5. Проверьте результат:**

```bash
git log --oneline -5
git status
```

Если всё на месте, страховочную ветку можно удалить: `git branch -d backup/payments-before-restore`.

## Если в reflog ничего нет

Такое бывает редко, например если reflog отключён или очищен. Тогда ищите «висящие» коммиты:

```bash
git fsck --lost-found
```

Команда выведет `dangling commit <hash>`. Проверьте каждый через `git show <hash>` и восстановите нужный так же: `git branch recovered <hash>`.

## Важное ограничение

Восстанавливаются только **закоммиченные** изменения. Если на момент reset в рабочей директории были незакоммиченные правки, `reset --hard` их перезаписал, и Git их не хранит. Исключение: файлы, которые были добавлены через `git add`. Их содержимое может найтись среди `dangling blob` в выводе `git fsck --lost-found`, но уже без имён файлов.

Пушить ничего не нужно: ветка не публиковалась, поэтому force-push не понадобится.
