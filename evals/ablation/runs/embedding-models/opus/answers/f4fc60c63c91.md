### Analysis
The spec asks for `validate_inn(inn: str) -> bool`. It accepts a 10-digit legal-entity INN or a 12-digit individual INN and checks the FNS control digits. I check the format first with one ASCII-only regex, then run a weighted checksum: `(Σ digit·weight mod 11) mod 10`. A 10-digit INN has one control digit. A 12-digit INN has two.

One detail matters. I don't use `str.isdigit()`, because it accepts non-ASCII digits like `"²"` or Arabic-Indic numerals, and the spec says any non-digit must return False. I use `re.fullmatch(..., re.ASCII)` instead. Unlike `re.match(r"...$")`, it also rejects a trailing `"\n"`.

### Implementation

`inn.py`
```python
import re

_INN_FORMAT = re.compile(r"\d{10}|\d{12}", re.ASCII)

# Weight vectors from the FNS control-digit algorithm.
_WEIGHTS_10 = (2, 4, 10, 3, 5, 9, 4, 6, 8)
_WEIGHTS_12_FIRST = (7, 2, 4, 10, 3, 5, 9, 4, 6, 8)
_WEIGHTS_12_SECOND = (3, 7, 2, 4, 10, 3, 5, 9, 4, 6, 8)


def _control_digit(digits: list[int], weights: tuple[int, ...]) -> int:
    return sum(d * w for d, w in zip(digits, weights)) % 11 % 10


def validate_inn(inn: str) -> bool:
    """Return True if `inn` is a valid Russian INN (10 or 12 ASCII digits, correct checksum)."""
    if not _INN_FORMAT.fullmatch(inn):
        return False

    digits = [int(ch) for ch in inn]

    if len(digits) == 10:
        return digits[9] == _control_digit(digits, _WEIGHTS_10)

    return (
        digits[10] == _control_digit(digits, _WEIGHTS_12_FIRST)
        and digits[11] == _control_digit(digits, _WEIGHTS_12_SECOND)
    )
```

`test_inn.py`
```python
import pytest

from inn import validate_inn

VALID_10 = "7707083893"    # Sberbank's public INN
VALID_12 = "500100732890"  # control digits computed by hand: 9, then 0


@pytest.mark.parametrize("inn", [VALID_10, VALID_12])
def test_valid_inn(inn):
    assert validate_inn(inn) is True


@pytest.mark.parametrize("inn", [
    "7707083894",    # 10 digits, wrong control digit
    "500100732880",  # 12 digits, wrong first control digit
    "500100732891",  # 12 digits, wrong second control digit
])
def test_bad_checksum(inn):
    assert validate_inn(inn) is False


@pytest.mark.parametrize("inn", [
    "",
    " ",
    " 7707083893",
    "7707083893 ",
    "7707083893\n",
    "77070 83893",
    "770708389a",
    "+707083893",
    "７７０７０８３８９３",  # full-width digits
    "²707083893",           # superscript: str.isdigit() would accept this
])
def test_non_digit_input(inn):
    assert validate_inn(inn) is False


@pytest.mark.parametrize("inn", ["1", "770708389", "77070838931", "5001007328901"])
def test_wrong_length(inn):
    assert validate_inn(inn) is False


@pytest.mark.parametrize("valid", [VALID_10, VALID_12])
def test_changing_any_single_digit_breaks_checksum_on_last_digit(valid):
    # Changing the last control digit must always invalidate.
    last = int(valid[-1])
    for d in range(10):
        if d != last:
            assert validate_inn(valid[:-1] + str(d)) is False
```

- I worked out both fixtures by hand. For `7707083893`, the weighted sum is 267, 267 mod 11 = 3, and the last digit is 3. For `500100732890`, the first sum is 196 (mod 11 = 9) and the second is 209 (mod 11 = 0).
- **Weights:** I'm recalling the weight vectors and the mod 11 / mod 10 rule from memory. They match the widely published FNS algorithm, but I haven't checked them against an official FNS document this turn. Please confirm them against your team's reference.
- **Complexity:** O(1). The input is at most 12 characters.
- **Points for the spec authors:**
  - An all-zero INN like `"0000000000"` passes the checksum and returns True. Real INNs can't start with `00`, because the first digits are a region code. If you want that rejected, it needs an explicit rule.
  - The spec doesn't say what happens with a non-`str` input such as `None` or `int`. Right now `re.fullmatch` raises a `TypeError`. I think that's the right fail-fast behavior for a caller bug, but you can add an `isinstance` guard if you'd rather get False.
