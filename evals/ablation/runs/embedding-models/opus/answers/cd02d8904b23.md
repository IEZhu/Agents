Да, их почти наверняка можно вернуть. `git reset --hard` не удаляет коммиты, он только переносит указатель ветки. Сами коммиты остаются в репозитории, и на них по-прежнему ссылается reflog. По умолчанию недостижимые записи reflog хранятся 30 дней (`gc.reflogExpireUnreachable`; значение по памяти, не проверено). Восстанавливать лучше сразу и не запускать `git gc`.

### Шаг 1. Ничего лишнего не делайте

Пока не восстановили ветку, не запускайте `git gc` или `git prune` и не делайте новых reset. Новые коммиты сами по себе не помешают, но лучше не усложнять картину.

### Шаг 2. Найдите состояние до reset в reflog

```bash
git checkout feature/payments   # если вы не на ней
git reflog -n 10
```

Вы увидите примерно такое:

```
a1b2c3d HEAD@{0}: reset: moving to HEAD~3
9f8e7d6 HEAD@{1}: commit: <сообщение вашего последнего коммита>
...
```

Нужна строка сразу под `reset: moving to HEAD~3`. Обычно это `HEAD@{1}`, и её хеш указывает на последний из трёх потерянных коммитов. Можно смотреть и reflog самой ветки, там меньше шума от переключений между ветками:

```bash
git reflog show feature/payments
```

### Шаг 3. Убедитесь, что это нужный коммит

```bash
git log --oneline -5 9f8e7d6
```

В выводе должны быть все три ваших коммита сверху.

### Шаг 4. Верните ветку на этот коммит

```bash
git reset --hard 9f8e7d6        # или: git reset --hard HEAD@{1}
```

Если reset был последней операцией, которая двигала HEAD, подойдёт и короткий вариант:

```bash
git reset --hard ORIG_HEAD
```

`reset` записывает в `ORIG_HEAD` позицию HEAD до своего выполнения. Но `merge`, `rebase` и другой `reset` его перезаписывают, поэтому вариант с хешем из reflog надёжнее.

Есть и более осторожный путь: сначала сохранить коммиты в отдельную ветку, а потом уже трогать текущую:

```bash
git branch payments-rescue 9f8e7d6
```

### Шаг 5. Проверьте результат

```bash
git log --oneline -5
git status
```

Когда убедитесь, что всё на месте, запушьте ветку, чтобы такая ситуация больше не грозила потерей работы:

```bash
git push -u origin feature/payments
```

### Важная оговорка

Reflog возвращает только **закоммиченное**. Если на момент reset у вас были незакоммиченные изменения, `--hard` их стёр:

- изменения, которые были добавлены в индекс (`git add`), но не закоммичены, иногда можно найти среди висячих blob-объектов: `git fsck --lost-found` (файлы появятся в `.git/lost-found/other/`, без имён);
- изменения, которые не добавлялись в индекс, Git не сохранял, и вернуть их можно только из истории IDE (например, Local History в JetBrains) или из бэкапов.

**Уверенность: HIGH** для восстановления коммитов через reflog и `ORIG_HEAD`, это стандартный и проверенный механизм Git. Срок хранения 30 дней указан по памяти.
