## Latest user message
В конфигурации 1С есть функция:

Функция ПолучитьОстатокТовара(Номенклатура, Склад) Экспорт
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ
	|	ЕСТЬNULL(ТоварыНаСкладахОстатки.КоличествоОстаток, 0) КАК Остаток
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Номенклатура = &Номенклатура И Склад = &Склад) КАК ТоварыНаСкладахОстатки";
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	Выборка = Запрос.Выполнить().Выбрать();
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
КонецФункции

В регистре ТоварыНаСкладах есть измерение ХарактеристикаНоменклатуры. Нужно, чтобы функция учитывала характеристику, если её передали, а если не передали — возвращала остаток по номенклатуре и складу, как раньше. Перепиши функцию.

## Rubric (what a strong answer does)
1. Adds an optional characteristic parameter and filters by ХарактеристикаНоменклатуры only when it is passed.
2. When no characteristic is passed, still returns the total over all characteristics: the filter stays in the virtual-table parameters, or СУММА is used if ХарактеристикаНоменклатуры appears in the outer query; never only the first characteristic's row.
3. Keeps the existing Russian identifiers (ПолучитьОстатокТовара, ТоварыНаСкладах, Номенклатура, Склад) exactly and writes valid 1C syntax.
4. Explains the change in Russian.

## Answer A
### Analysis

Добавляю необязательный третий параметр `ХарактеристикаНоменклатуры = Неопределено`. Условие на характеристику попадает в параметры виртуальной таблицы `Остатки` только тогда, когда характеристику передали. Существующие вызовы с двумя параметрами продолжат работать без изменений.

Есть важный момент: **у текущей функции уже есть ошибка**. Виртуальная таблица `Остатки` возвращает строки в разрезе *всех* измерений регистра. Раз в регистре есть `ХарактеристикаНоменклатуры`, то для товара с несколькими характеристиками запрос вернёт несколько строк, а `Выборка.Следующий()` прочитает только первую из них. В итоге функция возвращает остаток по одной случайной характеристике, а не общий остаток. Поэтому в новой версии остаток суммируется через `СУММА`.

### Implementation

```bsl
// Возвращает остаток товара на складе.
// Если ХарактеристикаНоменклатуры не передана (Неопределено), возвращает
// суммарный остаток по всем характеристикам.
Функция ПолучитьОстатокТовара(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено) Экспорт
	
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ
	|	ЕСТЬNULL(СУММА(ТоварыНаСкладахОстатки.КоличествоОстаток), 0) КАК Остаток
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, &УсловиеОтбора) КАК ТоварыНаСкладахОстатки";
	
	УсловиеОтбора = "Номенклатура = &Номенклатура И Склад = &Склад";
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	
	Если ХарактеристикаНоменклатуры <> Неопределено Тогда
		УсловиеОтбора = УсловиеОтбора + " И ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры";
		Запрос.УстановитьПараметр("ХарактеристикаНоменклатуры", ХарактеристикаНоменклатуры);
	КонецЕсли;
	
	Запрос.Текст = СтрЗаменить(Запрос.Текст, "&УсловиеОтбора", УсловиеОтбора);
	
	Выборка = Запрос.Выполнить().Выбрать();
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
	
КонецФункции
```

Почему сделано именно так:

- **Текст условия собирается динамически.** Можно было бы обойтись без этого и написать `(&ОтборПоХарактеристике = ЛОЖЬ ИЛИ ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры)`. Но `ИЛИ` в параметрах виртуальной таблицы обычно мешает СУБД использовать индекс по измерению, и запрос замедляется на больших регистрах. Два чётких варианта условия работают быстрее.
- **Значение «не передали» — это только `Неопределено`.** Пустую ссылку на характеристику я считаю осмысленным значением: это движения по товарам без характеристик. Если в вашей конфигурации пустая характеристика тоже должна означать «по всем», замените проверку на `Если ЗначениеЗаполнено(ХарактеристикаНоменклатуры) Тогда`. Учтите, что тогда остаток именно по пустой характеристике получить уже не получится.
- **Агрегат без `СГРУППИРОВАТЬ ПО`** всегда возвращает одну строку, даже если движений нет (с `NULL`, который превращается в 0). Проверку `?(Выборка.Следующий(), ...)` я оставил для надёжности.

### Verification

1. Вызов с двумя параметрами для товара с несколькими характеристиками должен вернуть сумму по всем характеристикам. Если раньше этот вызов давал другое число, значит описанная выше ошибка действительно проявлялась.

Найдите все вызовы функции (глобальный поиск `ПолучитьОстатокТовара(`). Это нужно не для совместимости, её сохраняет параметр со значением по умолчанию. Это нужно, чтобы понять, какие места рассчитывали на старое поведение с «первой строкой».

## Answer B
### Анализ

Добавляем третий **необязательный** параметр со значением по умолчанию `Неопределено`. Тогда все существующие вызовы `ПолучитьОстатокТовара(Номенклатура, Склад)` продолжат работать без изменений. Условие по характеристике добавляется в параметры виртуальной таблицы только тогда, когда характеристику передали. Кроме того, остаток нужно **суммировать**: в исходной версии есть скрытая ошибка, о ней ниже.

### Реализация

```bsl
// Возвращает остаток товара на складе.
// Если ХарактеристикаНоменклатуры не передана (Неопределено), возвращает
// суммарный остаток по всем характеристикам номенклатуры на складе.
Функция ПолучитьОстатокТовара(Номенклатура, Склад, ХарактеристикаНоменклатуры = Неопределено) Экспорт
	
	ОтборПоХарактеристике = (ХарактеристикаНоменклатуры <> Неопределено);
	
	УсловиеОтбора = "Номенклатура = &Номенклатура И Склад = &Склад";
	Если ОтборПоХарактеристике Тогда
		УсловиеОтбора = УсловиеОтбора + " И ХарактеристикаНоменклатуры = &ХарактеристикаНоменклатуры";
	КонецЕсли;
	
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ
	|	ЕСТЬNULL(СУММА(ТоварыНаСкладахОстатки.КоличествоОстаток), 0) КАК Остаток
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, &УсловиеОтбора) КАК ТоварыНаСкладахОстатки";
	Запрос.Текст = СтрЗаменить(Запрос.Текст, "&УсловиеОтбора", УсловиеОтбора);
	
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	Если ОтборПоХарактеристике Тогда
		Запрос.УстановитьПараметр("ХарактеристикаНоменклатуры", ХарактеристикаНоменклатуры);
	КонецЕсли;
	
	Выборка = Запрос.Выполнить().Выбрать();
	Возврат ?(Выборка.Следующий(), Выборка.Остаток, 0);
	
КонецФункции
```

Почему сделано именно так:

- **`СУММА(...)` вместо одного поля.** У регистра есть измерение `ХарактеристикаНоменклатуры`, поэтому по одной паре «номенклатура + склад» виртуальная таблица остатков может вернуть несколько строк, по одной на каждую характеристику. Исходная функция брала первую строку через `Выборка.Следующий()` и возвращала остаток **одной произвольной характеристики**, а не общий. Значит, «как раньше» на самом деле работало правильно только для номенклатуры без характеристик. С агрегатом запрос всегда возвращает ровно одну строку. Если остатков нет, `СУММА` даёт `NULL`, и `ЕСТЬNULL` превращает его в 0.
- **Условие собирается в тексте, а не через `ИЛИ`.** Можно было бы написать одним запросом вариант `(НЕ &ОтборПоХарактеристике ИЛИ ХарактеристикаНоменклатуры = &Характеристика)`. Но `ИЛИ` в параметрах виртуальной таблицы обычно мешает СУБД использовать индекс. В текст попадают только константные фрагменты, а значения по-прежнему передаются параметрами, поэтому инъекции здесь нет.
- **Почему `Неопределено`, а не `ЗначениеЗаполнено`.** Пустая ссылка на характеристику может быть настоящим значением измерения: так обычно записывают движения по номенклатуре без характеристик. Если передана пустая ссылка, функция вернёт остаток именно «без характеристики». Если же вы хотите, чтобы пустая характеристика означала «по всем», замените проверку на `ОтборПоХарактеристике = ЗначениеЗаполнено(ХарактеристикаНоменклатуры);`.

### Проверка

Запустить этот код я не мог, поэтому проверьте на базе следующие случаи:

1. Номенклатура без характеристик, вызов с двумя параметрами: результат должен совпасть со старой функцией.
2. Номенклатура с двумя характеристиками (например, остатки 5 и 3), вызов без характеристики: должно вернуться 8. Старая функция вернула бы 5 или 3.
3. Тот же товар с характеристикой: 5 или 3 соответственно.
4. Характеристика, по которой нет движений, или пустой склад: 0.
5. Поищите все вызовы функции (Ctrl+F по конфигурации). Сигнатура совместима, но из-за исправления в п. 2 вызывающий код, который неявно полагался на «первую строку», начнёт получать суммарный остаток. Скорее всего, именно этого от него и ждали, но лучше убедиться.
