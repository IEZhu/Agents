## Answer A
### Analysis
The spec asks for `validate_inn(inn: str) -> bool`. It accepts a 10-digit legal-entity INN or a 12-digit individual INN and checks the FNS control digits. I check the format first with one ASCII-only regex, then run a weighted checksum: `(Σ digit·weight mod 11) mod 10`. A 10-digit INN has one control digit. A 12-digit INN has two.

One detail matters. I don't use `str.isdigit()`, because it accepts non-ASCII digits like `"²"` or Arabic-Indic numerals, and the spec says any non-digit must return False. I use `re.fullmatch(..., re.ASCII)` instead. Unlike `re.match(r"...$")`, it also rejects a trailing `"\n"`.

### Implementation

`inn.py`
```python
import re

_INN_FORMAT = re.compile(r"\d{10}|\d{12}", re.ASCII)

# Weight vectors from the FNS control-digit algorithm.
_WEIGHTS_10 = (2, 4, 10, 3, 5, 9, 4, 6, 8)
_WEIGHTS_12_FIRST = (7, 2, 4, 10, 3, 5, 9, 4, 6, 8)
_WEIGHTS_12_SECOND = (3, 7, 2, 4, 10, 3, 5, 9, 4, 6, 8)


def _control_digit(digits: list[int], weights: tuple[int, ...]) -> int:
    return sum(d * w for d, w in zip(digits, weights)) % 11 % 10


def validate_inn(inn: str) -> bool:
    """Return True if `inn` is a valid Russian INN (10 or 12 ASCII digits, correct checksum)."""
    if not _INN_FORMAT.fullmatch(inn):
        return False

    digits = [int(ch) for ch in inn]

    if len(digits) == 10:
        return digits[9] == _control_digit(digits, _WEIGHTS_10)

    return (
        digits[10] == _control_digit(digits, _WEIGHTS_12_FIRST)
        and digits[11] == _control_digit(digits, _WEIGHTS_12_SECOND)
    )
```

## Answer B
### Analysis

The spec asks for one pure function: check the format (only ASCII digits, length 10 or 12), then check the control digits with the FNS weighted-checksum algorithm. One trap matters here. Python's `str.isdigit()` also accepts non-ASCII digits such as full-width `７` or Arabic-Indic `٣`, and `int()` parses them without complaint. A naive version would accept them, even though the spec says any non-digit character must give `False`. I use `re.fullmatch` with an explicit `[0-9]` class, which also rejects a trailing `\n`. A regex using `$` would let that newline through.

### Implementation

`inn_validator.py`

```python
"""Validation of Russian taxpayer identification numbers (INN)."""

import re

LEGAL_ENTITY_LENGTH = 10
INDIVIDUAL_LENGTH = 12

# Control-digit weights defined by the FNS algorithm.
_WEIGHTS_10 = (2, 4, 10, 3, 5, 9, 4, 6, 8)
_WEIGHTS_12_FIRST = (7, 2, 4, 10, 3, 5, 9, 4, 6, 8)
_WEIGHTS_12_SECOND = (3, 7, 2, 4, 10, 3, 5, 9, 4, 6, 8)

# Explicit ASCII class: str.isdigit()/\d would also accept Unicode digits.
_ASCII_DIGITS = re.compile(r"[0-9]+")


def _control_digit(digits: list[int], weights: tuple[int, ...]) -> int:
    weighted_sum = sum(d * w for d, w in zip(digits, weights))
    return weighted_sum % 11 % 10


def validate_inn(inn: str) -> bool:
    """Return True if `inn` is a valid 10-digit (legal entity) or 12-digit (individual) INN."""
    if not isinstance(inn, str) or not _ASCII_DIGITS.fullmatch(inn):
        return False

    digits = [int(ch) for ch in inn]

    if len(digits) == LEGAL_ENTITY_LENGTH:
        return digits[9] == _control_digit(digits, _WEIGHTS_10)

    if len(digits) == INDIVIDUAL_LENGTH:
        return (
            digits[10] == _control_digit(digits, _WEIGHTS_12_FIRST)
            and digits[11] == _control_digit(digits, _WEIGHTS_12_SECOND)
        )

    return False
```
