## Answer A
Значение по умолчанию `bucket=[]` вычисляется **один раз**, когда интерпретатор выполняет `def`, а не при каждом вызове. Поэтому все вызовы без аргумента `bucket` получают **один и тот же** объект списка. Список изменяемый, и `append` меняет именно его, так что содержимое копится от вызова к вызову.

Это легко увидеть:

```python
def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

a = add_item(1)
b = add_item(2)
print(a is b)                 # True: это один и тот же список
print(add_item.__defaults__)  # ([1, 2],): «состояние» хранится в самой функции
```

### Как писать правильно

Стандартная идиома: значение по умолчанию `None`, а новый список создаётся внутри функции.

```python
def add_item(item, bucket: list | None = None) -> list:
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket

add_item(1)  # [1]
add_item(2)  # [2]

my = [0]
add_item(5, my)  # [0, 5]: переданный список по-прежнему изменяется
```

Пара замечаний:

- Проверяйте именно `is None`, а не `bucket = bucket or []`. Вариант с `or` молча заменит переданный пустой список новым, и изменения не дойдут до вызывающего кода.
- Если функция не должна менять список, который ей передали, делайте копию: `bucket = [] if bucket is None else list(bucket)`.
- Так же ведут себя все изменяемые значения по умолчанию: `{}`, `set()`, экземпляры собственных классов. Неизменяемые (`None`, числа, строки, кортежи) безопасны.
- Линтеры это ловят: в Ruff/flake8-bugbear это правило `B006` (код вспоминаю по памяти, сверьтесь с документацией), а pylint выдаёт `dangerous-default-value`.

Иногда этим поведением пользуются намеренно, например как простым кэшем между вызовами. Но такой код трудно читать, и лучше сделать это явно через `functools.lru_cache` или переменную уровня модуля.


## Answer B
Значение по умолчанию вычисляется **один раз**, когда интерпретатор выполняет `def`, а не при каждом вызове. Поэтому `bucket=[]` создаёт один список, и он остаётся привязан к функции. Все вызовы без аргумента `bucket` получают **один и тот же** объект. Список изменяемый (mutable), и `append` меняет именно его, так что результат прошлых вызовов никуда не пропадает.

Это видно напрямую:

```python
def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

a = add_item(1)
b = add_item(2)
print(a is b)                 # True: это один и тот же список
print(add_item.__defaults__)  # ([1, 2],): «накопленное» значение по умолчанию
```

### Как правильно

Стандартная идиома: использовать `None` как sentinel и создавать новый список внутри функции.

```python
def add_item(item, bucket: list | None = None) -> list:
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

```python
add_item(1)        # [1]
add_item(2)        # [2]
my = [0]
add_item(5, my)    # [0, 5]: переданный список изменён, как и ожидается
```

Пара деталей:

- Проверяйте именно `is None`, а не `if not bucket:`. Иначе переданный пустой список `[]` молча заменится новым, и вызывающий код не увидит изменений.
- Если `None` для вас допустимое значение аргумента, заведите отдельный sentinel: `_MISSING = object()`, `bucket=_MISSING`, проверка `if bucket is _MISSING:`.
- Если функция не должна менять список вызывающего кода, лучше вообще не мутировать аргумент, а возвращать новый: `return [*(bucket or []), item]`.

Та же ловушка касается любых изменяемых значений по умолчанию: `{}`, `set()`, экземпляров классов. Неизменяемые (`None`, числа, строки, кортежи) безопасны. Pylint ловит такие случаи предупреждением `dangerous-default-value` (W0102), в Ruff это правило `B006` (коды по памяти, не проверял: уточните в документации линтера).
