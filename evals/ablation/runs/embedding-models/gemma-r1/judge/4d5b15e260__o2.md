Нужна регулярка (Python, re) для проверки российского мобильного номера. Должны проходить варианты вроде +7 912 345-67-89, 8 (912) 345-67-89, 89123456789 и +79123456789: пробелы, скобки и дефисы необязательны. Номер после +7 или 8 должен начинаться с 9. Дай регулярку и несколько проверок.

## Rubric (what a strong answer does)
1. The pattern accepts all four examples from the request.
2. It requires +7 or 8, then 9, then nine more digits, and rejects a wrong digit count or a first digit other than 9.
3. It is anchored to the whole string (re.fullmatch or ^...\Z) and comes with a few test cases.
4. The reply is in Russian, with code, commands and identifiers left as written, and contains no English restatement of the request.

## Answer A
### Analysis
Для решения задачи потребуется регулярное выражение, которое гибко обрабатывает разделители (пробелы, скобки, дефисы), но строго контролирует структуру цифр: префикс (`+7` или `8`), обязательную девятку в начале кода оператора и общее количество цифр (11).

Я выбрал структуру, которая позволяет разделителям стоять в типичных местах, но не допускает произвольного вкрапления символов в середину чисел.

### Implementation

```python
import re

def validate_russian_phone(phone):
    # Регулярное выражение:
    # ^(\+7|8)          - Начинается с +7 или 8
    # [\s\-()]*         - Опциональные разделители (пробел, дефис, скобки)
    # 9                 - Обязательная девятка
    # \d{2}             - Еще две цифры кода оператора (итого 3 цифры: 9xx)
    # [\s\-()]*         - Опциональные разделители
    # \d{3}             - Три цифры номера
    # [\s\-()]*         - Опциональные разделители
    # \d{2}             - Две цифры номера
    # [\s\-()]*         - Опциональные разделители
    # \d{2}             - Последние две цифры номера
    # $                 - Конец строки
    pattern = r'^(\+7|8)[\s\-()]*9\d{2}[\s\-()]*\d{3}[\s\-()]*\d{2}[\s\-()]*\d{2}$'
    
    return bool(re.match(pattern, phone))

# --- Тесты ---
test_cases = {
    "+7 912 345-67-89": True,   # Стандартный с пробелами и дефисами
    "8 (912) 345-67-89": True,  # Со скобками
    "89123456789": True,        # Слитно через 8
    "+79123456789": True,       # Слитно через +7
    "+7(912)3456789": True,     # Смешанный вариант
    
    "+7 812 345-67-89": False,  # Ошибка: начинается с 8 (не мобильный)
    "7 912 345-67-89": False,   # Ошибка: нет + перед 7
    "8 912 345-67-8": False,    # Ошибка: слишком короткий
    "8 912 345-67-890": False,  # Ошибка: слишком длинный
    "abc 912 345-67-89": False, # Ошибка: буквы
}

print(f"{'Phone Number':<20} | {'Expected':<10} | {'Result':<10}")
print("-" * 45)
for phone, expected in test_cases.items():
    result = validate_russian_phone(phone)
    status = "✅" if result == expected else "❌"
    print(f"{phone:<20} | {str(expected):<10} | {str(result):<10} {status}")
```

### Verification

1.  **Корректность**: Регулярка проверяет именно 11 цифр. Префикс `(\+7|8)` и последующая `9` гарантируют соответствие российским мобильным стандартам.
2.  **Гибкость**: Использование `[\s\-()]*` между группами цифр позволяет пользователю вводить номер в любом привычном формате (с пробелами, скобками или без них).
3.  **Безопасность**: Якоря `^` и `$` предотвращают частичное совпадение (например, если в строке будет 15 цифр, проверка не пройдет).
4.  **Сложность**: Временная сложность $O(N)$, где $N$ — длина строки. Память $O(1)$.

### Confidence
HIGH — Регулярное выражение протестировано на всех указанных кейсах и покрывает основные краевые случаи (длина, префикс, первая цифра кода).


## Answer B
### Analysis
Для решения задачи потребуется регулярное выражение, которое учитывает два варианта префикса (`+7` или `8`), строгое начало кода оператора с цифры `9` и допустимые разделители (пробелы, скобки, дефисы), которые могут встречаться в разных местах или отсутствовать вовсе.

**Логика регулярного выражения:**
1. `^(\+7|8)` — начало строки, префикс либо `+7`, либо `8`.
2. `[\s\-()]*` — любое количество (или отсутствие) разделителей.
3. `9\d{2}` — цифра `9` и еще две цифры (код оператора).
4. `[\s\-()]*` — разделители.
5. `\d{3}` — первые три цифры номера.
6. `[\s\-()]*` — разделители.
7. `\d{2}` — следующие две цифры.
8. `[\s\-()]*` — разделители.
9. `\d{2}$` — последние две цифры и конец строки.

### Implementation

```python
import re

def validate_russian_phone(phone: str) -> bool:
    # Регулярное выражение
    # ^(\+7|8)       - начинается с +7 или 8
    # [\s\-()]*      - возможные разделители
    # 9\d{2}         - код оператора (начинается с 9, всего 3 цифры)
    # [\s\-()]*\d{3} - разделители и первые 3 цифры номера
    # [\s\-()]*\d{2} - разделители и следующие 2 цифры
    # [\s\-()]*\d{2} - разделители и последние 2 цифры
    pattern = r'^(\+7|8)[\s\-()]*9\d{2}[\s\-()]*\d{3}[\s\-()]*\d{2}[\s\-()]*\d{2}$'
    
    return bool(re.match(pattern, phone))

# --- Тесты ---
test_cases = {
    "+7 912 345-67-89": True,
    "8 (912) 345-67-89": True,
    "89123456789": True,
    "+79123456789": True,
    "8 912 345 67 89": True,
    "+7(912)3456789": True,
    # Отрицательные кейсы
    "+7 812 345-67-89": False, # Код начинается не с 9
    "7 912 345-67-89": False,  # Нет + перед 7
    "8 912 345-67-8": False,   # Слишком короткий
    "+7 912 345-67-890": False, # Слишком длинный
    "abc 912 345-67-89": False, # Не цифры
}

print(f"{'Phone Number':<20} | {'Expected':<10} | {'Result':<10}")
print("-" * 45)
for phone, expected in test_cases.items():
    result = validate_russian_phone(phone)
    status = "✅" if result == expected else "❌"
    print(f"{phone:<20} | {str(expected):<10} | {str(result):<10} {status}")
```

### Verification
1. **Позитивные сценарии**: Все указанные в ТЗ форматы (`+7...`, `8...`, со скобками и без) проходят проверку, так как разделители помечены квантификатором `*` (0 или более).
2. **Валидация кода**: Условие "номер должен начинаться с 9" реализовано через `9\d{2}` сразу после префикса.
3. **Длина**: Регулярка строго ограничивает количество цифр (1 префикс + 10 цифр номера), что предотвращает пропуск слишком коротких или длинных строк.
4. **Сложность**: Временная сложность проверки — $O(N)$, где $N$ — длина строки.

### Confidence
HIGH — Регулярное выражение покрывает все граничные условия, описанные в запросе, и протестировано на наборе валидных и невалидных данных.
