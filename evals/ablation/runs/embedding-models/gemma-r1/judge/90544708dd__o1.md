## Latest user message
PostgreSQL 16, таблица orders(id bigint, customer_id bigint, created_at timestamptz, amount numeric). Нужно для каждого клиента вывести его второй заказ по сумме: заказы клиента упорядочиваем по amount по убыванию, при равной сумме — по created_at по возрастанию, и берём второй в этом порядке. Клиентов с одним заказом не выводить. Напиши запрос и коротко поясни, почему он корректен.

## Rubric (what a strong answer does)
1. Numbers each customer's orders with ROW_NUMBER() (or an equivalent that always yields exactly one second row) partitioned by customer_id and ordered by amount DESC, created_at ASC, and keeps row number 2 (NULLS LAST or a final id tiebreaker is fine).
2. Customers with a single order drop out because they have no second row, or the query excludes them explicitly.
3. The explanation correctly describes how equal amounts are ordered by created_at.
4. The reply is in Russian, with code, commands and identifiers left as written, and contains no English restatement of the request.

## Answer A
```sql
WITH RankedOrders AS (
    SELECT 
        id, 
        customer_id, 
        amount, 
        created_at,
        ROW_NUMBER() OVER (
            PARTITION BY customer_id 
            ORDER BY amount DESC, created_at ASC
        ) as rn
    FROM orders
)
SELECT id, customer_id, amount, created_at
FROM RankedOrders
WHERE rn = 2;
```

### Почему запрос корректен:

1.  **`ROW_NUMBER()`**: Присваивает строгий порядковый номер каждой строке внутри группы. В отличие от `RANK()`, он не создает «дыр» и не дублирует номера при одинаковых значениях, что гарантирует получение ровно одной строки (второй) для каждого клиента.
2.  **`PARTITION BY customer_id`**: Сбрасывает счетчик для каждого нового клиента, позволяя нумеровать заказы индивидуально.
3.  **`ORDER BY amount DESC, created_at ASC`**: Точно реализует требуемую бизнес-логику сортировки: сначала самые дорогие заказы, затем самые ранние при равенстве сумм.
4.  **`WHERE rn = 2`**: 
    *   Выбирает именно второй заказ.
    *   Автоматически исключает клиентов с одним заказом, так как для них максимальное значение `rn` будет равно 1.


## Answer B
```sql
WITH RankedOrders AS (
    SELECT 
        id, 
        customer_id, 
        created_at, 
        amount,
        ROW_NUMBER() OVER (
            PARTITION BY customer_id 
            ORDER BY amount DESC, created_at ASC
        ) as rn
    FROM orders
)
SELECT id, customer_id, created_at, amount
FROM RankedOrders
WHERE rn = 2;
```

### Почему запрос корректен:

1.  **`ROW_NUMBER()`**: Эта оконная функция присваивает уникальный порядковый номер каждой строке внутри группы. В отличие от `RANK()`, она не создает «дыр» в нумерации при одинаковых значениях, что гарантирует получение именно одной (второй) строки.
2.  **`PARTITION BY customer_id`**: Сбрасывает счетчик для каждого нового клиента, позволяя нумеровать заказы индивидуально для каждого `customer_id`.
3.  **`ORDER BY amount DESC, created_at ASC`**: Строго реализует заданную бизнес-логику сортировки: сначала по сумме (от большей к меньшей), затем по дате (от старых к новым).
4.  **`WHERE rn = 2`**: 
    *   Выбирает именно второй заказ в отсортированном списке.
    *   Автоматически исключает клиентов с одним заказом, так как для них максимальное значение `rn` будет равно 1.
