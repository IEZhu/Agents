Off-by-one: лишняя `-1` в индексе, функция возвращает n+1 элементов.

`items = [1,2,3,4,5]`, `n=2` → `len(items) - n - 1 = 2` → `items[2:]` → `[3,4,5]`, три элемента вместо двух.

Та же `-1` ломает и границы:

| n | ожидается | возвращает |
|---|---|---|
| 0 | `[]` | `[5]` (`items[4:]`) |
| 5 (`== len`) | весь список | `[5]` (старт `-1`) |
| 6 (`> len`) | весь список | `[4,5]` (старт `-2`) |

Корень один: отрицательный старт среза в Python не обрезается до нуля, а отсчитывается от конца. При `n >= len(items)` выражение `len(items) - n - 1` уходит в минус, и срез начинает означать совсем другое — не «мало элементов», а «элементы с конца».

Фикс:

```python
def last_n(items, n):
    return items[max(len(items) - n, 0):]
```

`max(..., 0)` убирает отрицательный старт: `n >= len` даёт весь список, `n = 0` — пустой (`items[len:]`), отрицательный `n` — тоже пустой.

Вариант `items[-n:]` короче, но у него своя дыра: при `n = 0` это `items[0:]`, то есть весь список. Если берёшь его — нужна явная проверка `if n <= 0: return []`.

Тесты, которых тут не хватает: `n=0`, `n=1`, `n == len(items)`, `n > len(items)`, пустой список, отрицательный `n`. По последнему стоит принять решение сознательно — исключение или `[]`; сейчас контракт на этот случай не определён ни кодом, ни сигнатурой.
