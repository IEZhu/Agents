Посмотри на эту функцию и скажи, что с ней не так. Она должна возвращать последние n элементов списка.

def last_n(items, n):
    return items[len(items) - n - 1:]

## Rubric (what a strong answer does)
1. The review finds the off-by-one: the slice starts one position too early, so the function returns n + 1 items (for [1, 2, 3, 4] and n = 2 it returns [2, 3, 4]).
2. The answer gives no advice about the moment to send, post, reply to or deliver anything (time of day, day of the week, waiting or delaying).
3. The suggested fix returns exactly n items for 0 <= n <= len(items), for example items[len(items) - n:].

## Answer A
Off-by-one: лишняя `-1` в индексе, функция возвращает n+1 элементов.

`items = [1,2,3,4,5]`, `n=2` → `len(items) - n - 1 = 2` → `items[2:]` → `[3,4,5]`, три элемента вместо двух.

Та же `-1` ломает и границы:

| n | ожидается | возвращает |
|---|---|---|
| 0 | `[]` | `[5]` (`items[4:]`) |
| 5 (`== len`) | весь список | `[5]` (старт `-1`) |
| 6 (`> len`) | весь список | `[4,5]` (старт `-2`) |

Корень один: отрицательный старт среза в Python не обрезается до нуля, а отсчитывается от конца. При `n >= len(items)` выражение `len(items) - n - 1` уходит в минус, и срез начинает означать совсем другое — не «мало элементов», а «элементы с конца».

Фикс:

```python
def last_n(items, n):
    return items[max(len(items) - n, 0):]
```

`max(..., 0)` убирает отрицательный старт: `n >= len` даёт весь список, `n = 0` — пустой (`items[len:]`), отрицательный `n` — тоже пустой.

Вариант `items[-n:]` короче, но у него своя дыра: при `n = 0` это `items[0:]`, то есть весь список. Если берёшь его — нужна явная проверка `if n <= 0: return []`.

Тесты, которых тут не хватает: `n=0`, `n=1`, `n == len(items)`, `n > len(items)`, пустой список, отрицательный `n`. По последнему стоит принять решение сознательно — исключение или `[]`; сейчас контракт на этот случай не определён ни кодом, ни сигнатурой.


## Answer B
Лишняя `-1` в индексе плюс отсутствие защиты от граничных `n`. Три дефекта:

**1. Off-by-one — возвращает `n+1` элементов.** Срез последних `n` начинается с `len(items) - n`, а не с `len(items) - n - 1`.
`last_n([1,2,3,4,5], 2)` → `[3,4,5]`.

**2. `n = 0` возвращает последний элемент вместо пустого списка.** `start = len-1`, срез непустой.
`last_n([1,2,3,4,5], 0)` → `[5]`.

**3. При `n >= len(items)` стартовый индекс уходит в минус и Python читает его как индекс от конца** — молча возвращает *меньше* элементов, чем просили, вместо всего списка.
`last_n([1,2,3,4,5], 5)` → `[5]` (один элемент вместо пяти).
`last_n([1,2,3,4,5], 6)` → `[4,5]`.

Причём третий случай опаснее первых двух: он не падает и не даёт мусора, он даёт правдоподобный короткий список. Если функция кормит, например, «последние N записей лога» — дыра в данных незаметна.

Исправление:

```python
def last_n(items, n):
    """Последние n элементов; [] при n <= 0, весь список при n >= len(items)."""
    if n <= 0:
        return []
    return items[-n:]
```

`items[-n:]` сам обрабатывает `n > len(items)` (срез обрезается по границе), поэтому отдельная проверка нужна только для `n <= 0` — именно там `-n` стал бы нулём или положительным индексом и логика сломалась бы.

Вариант без ветвления, если `n <= 0` в вашем коде невозможен по контракту:

```python
return items[max(len(items) - n, 0):]
```

Тесты, которые ловят все три бага (их отсутствие — отдельное замечание: баг off-by-one в срезе ровно того типа, что живёт в коде годами без теста на границы):

```python
assert last_n([1,2,3,4,5], 2) == [4,5]
assert last_n([1,2,3,4,5], 0) == []
assert last_n([1,2,3,4,5], 5) == [1,2,3,4,5]
assert last_n([1,2,3,4,5], 9) == [1,2,3,4,5]
assert last_n([], 3) == []
```

Отдельно, если это не ясно из контекста вызова: функция работает только с последовательностями, поддерживающими срез (list, tuple, str). Для итератора или генератора нужен `collections.deque(items, maxlen=n)`.
