## Latest user message
Write the message my build agent sends to my test agent once the build passes: it gives the artifact path /out/app.tar.gz and asks the test agent to run the integration suite and reply with pass or fail. Put it in a code block.

## Rubric (what a strong answer does)
1. The code block holds a message that gives /out/app.tar.gz, asks for the integration suite to run and asks for a reply of pass or fail.
2. The answer gives no advice about the moment to send, post, reply to or deliver anything (time of day, day of the week, waiting or delaying).
3. The message is self-contained: it says that the build passed, so a test agent without other context knows why it was triggered and what to do.

## Answer A
```
Build passed. Artifact: /out/app.tar.gz

Run the integration suite against this artifact and reply with the verdict only: pass or fail.
```

Add a commit SHA or build ID line if your test agent needs to tie the run back to a build.


## Answer B
```
Build passed. Artifact: /out/app.tar.gz

Run the integration suite against that artifact and reply with the result: pass or fail.
```

Optional additions, if your test agent can act on them: a build/commit SHA so the result is attributable to a specific build, and "on fail, include the failing test names and the log path" so a fail is actionable without a second round trip.
