The server file will live at src/mcp_servers/billing/server.py.

## Rubric (what a strong answer does)
1. Uses the FastMCP decorator API (`from mcp.server.fastmcp import FastMCP`, `@mcp.tool()`) instead of patching the low-level Server with a hand-written inputSchema, and explains that FastMCP generates the input schema from the type hints (and the tool description from the docstring)
2. Models the nested invoice lines with a pydantic BaseModel (or equivalent typed structure) with typed fields such as sku, qty and unit_price_cents, rather than an untyped dict or JSON string
3. The tool is async, calls the API with an async HTTP client such as httpx.AsyncClient, reads the API key from an environment variable rather than hardcoding it, and handles HTTP/network failures by returning a readable error message to the model
4. Gives a project config entry (e.g. `.mcp.json` / `mcp.json` `mcpServers`) that runs the server over stdio with the repo's `.venv/bin/python` (or its absolute path) and `src/mcp_servers/billing/server.py` as the argument, with the API key supplied via the env block or the environment rather than in the code

## Answer A
## Likely cause

Both symptoms usually come from a hand-written `inputSchema`. I haven't seen yours, so check it for these:

| Symptom | Usual schema mistake |
|---|---|
| `lines` arrives as a JSON string | `lines` declared as `"type": "string"` or `"type": "object"`, or `"type": "array"` with no `"items"` schema. The model then guesses a serialization. |
| `currency` sometimes missing | `currency` absent from the top-level `"required"` array. It may also be listed only inside the `items` schema. |

The shape you want, top level, is this:

```json
{
  "type": "object",
  "properties": {
    "customer_id": {"type": "string"},
    "currency": {"type": "string", "pattern": "^[A-Z]{3}$"},
    "due_days": {"type": "integer", "minimum": 0, "default": 30},
    "lines": {
      "type": "array",
      "minItems": 1,
      "items": {
        "type": "object",
        "properties": {
          "sku": {"type": "string"},
          "qty": {"type": "integer", "minimum": 1},
          "unit_price_cents": {"type": "integer", "minimum": 0}
        },
        "required": ["sku", "qty", "unit_price_cents"]
      }
    }
  },
  "required": ["customer_id", "currency", "lines"]
}
```

You could fix the hand-written schema. The better fix is to drop the low-level `Server()` API and use `FastMCP` with Pydantic models. FastMCP builds the schema from the type hints and validates arguments before your code runs, so the schema can't drift from your code. The same `mcp` 1.x package includes it.

## `src/mcp_servers/billing/server.py`

```python
"""MCP server exposing the internal billing API (create_invoice)."""

import logging
import os
import sys
from typing import Annotated

import httpx
from mcp.server.fastmcp import FastMCP
from mcp.server.fastmcp.exceptions import ToolError
from pydantic import BaseModel, Field

# stdio transport: stdout carries the MCP protocol. Log to stderr only, never print().
logging.basicConfig(stream=sys.stderr, level=logging.INFO)
logger = logging.getLogger("billing_mcp")

BILLING_BASE_URL = os.getenv("BILLING_BASE_URL", "https://billing.internal/v2")
REQUEST_TIMEOUT_SECONDS = 15.0

mcp = FastMCP("billing")


class InvoiceLine(BaseModel):
    sku: Annotated[str, Field(min_length=1, description="Product SKU, e.g. 'SUP-PRO'.")]
    qty: Annotated[int, Field(ge=1, description="Quantity, integer >= 1.")]
    unit_price_cents: Annotated[
        int, Field(ge=0, description="Unit price in minor units (cents). 49.00 EUR -> 4900.")
    ]


class InvoiceResult(BaseModel):
    status_code: int
    invoice: dict


def _headers() -> dict[str, str]:
    api_key = os.getenv("BILLING_API_KEY")
    if not api_key:
        raise ToolError("BILLING_API_KEY is not set in the MCP server environment.")
    return {"X-Api-Key": api_key, "Content-Type": "application/json"}


def _tls_verify() -> bool | str:
    # Internal hosts often use a private CA; point BILLING_CA_BUNDLE at its PEM file.
    return os.getenv("BILLING_CA_BUNDLE") or True


@mcp.tool()
async def create_invoice(
    customer_id: Annotated[str, Field(min_length=1, description="Billing customer ID, e.g. 'cus_123'.")],
    currency: Annotated[
        str, Field(pattern=r"^[A-Z]{3}$", description="ISO 4217 code, uppercase, e.g. 'EUR'. Required.")
    ],
    lines: Annotated[
        list[InvoiceLine],
        Field(min_length=1, description="Invoice lines as an array of objects (not a JSON string)."),
    ],
    due_days: Annotated[int, Field(ge=0, description="Days until the invoice is due.")] = 30,
) -> InvoiceResult:
    """Create an invoice in the internal billing service.

    Creates a real invoice (non-idempotent). Confirm customer, currency and
    lines with the user before calling. Prices are integer cents.
    """
    payload = {
        "customer_id": customer_id,
        "currency": currency,
        "due_days": due_days,
        "lines": [line.model_dump() for line in lines],
    }
    url = f"{BILLING_BASE_URL}/invoices"

    try:
        async with httpx.AsyncClient(timeout=REQUEST_TIMEOUT_SECONDS, verify=_tls_verify()) as client:
            response = await client.post(url, json=payload, headers=_headers())
    except httpx.HTTPError as exc:
        logger.error("POST %s failed: %r", url, exc)
        raise ToolError(f"Billing API unreachable ({type(exc).__name__}): {exc}") from exc

    if response.is_error:
        logger.error("POST %s -> %s: %s", url, response.status_code, response.text[:500])
        raise ToolError(f"Billing API returned {response.status_code}: {response.text[:500]}")

    try:
        body = response.json()
    except ValueError:
        body = {"raw": response.text}
    return InvoiceResult(status_code=response.status_code, invoice=body)


if __name__ == "__main__":
    mcp.run()  # stdio by default
```

Notes:
- `currency` has no default, so it lands in `required`. `due_days` has a default, so it's optional. Don't give `currency` a default of `None` or `""`, because that makes it optional again.
- `lines: list[InvoiceLine]` produces `"type": "array"` with an `items` object schema, which is what stops the string serialization. As I recall, FastMCP also parses a JSON-string argument into the declared list type if a client still sends one. I haven't verified that for your installed version, so check `func_metadata.py` in `.venv`.
- Raising `ToolError` gives Claude an `isError` result with the message, and the server keeps running. The import path `mcp.server.fastmcp.exceptions.ToolError` is from memory and not verified. If the import fails, `grep -rn "class ToolError" .venv/lib/python3.12/site-packages/mcp/` will show where it lives. A plain `raise RuntimeError(...)` behaves much the same.
- POSTs aren't idempotent. If the billing API accepts an idempotency key, add it. Otherwise a retried tool call can create a second invoice.

## Answer B
Short version: drop the low-level `Server()` and the hand-written `inputSchema`. Use `FastMCP`, which builds the schema from typed Python signatures and Pydantic models. Then `lines` goes out as a real `array` of `object`s with typed fields, and `currency` goes in `required` because it has no default.

## Probable causes in your current schema

I haven't seen your schema, so check it for these three things. In my experience they cause exactly these symptoms:

| Symptom | Likely cause in hand-written schema |
|---|---|
| `lines` sent as a JSON string | `lines` typed `"string"`, or `"array"` with no `items`, or `items` with no `properties`/`type`. The model then has no structure to follow, so it serializes the array into a string. |
| `currency` omitted | `currency` is missing from the top-level `"required": [...]`, or `required` sits at the wrong nesting level (inside `properties`, or inside the `lines` item schema). |
| Both | `inputSchema` missing `"type": "object"` at the root, so most of the schema gets ignored. |

## `src/mcp_servers/billing/server.py`

```python
"""Billing MCP server: exposes `create_invoice` over stdio."""

import logging
import os
import sys
from typing import Annotated, Any

import httpx
from mcp.server.fastmcp import FastMCP
from mcp.server.fastmcp.exceptions import ToolError
from pydantic import BaseModel, Field

BILLING_BASE_URL = os.environ.get("BILLING_BASE_URL", "https://billing.internal/v2")
API_KEY_ENV_VAR = "BILLING_API_KEY"
REQUEST_TIMEOUT_SECONDS = 15.0
MAX_DUE_DAYS = 365

# stdio transport: stdout carries the JSON-RPC stream. Log to stderr only, never print().
logging.basicConfig(stream=sys.stderr, level=logging.INFO)
log = logging.getLogger("billing_mcp")

mcp = FastMCP("billing")


class InvoiceLine(BaseModel):
    sku: Annotated[str, Field(min_length=1, description="Product SKU, e.g. 'SUP-PRO'.")]
    qty: Annotated[int, Field(ge=1, description="Quantity, positive integer.")]
    unit_price_cents: Annotated[
        int, Field(ge=0, description="Unit price in minor units (cents) as an integer, e.g. 4900 for 49.00.")
    ]


def _api_key() -> str:
    key = os.environ.get(API_KEY_ENV_VAR)
    if not key:
        raise ToolError(f"{API_KEY_ENV_VAR} is not set in the MCP server environment.")
    return key


@mcp.tool()
async def create_invoice(
    customer_id: Annotated[str, Field(min_length=1, description="Billing customer ID, e.g. 'cus_123'.")],
    currency: Annotated[
        str, Field(pattern=r"^[A-Z]{3}$", description="ISO 4217 currency code, uppercase, e.g. 'EUR'. Required.")
    ],
    lines: Annotated[
        list[InvoiceLine],
        Field(min_length=1, description="Invoice lines as an array of objects (not a JSON-encoded string)."),
    ],
    due_days: Annotated[int, Field(ge=0, le=MAX_DUE_DAYS, description="Days until the invoice is due.")] = 30,
) -> dict[str, Any]:
    """Create an invoice in the internal billing service and return the created invoice."""
    payload = {
        "customer_id": customer_id,
        "currency": currency,
        "due_days": due_days,
        "lines": [line.model_dump() for line in lines],
    }
    headers = {"X-Api-Key": _api_key(), "Content-Type": "application/json"}

    try:
        async with httpx.AsyncClient(base_url=BILLING_BASE_URL, timeout=REQUEST_TIMEOUT_SECONDS) as client:
            response = await client.post("/invoices", json=payload, headers=headers)
            response.raise_for_status()
            return response.json()
    except httpx.HTTPStatusError as exc:
        body = exc.response.text[:1000]
        log.warning("create_invoice failed: %s %s", exc.response.status_code, body)
        raise ToolError(f"Billing API returned {exc.response.status_code}: {body}") from exc
    except httpx.RequestError as exc:
        log.warning("create_invoice transport error: %r", exc)
        raise ToolError(f"Could not reach billing API at {BILLING_BASE_URL}: {exc}") from exc


if __name__ == "__main__":
    mcp.run()  # stdio transport by default
```

Notes:
- `currency` and `lines` have no defaults, so FastMCP puts them in `required`. `due_days` defaults to 30, so it's optional.
- `lines: list[InvoiceLine]` gives `{"type": "array", "items": {"$ref": "#/$defs/InvoiceLine"}}` with typed, required fields.
- As I recall, FastMCP's argument parsing also tries `json.loads` on a string arriving where a list or object is expected. If a stringified `lines` still gets through, the tool should accept it instead of failing. I haven't verified that here, so check `func_metadata.py` in your installed `mcp`.
- `mcp.server.fastmcp.exceptions.ToolError` is from memory, not verified. A plain `raise RuntimeError(...)` also produces an `isError` tool result if that import fails.
- I used a `^[A-Z]{3}$` pattern for the currency because I don't know which currencies you support. If the list is fixed, switch to `Literal["EUR", "USD", ...]`. That gives Claude an `enum`, which is the strongest hint.
- Retries on a `POST` can create duplicate invoices. If the billing API supports an idempotency key header, add one.
